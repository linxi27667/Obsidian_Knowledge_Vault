## 一、无线通信基础

### 1.1 电磁波频段划分

无线通信利用电磁波在空间中传播来传输信息。根据频率（或波长）不同，电磁波被划分为多个频段：

| 频段名称 | 频率范围 | 波长范围 | 典型应用 |
|---------|---------|---------|---------|
| 甚低频 VLF | 3–30 kHz | 10–100 km | 潜艇通信 |
| 低频 LF | 30–300 kHz | 1–10 km | RFID（125/134 kHz） |
| 中频 MF | 300 kHz–3 MHz | 100–1000 m | AM 广播 |
| 高频 HF | 3–30 MHz | 10–100 m | 短波广播、业余无线电 |
| 甚高频 VHF | 30–300 MHz | 1–10 m | FM 广播、对讲机 |
| 超高频 UHF | 300 MHz–3 GHz | 10–100 cm | 手机、WiFi、蓝牙、Zigbee |
| 超高频 SHF | 3–30 GHz | 1–10 cm | 5G 毫米波、卫星通信 |
| 极高频 EHF | 30–300 GHz | 1–10 mm | 雷达、6G 研究 |

> [!note] ISM 频段
> ISM（Industrial, Scientific and Medical）频段是国际上免许可使用的频段，嵌入式无线通信主要工作在此范围：
> - **Sub-GHz**：315 MHz（美/中）、433 MHz（全球）、868 MHz（欧）、915 MHz（美）
> - **2.4 GHz**：2400–2483.5 MHz（WiFi、蓝牙、Zigbee 共用）
> - **5.8 GHz**：5725–5875 MHz（WiFi、雷达）

### 1.2 调制方式

调制是将数字基带信号搬移到射频载波上的过程。主要参数为幅度、频率、相位。

#### 1.2.1 ASK — 幅移键控（Amplitude Shift Keying）

- 原理：用数字信号控制载波的**幅度**，有信号为高幅度，无信号为低幅度
- 最简单形式为 OOK（On-Off Keying）：1 = 有载波，0 = 无载波
- 优点：实现简单，成本低
- 缺点：抗噪声能力差，易受衰落影响
- 典型应用：RFID（125 kHz）、简单遥控器、AM 调制

```
OOK 调制示意：
数据：  1   0   1   1   0
载波：  ∿∿∿ ___ ∿∿∿ ∿∿∿ ___
```

#### 1.2.2 FSK — 频移键控（Frequency Shift Keying）

- 原理：用数字信号控制载波的**频率**，1 对应高频 f1，0 对应低频 f0
- 变体：GFSK（高斯滤波 FSK，蓝牙使用）、MSK（最小频移键控）
- 优点：抗幅度噪声好，实现较简单
- 缺点：频带利用率较低
- 典型应用：蓝牙 BR/EDR、无线门铃、低速率无线传感器

```
FSK 调制示意：
数据 1 → 高频载波 f1
数据 0 → 低频载波 f0
```

#### 1.2.3 PSK — 相移键控（Phase Shift Keying）

- 原理：用数字信号控制载波的**相位**
- BPSK：2 种相位（0°、180°），每符号 1 bit
- QPSK：4 种相位（0°、90°、180°、270°），每符号 2 bit
- 8PSK：8 种相位，每符号 3 bit
- 优点：频带利用率高于 FSK，抗噪声能力较好
- 典型应用：卫星通信、数字电视、WiFi（作为子载波调制）

#### 1.2.4 QAM — 正交幅度调制（Quadrature Amplitude Modulation）

- 原理：同时调制**幅度和相位**，将信号映射到 IQ 星座图上
- 常见阶数：16-QAM（4 bit/符号）、64-QAM（6 bit/符号）、256-QAM（8 bit/符号）、1024-QAM（10 bit/符号）
- 阶数越高 → 频谱效率越高 → 但对信噪比要求越高
- 典型应用：WiFi 5（256-QAM）、WiFi 6（1024-QAM）、4G/5G

```
QAM 星座图示意（16-QAM）：

    Q
    |
 *  *  *  *
 *  *  *  *
 *  *  *  *
 *  *  *  *
----+--------→ I

每个 * 代表一个符号点，坐标 (I, Q) 对应特定的幅度和相位组合。
```

> [!tip] 调制方式与数据速率的关系
> 数据速率 = 符号速率 × 每符号比特数
> 例如 WiFi 6 使用 1024-QAM，每符号传输 10 bit，配合高符号速率实现极高吞吐量。

### 1.3 扩频技术

扩频（Spread Spectrum）技术将信号扩展到比原始带宽宽得多的频带上发送，以提高抗干扰能力和安全性。

#### 1.3.1 FHSS — 跳频扩频（Frequency Hopping Spread Spectrum）

- 原理：发送端和接收端按预定伪随机序列在多个频率之间快速跳变
- 跳频速率：蓝牙经典模式为 1600 hops/s（每 625 μs 跳一次）
- 优点：抗窄带干扰强、低截获概率、可多用户共存
- 缺点：同步机制复杂
- 典型应用：蓝牙 Classic、早期军事通信

```
FHSS 跳频示意：
时间 →  t1    t2    t3    t4    t5
频率     f3    f7    f1    f5    f2
         ↓     ↓     ↓     ↓     ↓
        载波在 f1-fN 之间按伪随机序列跳变
```

#### 1.3.2 DSSS — 直接序列扩频（Direct Sequence Spread Spectrum）

- 原理：将每个数据比特与一个高速伪随机码（扩频码/码片序列）相乘，扩展到更宽带宽
- 扩频因子（Spreading Factor）= 码片速率 / 数据速率
- 处理增益 = 10 × log10(扩频因子)
- 优点：抗多径干扰、抗窄带干扰、保密性好
- 典型应用：WiFi 802.11b（Barker 码、CCK）、GPS（CDMA）

#### 1.3.3 CSS — 线性调频扩频（Chirp Spread Spectrum）

- 原理：使用频率随时间线性变化的线性调频信号（Chirp）
- 优点：极低信噪比下仍可解调、抗多普勒效应
- 典型应用：LoRa（Semtech 专利调制）

```
CSS Chirp 信号：
频率
 ↑     /
 |    /
 |   /
 |  /
 | /
 +----------→ 时间
  上扫频 Chirp（Up-Chirp）
```

### 1.4 信道容量与香农定理

香农-哈特利定理给出了信道容量的理论上限：

$$C = B \times \log_2(1 + SNR)$$

- C：信道容量（bit/s）
- B：信道带宽（Hz）
- SNR：信噪比（线性值，非 dB）

> [!example] 计算示例
> WiFi 6 信道带宽 160 MHz，SNR = 30 dB（线性值 1000）：
> C = 160M × log2(1 + 1000) ≈ 160M × 10 ≈ 1.6 Gbps（理论上限，单天线）

### 1.5 链路预算（Link Budget）

链路预算用于计算无线通信系统的最大传输距离：

```
链路预算 = 发射功率(dBm) + 发射天线增益(dBi)
         - 路径损耗(dB)
         + 接收天线增益(dBi)
         - 接收灵敏度(dBm)
         - 其他损耗(dB)（馈线、穿透、衰落余量等）
```

自由空间路径损耗（FSPL）公式：

$$FSPL(dB) = 20\log_{10}(d) + 20\log_{10}(f) + 20\log_{10}\left(\frac{4\pi}{c}\right)$$

简化为（d 单位 km，f 单位 MHz）：

$$FSPL(dB) = 32.44 + 20\log_{10}(d) + 20\log_{10}(f)$$

### 2.2 WiFi 信道与频段

#### 2.4 GHz 信道

- 总范围：2400–2483.5 MHz
- 共 14 个信道，每个信道 22 MHz（有效 20 MHz + 保护间隔）
- 不重叠信道：**1、6、11**（最常用的三信道规划）
- 中国开放信道：1–13

```
2.4 GHz 信道分布：
Ch1   Ch2   Ch3   Ch4   Ch5   Ch6   Ch7   Ch8   Ch9   Ch10  Ch11  Ch12  Ch13
|-----|-----|-----|-----|-----|-----|-----|-----|-----|-----|-----|-----|-----|
2412  2417  2422  2427  2432  2437  2442  2447  2452  2457  2462  2467  2472 MHz

不重叠：Ch1(2412)    Ch6(2437)    Ch11(2462)
```

#### 5 GHz 信道

- 范围：5150–5850 MHz（各国不同）
- 不重叠信道多（20 MHz 带宽下约 25 个）
- 支持 40/80/160 MHz 宽信道（WiFi 5/6）
- DFS（动态频率选择）信道：需检测雷达信号，检测到必须让出

#### 6 GHz 信道（WiFi 6E / WiFi 7）

- 范围：5925–7125 MHz（各国开放不同）
- 全新频段，无旧设备干扰
- 支持最多 7 个 160 MHz 信道或 3 个 320 MHz 信道（WiFi 7）

### 2.3 OFDM 与 OFDMA

#### OFDM — 正交频分复用

- 将宽信道分成多个窄子载波（如 64 个），每个子载波独立调制
- 子载波间隔 312.5 kHz（WiFi），正交排列避免干扰
- 优点：抗多径衰落、频谱效率高
- WiFi 802.11a/g/n/ac/ax 均使用 OFDM

#### OFDMA — 正交频分多址（WiFi 6 引入）

- 在 OFDM 基础上，将子载波分组为 **RU（Resource Unit）**
- 不同用户可同时使用不同 RU，实现频域上的多用户并行
- 显著降低多用户场景下的延迟
- 上下行均支持

```
OFDM vs OFDMA：

OFDM（WiFi 4/5）：
用户1 |████████████████████████████████|  ← 占用全部子载波
用户2 |                                |  ← 等待
用户3 |                                |  ← 等待

OFDMA（WiFi 6）：
用户1 |████████|        |████████|        |  ← 占用部分 RU
用户2 |        |████████|        |████████|  ← 同时使用其他 RU
用户3 |████████|████████|████████|████████|  ← 三用户并行
```

### 2.4 MIMO 技术

#### SU-MIMO（单用户 MIMO）

- 多根天线同时为一个用户服务
- 空间复用：不同天线发送不同数据流 → 速率倍增
- 空间分集：不同天线发送相同数据 → 可靠性提升
- WiFi 4 开始支持（最多 4×4）

#### MU-MIMO（多用户 MIMO）

- 多根天线同时为多个用户服务
- WiFi 5：仅下行 MU-MIMO（最多 4 用户）
- WiFi 6：上行 + 下行 MU-MIMO（最多 8 用户）
- WiFi 7：增强 MU-MIMO + MLO

#### 波束成形（Beamforming）

- AP 通过调整各天线的相位和幅度，将信号能量集中到特定客户端方向
- 提高信噪比、增大覆盖范围
- 需要信道反馈（CSI）支持

### 2.5 WiFi 6 关键特性

| 特性 | 说明 |
|------|------|
| OFDMA | 多用户频分复用，降低延迟 |
| 1024-QAM | 每符号 10 bit，提升 25% 速率 |
| TWT（Target Wake Time） | 设备协商唤醒时间，IoT 设备省电关键 |
| BSS Coloring | 基本服务集着色，区分同频 AP，减少干扰 |
| 上行 MU-MIMO | 多设备同时上行 |
| 更长 OFDM 符号 | 抗多径能力增强，覆盖更远 |
| 20 MHz-only 模式 | IoT 设备专用，降低功耗和复杂度 |

> [!important] TWT 对 IoT 的意义
> TWT 允许 IoT 设备与 AP 协商精确的唤醒/休眠时间表，设备可以在非通信时段深度休眠，大幅降低平均功耗。这是 WiFi 6 对嵌入式 IoT 最重要的特性之一。

## 三、蓝牙 Bluetooth

### 3.1 蓝牙技术概览

蓝牙工作在 2.4 GHz ISM 频段，使用 FHSS 跳频技术（每秒 1600 跳），分为两大技术路线：

```
蓝牙技术体系
├── Classic Bluetooth（经典蓝牙）
│   ├── BR（Basic Rate）—— 1 Mbps，GFSK
│   ├── EDR（Enhanced Data Rate）—— 2/3 Mbps，π/4-DQPSK / 8DPSK
│   └── 应用：音频流（A2DP）、文件传输、串口（SPP）
│
└── Bluetooth Low Energy（低功耗蓝牙）
    ├── BLE 4.0/4.1/4.2
    ├── BLE 5.0/5.1/5.2/5.3/5.4
    └── 应用：IoT 传感器、穿戴设备、Mesh 网络
```

### 3.2 Classic Bluetooth（BR/EDR）

#### 协议栈

```
┌─────────────────────────────────────┐
│          应用层 Profiles            │  A2DP、HFP、SPP、HID、PAN...
├─────────────────────────────────────┤
│          中间协议层                  │  SDP、RFCOMM、L2CAP、AVDTP
├─────────────────────────────────────┤
│          主机控制接口 HCI            │  Host 与 Controller 的标准接口
├─────────────────────────────────────┤
│          链路管理层 LMP              │  链路建立、加密、功率控制
├─────────────────────────────────────┤
│          基带层 Baseband             │  跳频、时隙管理、纠错
├─────────────────────────────────────┤
│          射频层 Radio                │  2.4 GHz、79 个信道、FHSS
└─────────────────────────────────────┘
```

#### Piconet（微微网）

- 1 个 Master + 最多 7 个 Active Slave
- Master 控制跳频序列和时隙分配
- 通信基于时分复用（TDD），每个时隙 625 μs

### 3.3 BLE（Bluetooth Low Energy）

#### BLE 协议栈层次

```
┌────────────────────────────────────────────┐
│            应用层 (Application)             │  GATT Profile、自定义服务
├────────────────────────────────────────────┤
│     主机层 (Host)                           │
│  ┌──────────┐ ┌──────────┐ ┌─────────────┐│
│  │   GAP    │ │   GATT   │ │    SMP      ││  通用访问、属性协议、安全管理
│  └──────────┘ └──────────┘ └─────────────┘│
│  ┌──────────┐ ┌──────────┐                │
│  │  ATT     │ │  L2CAP   │                │  属性传输、逻辑链路控制
│  └──────────┘ └──────────┘                │
├────────────────────────────────────────────┤
│     控制器层 (Controller)                   │
│  ┌──────────┐ ┌──────────┐ ┌─────────────┐│
│  │   HCI    │ │  Link    │ │   PHY       ││  主机接口、链路层、物理层
│  │          │ │  Layer   │ │  (1M/2M/Coded)│
│  └──────────┘ └──────────┘ └─────────────┘│
└────────────────────────────────────────────┘
```

#### GAP 角色

| 角色 | 说明 | 示例 |
|------|------|------|
| Broadcaster | 仅发送广播（不可连接） | Beacon、温度广播 |
| Observer | 仅扫描/接收广播 | 扫描器、网关 |
| Peripheral | 可连接的从设备 | 心率带、传感器 |
| Central | 发起连接的主设备 | 手机、网关 |

#### GATT 数据模型

```
GATT 服务结构：

Service（服务）—— 逻辑功能组
├── Characteristic（特征）—— 单个数据点
│   ├── Value（值）—— 实际数据
│   ├── Descriptor（描述符）—— 元数据（如单位、范围）
│   └── Properties（属性）—— Read / Write / Notify / Indicate
└── Characteristic
    ├── Value
    └── ...

示例：心率服务
Service: Heart Rate Service (UUID: 0x180D)
├── Characteristic: Heart Rate Measurement (UUID: 0x2A37)
│   ├── Properties: Notify
│   └── Value: [Flags, Heart Rate, RR-Interval...]
└── Characteristic: Body Sensor Location (UUID: 0x2A38)
    ├── Properties: Read
    └── Value: Chest (0x01)
```

### 3.4 BLE 5.x 版本演进

#### BLE 5.0（2016）

| 特性 | 说明 |
|------|------|
| 2× 数据速率 | LE 2M PHY：符号速率 2 Msym/s，吞吐量翻倍 |
| 4× 覆盖距离 | LE Coded PHY（S=2 / S=8）：编码冗余，灵敏度提升 |
| 8× 广播容量 | Extended Advertising：扩展广播，支持更大广播数据 |
| AoA/AoD | 到达角/离开角测向（天线阵列） |

```
BLE 5.0 PHY 模式对比：

| PHY 模式     | 符号速率   | 数据速率  | 灵敏度    | 覆盖距离 |
|-------------|-----------|----------|----------|---------|
| LE 1M       | 1 Msym/s  | 1 Mbps   | -97 dBm  | 基准    |
| LE 2M       | 2 Msym/s  | 2 Mbps   | -94 dBm  | 较短    |
| LE Coded S=2| 1 Msym/s  | 500 kbps | -101 dBm | 2×      |
| LE Coded S=8| 1 Msym/s  | 125 kbps | -107 dBm | 4×      |
```

#### BLE 5.1（2019）

- **AoA / AoD 测向**：通过天线阵列的相位差计算信号方向
  - AoA（Angle of Arrival）：接收端多天线阵列
  - AoD（Angle of Departure）：发送端多天线阵列
- 定位精度可达厘米级
- 应用：室内定位、资产追踪

#### BLE 5.2（2020）

- **LE Audio**：全新蓝牙音频架构
  - LC3 编解码器：比 SBC 更高音质、更低功耗、更低码率
  - 多流音频（Multi-Stream）：支持真无线耳机双耳独立流
  - 广播音频（Auracast）：一对多音频广播（机场、会议室）
  - 听力辅助支持
- **EATT（Enhanced ATT）**：增强属性协议，支持多 L2CAP 通道并行

#### BLE 5.3（2021）

- **Periodic Advertising Enhancement**：周期性广播增强
- **Connection Subrating**：连接子评级，允许在不中断连接的情况下降低功耗
- **Channel Classification Enhancement**：信道分类增强，提升共存性能
- HCI 和 LL 层多项优化

#### BLE 5.4（2023）

- **PAwR（Periodic Advertising with Responses）**：周期性广播带响应
  - 支持无连接双向通信
  - 适用于大规模 ESL（电子货架标签）场景
- **Encrypted Advertising Data**：广播数据加密

### 3.5 蓝牙 Mesh

蓝牙 Mesh 基于 BLE 广播机制（非连接），实现多对多通信：

| 概念 | 说明 |
|------|------|
| 节点（Node） | 网络中的每个设备 |
| 消息（Message） | Mesh 通信的基本单元（Get/Set/Status） |
| 发布/订阅 | 发布者发送消息，订阅者接收 |
| 中继（Relay） | 节点可转发消息，扩展覆盖范围 |
| 代理（Proxy） | 允许 GATT 客户端通过代理节点访问 Mesh |
| 安全 | AES-128 加密，三层密钥体系（Net/App/Device） |

```
蓝牙 Mesh 网络拓扑：

    [手机] ←GATT Proxy→ [节点A] ←Relay→ [节点B]
                                          ↓
                                     [节点C] ←Relay→ [节点D]
                                          ↓
                                     [节点E]

消息通过广播泛洪（Managed Flooding）传播，中继节点转发。
最大跳数：127 跳（实际建议 ≤10 跳控制延迟）
```

> [!tip] Mesh 消息传输方式
> - **广播泛洪（Flooding）**：消息广播出去，中继节点转发，简单但效率低
> - **基于友谊（Friendship）**：低功耗节点（LPN）与 Friend 节点配对，Friend 缓存消息，LPN 定期轮询
> - **GATT Proxy**：不支持广播的设备通过 Proxy 节点的 GATT 连接访问 Mesh

## 四、Zigbee

### 4.1 Zigbee 概述

Zigbee 基于 IEEE 802.15.4 标准，专为低功耗、低数据速率的无线传感器网络和控制网络设计。

| 参数 | 规格 |
|------|------|
| 频段 | 2.4 GHz（全球）、868 MHz（欧）、915 MHz（美） |
| 数据速率 | 250 kbps（2.4 GHz）、40 kbps（915 MHz）、20 kbps（868 MHz） |
| 调制方式 | O-QPSK（2.4 GHz）、BPSK（868/915 MHz） |
| 信道数 | 16（2.4 GHz，5 MHz 间隔）、1（868 MHz）、10（915 MHz） |
| 网络容量 | 最多 65535 个节点 |
| 安全 | AES-128 |
| 传输距离 | 10–100 m（典型室内 30 m） |

### 4.2 IEEE 802.15.4 物理层与 MAC 层

```
Zigbee 协议栈：

┌─────────────────────────────────────┐
│        应用层 (Application)          │  ZDO、自定义应用、Cluster
├─────────────────────────────────────┤
│        网络层 (NWK)                  │  路由、Mesh 组网、安全
├─────────────────────────────────────┤
│        MAC 层 (IEEE 802.15.4)       │  CSMA-CA、信道访问、帧校验
├─────────────────────────────────────┤
│        PHY 层 (IEEE 802.15.4)       │  调制解调、射频收发
└─────────────────────────────────────┘
```

802.15.4 MAC 层特点：
- **CSMA-CA**：载波侦听多路访问/冲突避免（非 CSMA/CD）
- **超帧结构**：Beacon 模式下有 GTS（保证时隙）分配
- **帧类型**：Beacon、Data、ACK、MAC Command

### 4.3 Zigbee 3.0 协议栈

Zigbee 3.0 统一了此前多个应用层 Profile（ZHA、ZLL、ZSE 等）：

```
Zigbee 3.0 协议栈：

┌────────────────────────────────────────────┐
│    Zigbee Cluster Library (ZCL)            │  标准化的应用功能簇
│    ┌─────────────────────────────────────┐ │
│    │  基础簇：Basic、Power Config、OTA   │ │
│    │  灯光簇：On/Off、Level、Color       │ │
│    │  传感簇：Temperature、Humidity      │ │
│    │  安全簇：IAS Zone、IAS ACE          │ │
│    │  HVAC 簇：Thermostat               │ │
│    │  ...                                │ │
│    └─────────────────────────────────────┘ │
├────────────────────────────────────────────┤
│    Zigbee Device Object (ZDO)              │  设备发现、绑定、网络管理
├────────────────────────────────────────────┤
│    网络层 (NWK) + 安全层 (APS)            │  路由、Mesh、AES-128 加密
├────────────────────────────────────────────┤
│    IEEE 802.15.4 MAC + PHY                 │  CSMA-CA、O-QPSK 调制
└────────────────────────────────────────────┘
```

#### ZCL（Zigbee Cluster Library）

Cluster 是 Zigbee 应用层的核心概念，每个 Cluster 定义了一组相关的属性和命令：

```
Cluster 示例：On/Off Cluster (ID: 0x0006)

属性（Attributes）：
  - OnOff (ID: 0x0000) —— 布尔值，灯开/关状态

命令（Commands）：
  - Off (0x00) —— 关灯
  - On  (0x01) —— 开灯
  - Toggle (0x02) —— 切换
  - 响应：Report Attributes（状态上报）
```

### 4.4 网络拓扑

Zigbee 定义了三种设备角色和三种网络拓扑：

#### 设备角色

| 角色 | 功能 | 说明 |
|------|------|------|
| Coordinator（协调器） | 全功能设备，启动和管理网络 | 每个网络有且仅有一个 |
| Router（路由器） | 全功能设备，转发数据、扩展覆盖 | 需持续供电 |
| End Device（终端设备） | 精简功能设备，仅与父节点通信 | 可电池供电，支持休眠 |

#### 拓扑结构

```
星型拓扑（Star）：
         [Router]
            |
[EndDev]—[Coordinator]—[EndDev]
            |
         [Router]
特点：所有通信经过协调器，简单但覆盖有限

树型拓扑（Tree）：
            [Coordinator]
           /      |      \
       [Router] [Router] [Router]
       /    \      |       \
   [ED]  [ED]   [ED]    [Router]
                              |
                            [ED]
特点：分层路由，路径固定，不灵活

网状拓扑（Mesh）：
    [Router] ←——→ [Router]
        ↑              ↑
        |              |
   [Coordinator] ←→ [Router]
        |              ↓
    [Router]       [End Device]
特点：多路径冗余，自愈能力强，最常用
```

#### Zigbee 路由机制

- **AODV（Ad hoc On-demand Distance Vector）**：按需路由，Mesh 拓扑使用
- **树型路由**：基于网络地址的分层路由
- **多对一路由**：路由发现和维护

### 4.5 Zigbee vs Thread 对比

| 特性 | Zigbee 3.0 | Thread |
|------|-----------|--------|
| 底层标准 | IEEE 802.15.4（2.4 GHz） | IEEE 802.15.4（2.4 GHz） |
| 网络层 | Zigbee NWK（私有） | 6LoWPAN（IPv6） |
| IP 寻址 | 否 | 是（原生 IPv6） |
| 应用层 | ZCL（Zigbee Cluster Library） | 无统一标准（配合 Matter） |
| 网络拓扑 | 星型/树型/Mesh | 无 Leader/Mesh |
| 安全 | AES-128 | AES-CCM（128 位） |
| 边界路由器 | Zigbee Gateway | Thread Border Router |
| 互操作性 | Zigbee 认证 | Matter 认证（应用层） |
| 设备角色 | Coordinator / Router / End Device | Leader / Router / End Device / SED / MED |
| OTA 升级 | 支持（ZCL OTA Cluster） | 支持（SUIT/CoAP） |
| 生态系统 | 成熟、设备多 | 新兴、Matter 推动 |

## 五、Thread / Matter

### 5.1 Thread 协议

Thread 是由 Google/Nest 主导的基于 IPv6 的低功耗 Mesh 网络协议。

#### Thread 核心特点

- **基于 802.15.4 + 6LoWPAN**：在 802.15.4 帧上封装 IPv6
- **原生 IPv6 支持**：每个设备有全球唯一 IPv6 地址
- **无单点故障**：无中心控制器，Leader 自动选举
- **自愈 Mesh**：路由路径自动修复
- **低功耗**：支持 Sleepy End Device（SED）
- **安全**：AES-CCM-128、DTLS、Commissioning 安全配网

#### Thread 网络架构

```
Thread 网络组件：

┌──────────────────────────────────────────────┐
│              Thread 网络                      │
│                                              │
│  [Leader] ←自动选举→ [Router] ←→ [Router]   │
│     ↓                   ↓           ↓        │
│  [Router]          [REED]      [End Device]  │
│     ↓                   ↓                    │
│  [SED]             [SED/MED]                 │
│                                              │
└────────────────────┬─────────────────────────┘
                     │
          ┌──────────┴──────────┐
          │ Thread Border       │
          │ Router (TBR)        │  ← 连接 Thread 网络与外部网络
          └──────────┬──────────┘
                     │
              外部 IP 网络（WiFi/Ethernet/Cellular）
```

#### Thread 设备角色

| 角色 | 说明 |
|------|------|
| Border Router (TBR) | 连接 Thread 网络与外部 IP 网络，转发数据 |
| Leader | 自动选举，管理 Router ID 分配 |
| Router | 路由转发，需持续供电 |
| REED | Router-Eligible End Device，可升级为 Router |
| End Device (ED) | 终端设备，不转发数据 |
| Sleepy ED (SED) | 休眠终端设备，定期唤醒轮询 |
| MED | Minimal End Device，不休眠但不转发 |

### 5.2 Matter 协议

Matter（原 Project CHIP，由 CSA 联盟推出）是智能家居统一应用层标准。

#### Matter 架构

```
Matter 协议栈：

┌──────────────────────────────────────────────┐
│         应用层（Application Clusters）        │  灯光、温控、门锁等
├──────────────────────────────────────────────┤
│         数据模型层（Data Model）              │  Node → Endpoint → Cluster → Attribute
├──────────────────────────────────────────────┤
│         交互模型层（Interaction Model）       │  Read / Write / Subscribe / Invoke
├──────────────────────────────────────────────┤
│         安全层（Message Layer）               │  加密、认证、消息分帧
├──────────────────────────────────────────────┤
│         传输层                               │  TCP / UDP / MRP / BLE
├──────────────────────────────────────────────┤
│         网络层                               │  IPv6（WiFi / Thread / Ethernet）
└──────────────────────────────────────────────┘
```

#### Matter 数据模型

```
Matter Node（节点）
├── Endpoint 0（根端点，管理功能）
│   ├── Basic Information Cluster
│   ├── Network Commissioning Cluster
│   └── ...
├── Endpoint 1（功能端点）
│   ├── On/Off Cluster
│   ├── Level Control Cluster
│   └── Color Control Cluster
└── Endpoint 2（另一个功能端点）
    ├── Temperature Measurement Cluster
    └── Humidity Measurement Cluster
```

#### Matter 传输层选项

| 传输方式 | 底层技术 | 适用场景 |
|---------|---------|---------|
| WiFi | 802.11 | 高带宽（摄像头、音箱） |
| Thread | 802.15.4 + 6LoWPAN | 低功耗 Mesh（传感器、开关） |
| Ethernet | 有线 | 网关、桥接器 |
| BLE | 仅用于配网（Commissioning） | 设备初次配置 |

### 5.3 Thread + Matter 组合

Thread 提供网络层，Matter 提供应用层，两者配合形成完整的智能家居方案：

```
典型 Thread + Matter 系统：

[手机 App] ←WiFi→ [Thread Border Router / 智能音箱]
                          ↓ Thread Mesh
              ┌───────────┼───────────┐
           [灯泡]      [温湿度传感器]  [门锁]
              ↓                          ↓
           [开关]                     [传感器]

所有设备通过 Matter 统一数据模型交互，
Thread 提供 IPv6 Mesh 网络传输。
```

## 六、LoRa / LoRaWAN

### 6.1 LoRa 调制技术

LoRa（Long Range）是 Semtech 公司的专利调制技术，基于 CSS（线性调频扩频）。

#### LoRa 核心参数

| 参数 | 说明 | 取值范围 |
|------|------|---------|
| 扩频因子 SF | SF 越大 → 距离越远、速率越低 | SF7–SF12 |
| 带宽 BW | 信道带宽 | 125 / 250 / 500 kHz |
| 编码率 CR | 前向纠错编码率 | 4/5、4/6、4/7、4/8 |

#### 数据速率与 SF 的关系（BW = 125 kHz）

| SF | 码片数/SF | 符号时间 | 数据速率 | 灵敏度 | 覆盖 |
|----|----------|---------|---------|--------|------|
| 7 | 128 | 1.024 ms | 5.47 kbps | -123 dBm | 近 |
| 8 | 256 | 2.048 ms | 3.13 kbps | -126 dBm | ↓ |
| 9 | 512 | 4.096 ms | 1.76 kbps | -129 dBm | ↓ |
| 10 | 1024 | 8.192 ms | 0.98 kbps | -132 dBm | ↓ |
| 11 | 2048 | 16.384 ms | 0.44 kbps | -134.5 dBm | ↓ |
| 12 | 4096 | 32.768 ms | 0.25 kbps | -137 dBm | 远 |

#### LoRa 链路预算计算

```
示例：SF7, BW=125kHz, 发射功率 +14 dBm

发射功率：           +14 dBm
发射天线增益：        +2 dBi
自由空间路径损耗：    -111 dB (10 km, 868 MHz)
其他损耗（余量）：    -10 dB
接收天线增益：        +2 dBi
────────────────────────────
接收信号强度：        -103 dBm
接收灵敏度（SF7）：   -123 dBm
────────────────────────────
链路余量：            20 dB ✓ 足够
```

### 6.2 LoRaWAN 协议

LoRaWAN 是 LoRa 之上的 MAC 层和网络架构协议，由 LoRa Alliance 标准化。

#### LoRaWAN 网络架构

```
[终端设备] ←LoRa→ [网关] ←IP→ [网络服务器] ←API→ [应用服务器]
  (End Node)    (Gateway)    (Network Server)   (Application Server)
                  ↑                ↑
              可多个网关       集中管理、去重、
              接收同一消息     自适应速率(ADR)
```

#### LoRaWAN 设备类别

| 类别 | 下行窗口 | 功耗 | 延迟 | 典型应用 |
|------|---------|------|------|---------|
| **Class A** | 仅在每次上行后开两个短接收窗口（RX1/RX2） | 最低 | 最高（不确定） | 传感器、水表、烟感 |
| **Class B** | 在 Class A 基础上，周期性接收 Beacon + 调度下行时隙 | 中等 | 中等（可预测） | 需要定期下行控制的设备 |
| **Class C** | 持续监听（仅发送时关闭接收） | 最高 | 最低 | 路灯、执行器、需即时控制 |

```
Class A 通信时序：

上行 TX → RX1（1s 后）→ RX2（2s 后）
  ↓
设备休眠
  ↓
下次上行 TX → RX1 → RX2
  ↓
...

Class B 通信时序：

Beacon ← Beacon ← Beacon  （周期性同步）
  ↓
上行 TX → RX1 → RX2
  ↓
[调度下行时隙 Ping Slot] ← 网关在此窗口发送下行
  ↓
上行 TX → ...
```

#### 自适应数据速率（ADR）

- 网络服务器根据链路质量动态调整终端的 SF 和发射功率
- 链路好 → 降低 SF（提高速率、减少占空比）
- 链路差 → 提高 SF（增强抗干扰、增大覆盖）

#### LoRaWAN 安全

双层加密：
- **NwkSKey**：网络会话密钥，用于 MAC 层完整性校验（MIC）
- **AppSKey**：应用会话密钥，用于应用层数据加密/解密
- OTAA（Over-The-Air Activation）：动态密钥协商，更安全
- ABP（Activation By Personalization）：预置密钥，简单但安全性低

### 6.3 LoRaWAN 区域参数

| 区域 | 频段 | 最大发射功率 | 信道数 |
|------|------|------------|--------|
| EU868 | 863–870 MHz | +14 dBm (25 mW) | 3–8（可扩展） |
| US915 | 902–928 MHz | +30 dBm (1 W) | 64 上行 + 8 下行 |
| CN470 | 470–510 MHz | +17 dBm (50 mW) | 96 上行 |
| AS923 | 920–925 MHz | +16 dBm | 8–16 |

> [!note] 中国 LoRa 频段
> 中国大陆使用 CN470 频段（470–510 MHz），最大发射功率 17 dBm。需注意各地无线电管理政策可能不同。

## 七、NB-IoT

### 7.1 NB-IoT 概述

NB-IoT（Narrowband Internet of Things）是 3GPP 标准化的蜂窝物联网技术，工作在授权频段。

| 参数 | 规格 |
|------|------|
| 标准 | 3GPP Release 13+ |
| 频段 | 授权频段（运营商 LTE 频段内/保护带/独立部署） |
| 带宽 | 180 kHz（单 PRB） |
| 下行 | OFDMA，15 kHz 子载波间隔 |
| 上行 | SC-FDMA，15 kHz / 3.75 kHz 子载波间隔 |
| 数据速率 | 下行 ~250 kbps，上行 ~250 kbps（多 tone）/ ~20 kbps（单 tone） |
| 双工模式 | FDD（半双工） |
| 发射功率 | 20/23 dBm（Class 3） |

### 7.2 NB-IoT 部署模式

```
三种部署模式：

1. Standalone（独立部署）：
   独立占用一个运营商频段
   |  NB-IoT (180 kHz)  |

2. In-band（带内部署）：
   在 LTE 载波内占用 1 个 PRB
   |  LTE 信号  | NB |  LTE 信号  |

3. Guard-band（保护带部署）：
   利用 LTE 载波的保护带
   |  LTE 信号  | Guard | NB | Guard |
```

### 7.3 NB-IoT 省电技术

#### eDRX（Extended Discontinuous Reception）

- 扩展的非连续接收周期
- 传统 DRX 周期：2.56 s
- eDRX 周期：最长可配置到 ~43 min（PTW 窗口内寻呼）
- 适用于可容忍一定下行延迟的设备

```
eDRX 时序：

| 休眠（eDRX 周期，最长 ~43min）  | PTW 寻呼窗口 | 休眠 ...
                                   ↑
                              设备在此窗口监听寻呼
```

#### PSM（Power Saving Mode）

- 设备注册后进入 PSM，不再监听寻呼
- 仅在设备主动上行或 TAU 定时器到期时唤醒
- 功耗接近关机水平（μA 级）
- 最大 TAU 周期：310 小时（约 12.9 天）

```
PSM 时序：

连接 → 数据传输 → 连接释放 → Active Timer → PSM 休眠
                                              ↓
                                     TAU Timer 到期 → 唤醒注册 → 数据传输
```

#### PSM vs eDRX 对比

| 特性 | PSM | eDRX |
|------|-----|------|
| 下行可达性 | 不可达（PSM 期间） | 可达（PTW 窗口内） |
| 功耗 | 极低 | 低 |
| 下行延迟 | 最长 ~310 小时 | 最长 ~43 分钟 |
| 适用场景 | 仅上行（抄表、报警） | 需偶尔下行（配置更新） |

### 7.4 NB-IoT 覆盖增强

NB-IoT 通过重复传输和窄带处理增益实现覆盖增强：

- **MCL（Maximum Coupling Loss）**：最大耦合损耗
  - NB-IoT：164 dB（CE Level 2，比 GPRS 多 20 dB）
  - 对应覆盖：地下室、井下、偏远农村
- **覆盖增强等级**：
  - CE Level 0：正常覆盖（MCL ≤ 144 dB）
  - CE Level 1：增强覆盖（MCL ≤ 154 dB），重复传输
  - CE Level 2：极端覆盖（MCL ≤ 164 dB），更多重复

### 7.5 NB-IoT vs LoRa 对比

| 特性 | NB-IoT | LoRa/LoRaWAN |
|------|--------|-------------|
| 频段 | 授权频段 | ISM 非授权频段 |
| 网络 | 运营商基站 | 自建网关/社区网络 |
| 覆盖 | MCL 164 dB | MCL ~155 dB（SF12） |
| 数据速率 | ~250 kbps | 0.25–50 kbps |
| 功耗 | PSM 模式下极低 | Class A 极低 |
| 延迟 | 秒级（连接态）| 秒~分钟级（Class A） |
| 安全 | 运营商级（SIM） | AES-128 |
| 成本 | 需 SIM 卡 + 流量费 | 无月费，网关自建 |
| 移动性 | 支持（小区切换） | 不支持 |
| 定位 | 基站定位（精度百米级）| RSSI/TDoA（精度一般） |
| 适用场景 | 广域覆盖、移动资产 | 局域覆盖、自建网络 |

## 八、5G / 4G 蜂窝通信

### 8.1 蜂窝物联网技术演进

```
蜂窝物联网演进路线：

2G (GSM) → GPRS → EDGE
                    ↓
3G (WCDMA) → HSPA → HSPA+
                        ↓
4G (LTE) → LTE-A → LTE Cat-1 → Cat-4 → Cat-M1 (eMTC) → NB-IoT
                                                            ↓
5G NR → eMBB → uRLLC → mMTC (NB-IoT/eMTC 作为 5G mMTC 组成)
```

#### LTE 物联网 Category 对比

| Category | 下行速率 | 上行速率 | 带宽 | 功率 | 特点 |
|----------|---------|---------|------|------|------|
| Cat-1 | 10 Mbps | 5 Mbps | 20 MHz | Class 3 | 中速率，无需升级网络 |
| Cat-4 | 150 Mbps | 50 Mbps | 20 MHz | Class 3 | 高速率，路由器/视频 |
| Cat-M1 (eMTC) | 1 Mbps | 1 Mbps | 1.4 MHz | Class 3 | 中速率 IoT，支持移动性 |
| NB-IoT (Cat-NB1) | 250 kbps | 250 kbps | 180 kHz | Class 3/5 | 极低速率，深度覆盖 |

### 8.2 5G 三大场景

| 场景 | 全称 | 特点 | 典型应用 |
|------|------|------|---------|
| **eMBB** | Enhanced Mobile Broadband | 大带宽、高速率 | 4K/8K 视频、VR/AR |
| **uRLLC** | Ultra-Reliable Low Latency | 超可靠、超低延迟（<1ms）| 自动驾驶、远程手术、工业控制 |
| **mMTC** | massive Machine Type Comm. | 海量连接（100 万设备/km2）| 智能城市、环境监测 |

#### 5G NR 关键技术

- **灵活子载波间隔**：15/30/60/120/240 kHz（Numerology）
- **毫米波**：24.25–52.6 GHz，超大带宽
- **Massive MIMO**：64T64R 甚至 128 天线
- **网络切片**：同一物理网络虚拟出不同特性的逻辑网络
- **边缘计算 MEC**：数据在基站侧处理，降低延迟

### 8.3 4G/5G 模组 AT 指令开发

蜂窝模组通常通过 UART + AT 指令与 MCU 通信。

#### 常用 AT 指令（3GPP TS 27.007）

```bash
# 基本操作
AT                    # 测试 AT 通道
ATE1                  # 开启回显
AT+CPIN?              # 查询 SIM 卡状态
AT+CSQ                # 查询信号强度（RSSI）

# 网络注册
AT+CEREG?             # EPS 网络注册状态
AT+COPS?              # 查询运营商
AT+COPS=0             # 自动选网

# 数据连接
AT+CGDCONT=1,"IP","your_apn"  # 设置 APN
AT+CGACT=1,1          # 激活 PDP 上下文
AT+CGPADDR=1          # 查询分配的 IP 地址

# TCP/UDP
AT+CIPSTART="TCP","server_ip",port  # 建立 TCP 连接
AT+CIPSEND=length      # 发送数据
+CIPRXGET:             # 接收数据 URC

# 省电
AT+CPSMS=1,,,"01000011","01000011"  # 开启 PSM
AT+CEDRXS=1,4,"0010"  # 开启 eDRX

# 电量
AT+CBC                 # 查询电池电量
```

## 九、Sub-GHz 频段通信

### 9.1 Sub-GHz 概述

Sub-GHz 指工作频率低于 1 GHz 的无线通信，主要使用 ISM 频段：

| 频段 | 频率 | 主要区域 | 典型应用 |
|------|------|---------|---------|
| 315 MHz | 315 MHz | 美国、中国 | 遥控器、车库门 |
| 433 MHz | 433.05–434.79 MHz | 全球（欧洲、中国等） | 无线门铃、温湿度传感器 |
| 868 MHz | 868–870 MHz | 欧洲 | LoRa、无线传感器 |
| 915 MHz | 902–928 MHz | 美洲 | LoRa、Zigbee Sub-GHz |

### 9.2 Sub-GHz 的优势

- **传播距离远**：频率越低，自由空间损耗越小，绕射能力越强
- **穿透能力好**：穿墙能力优于 2.4 GHz
- **干扰少**：Sub-GHz 频段设备少于 2.4 GHz
- **功耗低**：较低的数据速率通常意味着更低的功耗

### 9.3 Sub-GHz 无线技术对比

| 技术 | 频段 | 速率 | 距离 | 功耗 | 协议 |
|------|------|------|------|------|------|
| TI CC13xx Proprietary | Sub-GHz | 可配置 | 数 km | 极低 | 私有协议 |
| Zigbee Sub-GHz | 868/915 MHz | 20–40 kbps | ~100 m | 低 | Zigbee |
| LoRa | 868/915/433 MHz | 0.25–50 kbps | 数 km~20 km | 极低 | LoRaWAN |
| Sigfox | 868/915 MHz | 100 bps | 数 km~50 km | 极低 | Sigfox |
| Wireless M-Bus | 868 MHz | 2.4–100 kbps | ~1 km | 低 | M-Bus（欧洲表计） |
| Wize | 169 MHz | ~2.4 kbps | 数十 km | 低 | 水表/燃气表 |

| 芯片 | 厂商 | 频段 | 特点 |

### 10.4 成本分析框架

```
总拥有成本 = 硬件成本 + 运营成本 + 基础设施成本

硬件成本（每节点）：
  芯片/模组 + 天线 + PCB + 其他 BOM

运营成本（年）：
  蜂窝流量费（NB-IoT/4G: ¥120–360/年）
  云平台费用
  维护费用

基础设施成本：
  LoRa 网关：¥500–3000/个（覆盖 2–10 km）
  WiFi AP：¥200–1000/个（覆盖 30–100 m）
  Zigbee 网关：¥100–500/个

盈亏平衡分析：
  当节点数量 > N 时，自建 LoRa 网关的总成本低于 NB-IoT 流量费
  N ≈ 网关成本 / (NB-IoT 年费 × 使用年限)
```

## 十一、天线基础

### 11.1 天线基本参数

| 参数 | 符号 | 说明 |
|------|------|------|
| 频率 | f | 天线谐振频率，决定天线尺寸 |
| 增益 | G | dBi（相对于各向同性天线）/ dBd（相对于偶极子）|
| 带宽 | BW | 天线有效工作的频率范围 |
| 阻抗 | Z | 通常 50 Ω，需与射频电路匹配 |
| VSWR | — | 电压驻波比，理想值 1:1，通常要求 < 2:1 |
| 回波损耗 | S11 | 反射功率，通常要求 < -10 dB |
| 方向图 | — | 天线辐射方向分布（全向/定向）|
| 极化 | — | 线极化（垂直/水平）/ 圆极化 |

### 11.2 天线类型

#### 11.2.1 PCB 天线（板载天线）

- 直接在 PCB 上蚀刻的天线
- 类型：
  - **蛇形/meander 天线**：紧凑，适合 2.4 GHz
  - **倒 F 天线（IFA/PIFA）**：手机常用，性能好
  - **贴片天线（Patch）**：定向辐射，适合 GPS
  - **环形天线（Loop）**：适合 NFC（13.56 MHz）
- 优点：无额外成本、体积小
- 缺点：性能受 PCB 布局影响、增益有限

```
PCB Meander 天线示意：
┌─────────────────────────┐
│  ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐  │
│  │ │ │ │ │ │ │ │ │ │  │  ← 蛇形走线
│  │ └─┘ └─┘ └─┘ └─┘ │  │
│  └───────────────────┘  │
│        PCB 板            │
└─────────────────────────┘
```

#### 11.2.2 外置天线

- 通过连接器（SMA、U.FL、IPEX）连接到 PCB
- 类型：
  - **鞭状天线（Whip）**：全向，最常见
  - **胶棒天线（Rubber Duck）**：全向，有保护外壳
  - **吸盘天线**：高增益，通过馈线连接
  - **八木天线（Yagi）**：高增益定向
  - **面板天线（Panel）**：定向，壁挂安装
- 优点：性能好、可更换
- 缺点：增加成本和体积

#### 11.2.3 陶瓷天线

- 利用陶瓷介质缩小天线尺寸
- 类型：
  - **陶瓷贴片天线（Ceramic Patch）**：GPS 天线常用
  - **陶瓷芯片天线（Chip Antenna）**：极小尺寸，适合可穿戴
- 优点：尺寸极小、性能较好
- 缺点：带宽窄、对 PCB 布局敏感

### 11.3 天线增益与方向图

#### 增益

- **dBi**：相对于各向理想点源天线的增益
  - 0 dBi = 理想点源（球形辐射）
  - 2.15 dBi = 半波偶极子（Dipole）
  - 5–8 dBi = 全向高增益天线（鞭状）
  - 10–15 dBi = 定向天线（八木/面板）
- **dBd**：相对于半波偶极子
  - dBd = dBi - 2.15

增益越高 → 能量越集中 → 覆盖方向更远、但覆盖角度更窄

```
方向图示意：

全向天线（如偶极子）         定向天线（如八木）
俯视：                      俯视：
    ┌───┐                      │
    │   │                   ───┼───→
    └───┘                      │
  360° 均匀                  主瓣窄、增益高
```

#### 天线方向图参数

- **主瓣（Main Lobe）**：增益最大的方向
- **半功率波束宽度（HPBW）**：主瓣增益下降 3 dB 的角度范围
- **副瓣（Side Lobe）**：除主瓣外的辐射方向
- **前后比（F/B Ratio）**：主瓣最大增益与反向增益之比

### 11.4 阻抗匹配

射频系统标准阻抗为 50 Ω，天线阻抗需要与之匹配：

#### VSWR（电压驻波比）

$$VSWR = \frac{1 + |\Gamma|}{1 - |\Gamma|}$$

其中 Γ 为反射系数。VSWR 与反射功率的关系：

| VSWR | 反射功率 | 回波损耗 | 匹配质量 |
|------|---------|---------|---------|
| 1:1 | 0% | ∞ dB | 完美匹配（理想） |
| 1.5:1 | 4% | -14 dB | 优秀 |
| 2:1 | 11% | -9.5 dB | 良好（通常可接受） |
| 3:1 | 25% | -6 dB | 一般 |
| 10:1 | 67% | -0.9 dB | 差（大量反射） |

> [!important] VSWR < 2:1 的意义
> VSWR < 2:1 意味着反射功率 < 11%，即 > 89% 的功率被天线辐射出去。这是工程设计中通常的最低要求。

#### 阻抗匹配网络

当天线阻抗不等于 50 Ω 时，需要匹配网络调节：

```
常见匹配网络拓扑：

1. L 型匹配（最简单）：
   RF ─┤L├──┬── 天线
           │
          ┤C├
           │
          GND

2. Pi 型匹配：
   RF ─┬──┤L├──┬── 天线
      │       │
     ┤C1├    ┤C2├
      │       │
     GND     GND

3. 传输线匹配：
   使用 λ/4 阻抗变换器
```

### 11.5 天线布局注意事项

1. **净空区（Keep-Out Area）**：天线周围不能有铜皮、走线、金属件
2. **接地面（Ground Plane）**：多数天线需要足够大的接地面作为参考
3. **馈线**：PCB 走线需做 50 Ω 阻抗控制（微带线/带状线）
4. **朝向**：天线远离金属外壳、电池、LCD 等
5. **连接器**：U.FL（板端）+ SMA（外接天线）常用组合
6. **多天线隔离**：多天线系统需注意隔离度（通常 > 15 dB）

```
PCB 天线布局示意：

┌─────────────────────────────────────┐
│                              ┌──────┐│
│  主板区域                      │ 天线 ││
│  （有地平面）                   │ 净空区││
│  （IC、走线等）                 │(无铜)││
│                              └──────┘│
│←────── 主板 ─────→│←── 天线区域 ──→│
└─────────────────────────────────────┘

天线区域：无铜、无器件、无走线
馈线：50 Ω 微带线连接到天线
```
