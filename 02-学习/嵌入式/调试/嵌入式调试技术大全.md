## 1. 调试工具概述

### 1.1 主流调试器对比

| 特性 | J-Link | ST-Link | DAP-Link | ESP-Prog |
|------|--------|---------|----------|----------|
| 厂商 | SEGGER | ST Micro | ARM/OpenOCD | Espressif |
| 支持芯片 | 几乎所有ARM | STM32为主 | ARM Cortex-M | ESP32系列 |
| 调试接口 | SWD/JTAG | SWD/JTAG | SWD | JTAG |
| 最大时钟 | 50 MHz (SWD) | 4 MHz | 10 MHz | 20 MHz |
| RTT支持 | 原生支持 | 不支持 | 不支持 | 不支持 |
| 价格 | 较贵(数百元) | 便宜/自带 | 便宜 | 便宜 |
| 固件更新 | 频繁 | 偶尔 | 开源 | 偶尔 |
| 虚拟串口 | 有(UART) | 有(VCP) | 有(CDC) | 有(两路) |
| Ozone调试 | 支持 | 不支持 | 不支持 | 不支持 |

### 1.2 J-Link 系列

J-Link 是 SEGGER 公司出品的专业调试器，功能最为全面。

**型号分类：**
- **J-Link EDU**：教育版，功能完整但仅限非商业用途
- **J-Link BASE**：基础商业版
- **J-Link PLUS**：增加 Flash BP、Flash DL 等高级功能
- **J-Link Ultra+**：高速版，支持高达 50 MHz SWD
- **J-Link PRO**：以太网接口，支持远程调试

**J-Link 关键特性：**
```
- 无限 Flash 断点（Flash BP 需要 PLUS 及以上）
- RTT 实时传输（替代 printf，零延迟）
- SWO 数据流（ITM/ETM）
- GDB Server 内置
- 支持 J-Flash 独立烧录
- Ozone 图形化调试器
- 支持 5000+ 种 MCU
```

**J-Link 常用命令（J-Link Commander）：**
```bash
# 连接目标
connect
# 选择设备
device STM32F407VG
# 设置接口速度
speed 4000
# 读取寄存器
reg
# 读取内存
mem32 0x20000000 0x10
# 写入内存
w4 0x20000000 0xDEADBEEF
# 复位
r
# 运行
go
# 暂停
halt
# 烧录固件
loadfile firmware.bin 0x08000000
```

### 1.3 ST-Link

ST-Link 是 ST 官方调试器，通常集成在 Nucleo/Discovery 开发板上。

**型号：**
- **ST-Link/V2**：经典版，SWD/JTAG
- **ST-Link/V2-1**：Nucleo 板载，增加 VCP 和 MSD
- **ST-Link/V3**：支持更高速度、多协议

**ST-Link 升级固件：**
```bash
# 使用 ST-Link Upgrade 工具
# 或通过 STM32CubeProgrammer
STM32_Programmer_CLI -c port=SWD freq=4000
```

### 1.4 DAP-Link

DAP-Link 是 ARM 官方开源的调试器方案，基于 CMSIS-DAP 协议。

**优势：**
- 完全开源（GitHub: ARMmbed/DAPLink）
- 支持所有 ARM Cortex-M 处理器
- 通过 USB HID 通信，免驱动
- 支持 MSD 拖拽烧录
- 兼容 OpenOCD、pyOCD 等工具

**DAP-Link 配置 OpenOCD：**
```bash
openocd -f interface/cmsis-dap.cfg -f target/stm32f4x.cfg
```

### 1.5 ESP-Prog

ESP-Prog 是乐鑫官方调试工具，专为 ESP32 系列设计。

**功能：**
- JTAG 调试接口（用于 OpenOCD）
- 两路串口（UART0/UART1）
- 自动下载电路（EN + BOOT 控制）
- 支持 ESP32/ESP32-S2/S3/C3/C6/H2

**ESP-Prog OpenOCD 配置：**
```bash
openocd -f interface/ftdi/esp32_devkitj_v1.cfg -f target/esp32.cfg
```

## 2. GDB 调试

### 2.1 GDB 远程调试架构

```
┌─────────────┐     TCP/IP      ┌──────────────┐    SWD/JTAG    ┌──────────┐
│   GDB 客户端 │ ◄────────────► │  GDB Server  │ ◄────────────► │  目标MCU  │
│  (arm-none-  │   port 3333    │ (J-Link GDB  │                │          │
│   eabi-gdb)  │                │  Server/OpenOCD)               │          │
└─────────────┘                 └──────────────┘                └──────────┘
```

### 2.2 启动 GDB Server

**J-Link GDB Server：**
```bash
JLinkGDBServer -device STM32F407VG -if SWD -speed 4000 -port 3333
```

**OpenOCD 作为 GDB Server：**
```bash
openocd -f interface/jlink.cfg -f target/stm32f4x.cfg
# 默认监听 3333 端口（GDB）和 4444 端口（Telnet）
```

**pyOCD：**
```bash
pyocd gdbserver --target stm32f407vg --port 3333
```

### 2.3 GDB 客户端连接

```bash
# 启动 GDB
arm-none-eabi-gdb firmware.elf

# 连接 GDB Server
(gdb) target remote localhost:3333

# 加载固件到目标
(gdb) load

# 复位目标
(gdb) monitor reset

# 设置初始断点并运行
(gdb) break main
(gdb) continue
```

### 2.4 断点（Breakpoint）

```bash
# 函数断点
(gdb) break main
(gdb) break app_init

# 行断点
(gdb) break main.c:42

# 条件断点：仅当满足条件时中断
(gdb) break main.c:42 if count > 100

# 临时断点：命中一次后自动删除
(gdb) tbreak main

# 硬件断点（Flash 中的代码必须使用硬件断点）
(gdb) hbreak flash_function

# 查看所有断点
(gdb) info breakpoints

# 禁用/启用断点
(gdb) disable 1
(gdb) enable 1

# 删除断点
(gdb) delete 1
(gdb) delete          # 删除所有
```

### 2.5 观察点（Watchpoint）

观察点用于监视变量或内存地址的变化。

```bash
# 写观察点：变量被写入时中断
(gdb) watch my_variable

# 读观察点：变量被读取时中断
(gdb) rwatch my_variable

# 读写观察点
(gdb) awatch my_variable

# 硬件观察点（MCU 通常只有 2-4 个）
(gdb) watch *(uint32_t*)0x20000100

# 查看观察点
(gdb) info watchpoints
```

### 2.6 内存查看与修改

```bash
# 查看内存（十六进制）
(gdb) x/16xb 0x20000000     # 16 字节，十六进制
(gdb) x/8xw 0x20000000      # 8 个字（32位），十六进制
(gdb) x/32xb &my_array      # 查看数组

# 格式说明
# x/[数量][格式][大小] 地址
# 格式: x=十六进制, d=十进制, u=无符号, t=二进制, c=字符, s=字符串
# 大小: b=字节, h=半字(16位), w=字(32位), g=巨字(64位)

# 打印变量
(gdb) print my_variable
(gdb) print/x my_variable   # 十六进制
(gdb) print/t my_variable   # 二进制
(gdb) print *my_pointer     # 解引用
(gdb) print my_struct       # 打印结构体

# 修改内存
(gdb) set {uint32_t}0x20000000 = 0xDEADBEEF
(gdb) set my_variable = 42

# 搜索内存
(gdb) find /b 0x20000000, 0x2000FFFF, 0xAA
(gdb) find /w 0x20000000, 0x2000FFFF, 0xDEADBEEF
```

### 2.7 寄存器查看

```bash
# 查看所有寄存器
(gdb) info registers

# 查看特定寄存器
(gdb) print $pc
(gdb) print $sp
(gdb) print $lr
(gdb) print $r0

# 查看浮点寄存器
(gdb) info registers float

# 查看特殊寄存器
(gdb) print/x $xPSR
(gdb) print/x $CONTROL
(gdb) print/x $FAULTMASK
(gdb) print/x $BASEPRI

# 通过 Monitor 命令读取外设寄存器
(gdb) monitor mem32 0x40023C00 1   # 读 Flash 寄存器
(gdb) monitor reg                   # 读 CPU 寄存器
```

### 2.8 Core Dump 分析

Core Dump 是在程序崩溃时保存的内存快照，用于事后分析。

**生成 Core Dump（通过 GDB）：**
```bash
# 连接目标后，导出内存
(gdb) dump binary memory core_dump.bin 0x20000000 0x2001FFFF
(gdb) dump binary memory flash_dump.bin 0x08000000 0x080FFFFF
```

**使用 J-Link 导出：**
```bash
# J-Link Commander
savebin core_dump.bin 0x20000000 0x20000
savebin flash_dump.bin 0x08000000 0x100000
```

**加载 Core Dump 分析：**
```bash
# 加载 ELF 和 core dump
arm-none-eabi-gdb firmware.elf
(gdb) target remote localhost:3333
(gdb) restore core_dump.bin 0x20000000
(gdb) bt           # 查看调用栈
(gdb) info locals  # 查看局部变量
```

**ESP-IDF Core Dump：**
```bash
# ESP32 内置 Core Dump 功能
idf.py coredump-info    # 解析 Core Dump
idf.py coredump-debug   # GDB 调试 Core Dump
```

## 3. SWD/JTAG 接口

### 3.1 SWD 引脚定义

SWD（Serial Wire Debug）只需要 2 根信号线。

| 引脚 | 名称 | 说明 |
|------|------|------|
| SWDIO | 数据 I/O | 双向数据线，开漏输出需上拉 |
| SWCLK | 时钟 | 调试时钟，由调试器驱动 |
| GND | 地 | 必须连接 |
| SWO | 串行输出 | 可选，用于 ITM/ETM 跟踪 |
| NRST | 复位 | 可选，调试器控制复位 |
| VCC | 电源参考 | 可选，用于电平检测 |

**标准 10-pin SWD 接口（ARM Cortex）：**
```
       ┌─────────┐
  VCC  │ 1     2 │ SWDIO
  GND  │ 3     4 │ SWCLK
  GND  │ 5     6 │ SWO (可选)
  GND  │ 7     8 │ NC
  GND  │ 9    10 │ NRST
       └─────────┘
```

**常见 4-wire 最小连接：**
```
调试器          目标MCU
SWDIO ────────── SWDIO
SWCLK ────────── SWCLK
GND   ────────── GND
VCC   ────────── VCC (参考电压)
```

### 3.2 JTAG 引脚定义

JTAG 需要 4-5 根信号线。

| 引脚 | 名称 | 说明 |
|------|------|------|
| TDI | 数据输入 | 数据从调试器到目标 |
| TDO | 数据输出 | 数据从目标到调试器 |
| TCK | 时钟 | 测试时钟 |
| TMS | 模式选择 | 状态机控制 |
| TRST | 复位 | 可选，TAP 控制器复位 |

**标准 20-pin JTAG 接口：**
```
        ┌───────────┐
  VCC   │  1     2  │ VCC
  TMS   │  3     4  │ GND
  TCK   │  5     6  │ GND
  TDO   │  7     8  │ GND
  TRST  │  9    10  │ GND
  TDI   │ 11    12  │ GND
  GND   │ 13    14  │ GND
  NRST  │ 15    16  │ GND
  GND   │ 17    18  │ GND
  GND   │ 19    20  │ GND
        └───────────┘
```

### 3.3 SWD vs JTAG 速度对比

| 特性 | SWD | JTAG |
|------|-----|------|
| 信号线数 | 2 (SWDIO+SWCLK) | 4-5 (TDI+TDO+TCK+TMS) |
| 最大频率 | 50 MHz (J-Link Ultra+) | 20-100 MHz |
| 引脚复用 | 仅 SWD 调试 | 可菊花链接多设备 |
| 适用场景 | 单芯片调试首选 | 多核/多芯片调试 |
| 突出优势 | 引脚少，速度够用 | 支持边界扫描(BSDL) |

**选择建议：**
- 单核 MCU 项目：**SWD**（引脚少、速度足够）
- 多核/多芯片：**JTAG**（支持菊花链）
- FPGA 调试：**JTAG**（需要边界扫描）

### 3.4 SWO 串行输出

SWO（Serial Wire Output）是 SWD 接口上的单向输出引脚，用于实时跟踪数据。

**SWO 支持的协议：**
- **UART 模式**：最常用，波特率自动协商
- **Manchester 模式**：更可靠但较少使用

**SWO 数据来源：**
- **ITM（Instrumentation Trace Macrocell）**：软件 printf 输出
- **DWT（Data Watchpoint and Trace）**：硬件事件跟踪
- **ETM（Embedded Trace Macrocell）**：指令跟踪（高端 MCU）

**配置 SWO 输出（STM32 HAL）：**
```c
// 使能 ITM
ITM->TCR = ITM_TCR_ITMENA_Msk;
ITM->TER = 1UL;  // 使能 Stimulus Port 0

// 重定向 printf 到 ITM
int fputc(int ch, FILE *f) {
    ITM_SendChar(ch);
    return ch;
}
```

**J-Link SWO 配置：**
```bash
# 启动 J-Link SWO Viewer
JLinkSWOViewer -device STM32F407VG -swofreq 6000000

# 或在 Ozone 中配置 SWO
# Project Settings -> Trace -> Enable SWO
# SWO Frequency: 6000000 (6 MHz)
# ITM Port: 0
```

## 4. RTT (Real-Time Transfer)

### 4.1 RTT 原理

J-Link RTT 是 SEGGER 开发的实时数据传输技术，通过在目标 RAM 中放置一个环形缓冲区实现双向通信。

```
┌─────────────┐         ┌─────────────┐
│   目标 MCU   │         │   J-Link    │
│             │         │             │
│  ┌───────┐  │  RAM    │  ┌───────┐  │
│  │Up Buffer│ ────────► │  │J-Link │  │
│  │(Target→Host)        │  │RTT    │  │
│  └───────┘  │         │  │Viewer │  │
│             │         │  └───────┘  │
│  ┌───────┐  │         │  ┌───────┐  │
│  │Down   │ ◄──────── │  │Host→  │  │
│  │Buffer │  │  RAM    │  │Target │  │
│  └───────┘  │         │  └───────┘  │
└─────────────┘         └─────────────┘
```

**RTT 核心优势：**
- **零延迟**：不需要等待串口传输完成
- **极高速度**：可达 2 MB/s 以上
- **双向通信**：支持 Host 发送数据到 Target
- **不占用外设**：纯 RAM 操作，不占用 UART
- **最小侵入**：对程序执行几乎无影响
- **输出可选**：可以在调试器端开关，不影响程序执行

### 4.2 SEGGER_RTT 移植

**步骤 1：添加 RTT 源文件**

从 J-Link 安装目录或 SEGGER 官网获取：
```
SEGGER_RTT/
├── RTT/
│   ├── SEGGER_RTT.c
│   ├── SEGGER_RTT.h
│   ├── SEGGER_RTT_Conf.h    # 配置文件
│   └── SEGGER_RTT_printf.c  # 可选，格式化输出
└── Syscalls/
    └── SEGGER_RTT_Syscalls_SES.c  # SES 集成
```

**步骤 2：配置 SEGGER_RTT_Conf.h**
```c
// RTT 缓冲区大小
#define BUFFER_SIZE_UP      (1024)   // Target -> Host 缓冲区
#define BUFFER_SIZE_DOWN    (16)     // Host -> Target 缓冲区

// 模式选择
#define SEGGER_RTT_MODE_DEFAULT     SEGGER_RTT_MODE_NO_BLOCK_SKIP
// SEGGER_RTT_MODE_NO_BLOCK_SKIP   缓冲区满时丢弃数据
// SEGGER_RTT_MODE_NO_BLOCK_TRIM   缓冲区满时截断数据
// SEGGER_RTT_MODE_BLOCK_IF_FIFO_FULL  阻塞等待（可能导致程序卡住）

// 使能 RTT 控制块搜索
#define SEGGER_RTT_IN_RAM           0
```

**步骤 3：代码中使用 RTT**
```c
#include "SEGGER_RTT.h"

void app_init(void) {
    // 初始化（通常不需要，自动初始化）
    SEGGER_RTT_Init();

    // 输出字符串
    SEGGER_RTT_WriteString(0, "Hello RTT!\n");

    // 格式化输出（类似 printf）
    SEGGER_RTT_printf(0, "Count: %d, Value: 0x%08X\n", count, value);

    // 二进制数据输出
    uint8_t data[] = {0xAA, 0xBB, 0xCC};
    SEGGER_RTT_Write(0, data, sizeof(data));
}

void app_loop(void) {
    // 检查是否有来自 Host 的数据
    char buf[32];
    unsigned len = SEGGER_RTT_Read(0, buf, sizeof(buf) - 1);
    if (len > 0) {
        buf[len] = '\0';
        SEGGER_RTT_printf(0, "Received: %s\n", buf);
    }
}
```

### 4.5 RTT 封装 log_print

```c
// log_rtt.h
#ifndef LOG_RTT_H
#define LOG_RTT_H

#include "SEGGER_RTT.h"

// 日志级别
#define LOG_LEVEL_NONE  0
#define LOG_LEVEL_ERROR 1
#define LOG_LEVEL_WARN  2
#define LOG_LEVEL_INFO  3
#define LOG_LEVEL_DEBUG 4
#define LOG_LEVEL_VERBOSE 5

#ifndef LOG_DEFAULT_LEVEL
#define LOG_DEFAULT_LEVEL LOG_LEVEL_DEBUG
#endif

// 颜色定义（RTT 支持 ANSI 颜色）
#define RTT_COLOR_RED     "\033[31m"
#define RTT_COLOR_YELLOW  "\033[33m"
#define RTT_COLOR_GREEN   "\033[32m"
#define RTT_COLOR_CYAN    "\033[36m"
#define RTT_COLOR_RESET   "\033[0m"

#define LOG_E(tag, fmt, ...) \
    do { if (LOG_DEFAULT_LEVEL >= LOG_LEVEL_ERROR) \
        SEGGER_RTT_printf(0, RTT_COLOR_RED "[E][%s] " fmt "\n" RTT_COLOR_RESET, tag, ##__VA_ARGS__); \
    } while(0)

#define LOG_W(tag, fmt, ...) \
    do { if (LOG_DEFAULT_LEVEL >= LOG_LEVEL_WARN) \
        SEGGER_RTT_printf(0, RTT_COLOR_YELLOW "[W][%s] " fmt "\n" RTT_COLOR_RESET, tag, ##__VA_ARGS__); \
    } while(0)

#define LOG_I(tag, fmt, ...) \
    do { if (LOG_DEFAULT_LEVEL >= LOG_LEVEL_INFO) \
        SEGGER_RTT_printf(0, RTT_COLOR_GREEN "[I][%s] " fmt "\n" RTT_COLOR_RESET, tag, ##__VA_ARGS__); \
    } while(0)

#define LOG_D(tag, fmt, ...) \
    do { if (LOG_DEFAULT_LEVEL >= LOG_LEVEL_DEBUG) \
        SEGGER_RTT_printf(0, RTT_COLOR_CYAN "[D][%s] " fmt "\n" RTT_COLOR_RESET, tag, ##__VA_ARGS__); \
    } while(0)

#endif // LOG_RTT_H
```

## 5. 逻辑分析仪

### 5.1 主流逻辑分析仪对比

| 型号 | 采样率 | 通道数 | 价格 | 特点 |
|------|--------|--------|------|------|
| Saleae Logic Pro 16 | 500 MS/s | 16 | 贵 | 协议解码强大，软件体验好 |
| Saleae Logic 8 | 100 MS/s | 8 | 中等 | 性价比高 |
| DSLogic Plus | 400 MS/s | 16 | 便宜 | 开源硬件，Sigrok 兼容 |
| DSLogic U3Pro16 | 1 GS/s | 16 | 中等 | 高采样率 |
| DreamSourceLab DSView | - | - | 免费 | 开源软件，支持多种硬件 |

### 5.2 Saleae Logic 使用

**软件安装：**
- 下载 Logic 2 软件
- 连接 USB，自动识别设备

**基本测量流程：**
1. 设置采样率（至少为目标信号频率的 4 倍）
2. 设置电压阈值（通常 1.65V 对于 3.3V 系统）
3. 连接探针到目标信号
4. 设置触发条件
5. 开始采集

**触发模式：**
- **边沿触发**：上升沿/下降沿
- **电平触发**：高电平/低电平
- **模式触发**：特定数据模式
- **协议触发**：特定协议帧（高级功能）

## 6. 示波器使用技巧

### 6.1 触发设置

触发是示波器捕获稳定波形的关键。

**边沿触发（最常用）：**
```
触发条件：信号穿越触发电平且方向匹配
┌─ 设置 ─┐
│ Source:  CH1
│ Type:   Rising Edge (上升沿)
│ Level:  1.65V (3.3V 系统中点)
│ Mode:   Auto / Normal / Single
│ Coupling: DC
└────────┘
```

**脉宽触发：**
```
适用场景：检测异常窄脉冲或宽脉冲
设置：Trigger -> Pulse Width
条件：Positive Width > 10us（捕获宽度超过10us的正脉冲）
```

**欠幅触发：**
```
适用场景：检测幅度不足的异常脉冲
设置：Trigger -> Runt
条件：High Threshold = 2.5V, Low Threshold = 0.8V
```

**斜率触发：**
```
适用场景：检测上升/下降时间异常
设置：Trigger -> Slope
条件：Rise Time > 100ns
```

### 6.2 协议解码

现代示波器支持硬件协议解码。

**UART 解码设置：**
```
1. 选择信号通道
2. 数学/协议 -> UART
3. 配置参数：
   - 波特率: 115200
   - 数据位: 8
   - 校验: None
   - 停止位: 1
4. 解码结果以表格或波形叠加显示
```

**SPI 解码设置：**
```
1. 选择 MOSI/MISO/CLK/CS 通道
2. 数学/协议 -> SPI
3. 配置：
   - CPOL/CPHA: 根据从机数据手册
   - CS 极性: Active Low
   - Bit Order: MSB First
4. 解码显示每帧数据
```

### 6.3 电源纹波测量

电源纹波是评估电源质量的关键指标。

**测量方法：**
```
1. 探头设置：
   - 使用 1X 衰减（提高灵敏度）
   - 或使用 10X 探头 + 带宽限制

2. 示波器设置：
   - 带宽限制: 20 MHz（滤除高频噪声）
   - 耦合: AC（去除直流分量）
   - 垂直灵敏度: 10-50 mV/div
   - 时基: 1-10 ms/div

3. 测量技巧：
   - 缩短接地线（使用弹簧接地帽）
   - 在电源输出端就近测量
   - 使用 FFT 分析纹波频率成分
```

**纹波指标参考：**
| 应用场景 | 典型纹波要求 |
|---------|-------------|
| 数字电路 | < 100 mVpp |
| ADC 参考电压 | < 10 mVpp |
| 射频电路 | < 5 mVpp |
| 精密模拟 | < 1 mVpp |

### 6.4 信号完整性分析

**常见信号完整性问题：**

**1. 过冲/下冲（Overshoot/Undershoot）**
```
原因：阻抗不匹配、传输线效应
表现：信号超过 VCC 或低于 GND
解决：串联匹配电阻、缩短走线
```

**2. 振铃（Ringing）**
```
原因：信号反射、寄生电感电容
表现：信号在目标电平附近振荡
解决：端接匹配、减小回路面积
```

**3. 单调性问题**
```
原因：阈值电平附近有台阶
表现：信号在阈值附近停滞
解决：检查驱动能力、负载电容
```

**眼图分析：**
```
适用：高速串行信号（USB、LVDS、以太网）
方法：使用示波器的 Eye Diagram 功能
关键指标：眼高、眼宽、抖动
```

**方法 3：DMA 方式（非阻塞）**

```c
#include <stdio.h>
#include <string.h>
#include "usart.h"

#define TX_BUF_SIZE 512
static char tx_buffer[TX_BUF_SIZE];

int _write(int file, char *ptr, int len) {
    // 等待上次 DMA 传输完成
    while (huart1.gState != HAL_UART_STATE_READY) {}

    len = len < TX_BUF_SIZE ? len : TX_BUF_SIZE - 1;
    memcpy(tx_buffer, ptr, len);
    HAL_UART_Transmit_DMA(&huart1, (uint8_t *)tx_buffer, len);
    return len;
}
```

```c
// log_uart.c
#include "log_uart.h"
#include <string.h>
#include <stdio.h>
#include "usart.h"

log_level_t g_log_level = LOG_LEVEL_DEBUG;

static const char *level_str[] = {
    "", "E", "W", "I", "D", "V"
};

static const char *level_color[] = {
    "", "\033[31m", "\033[33m", "\033[32m", "\033[36m", "\033[37m"
};

void log_print(log_level_t level, const char *tag, const char *fmt, ...) {
    if (level > g_log_level) return;

    char buf[256];
    int offset = 0;

    // 添加颜色和前缀
    offset += snprintf(buf + offset, sizeof(buf) - offset,
                       "%s[%s][%s] ", level_color[level], level_str[level], tag);

    // 格式化用户消息
    va_list args;
    va_start(args, fmt);
    offset += vsnprintf(buf + offset, sizeof(buf) - offset, fmt, args);
    va_end(args);

    // 添加颜色重置和换行
    offset += snprintf(buf + offset, sizeof(buf) - offset, "\033[0m\r\n");

    // 发送（可根据实际需求选择阻塞/DMA/IT方式）
    HAL_UART_Transmit(&huart1, (uint8_t *)buf, offset, HAL_MAX_DELAY);
}
```

### 8.5 Hard Fault Handler 实现

```c
// hard_fault_handler.c
#include <stdint.h>
#include <stdio.h>

// 寄存器地址定义
#define SCB_CFSR   (*(volatile uint32_t *)0xE000ED28)
#define SCB_HFSR   (*(volatile uint32_t *)0xE000ED2C)
#define SCB_MMFAR  (*(volatile uint32_t *)0xE000ED34)
#define SCB_BFAR   (*(volatile uint32_t *)0xE000ED38)

// 异常帧结构体（压栈时自动保存）
typedef struct {
    uint32_t r0;
    uint32_t r1;
    uint32_t r2;
    uint32_t r3;
    uint32_t r12;
    uint32_t lr;   // 链接寄存器
    uint32_t pc;   // 程序计数器（故障发生位置）
    uint32_t psr;  // 程序状态寄存器
} exception_frame_t;

// 分析并打印故障信息
void hard_fault_analysis(exception_frame_t *frame) {
    printf("\n=== HARD FAULT ===\n");
    printf("R0  = 0x%08lX\n", frame->r0);
    printf("R1  = 0x%08lX\n", frame->r1);
    printf("R2  = 0x%08lX\n", frame->r2);
    printf("R3  = 0x%08lX\n", frame->r3);
    printf("R12 = 0x%08lX\n", frame->r12);
    printf("LR  = 0x%08lX  (返回地址)\n", frame->lr);
    printf("PC  = 0x%08lX  (故障指令地址)\n", frame->pc);
    printf("PSR = 0x%08lX\n", frame->psr);

    uint32_t cfsr = SCB_CFSR;
    uint32_t hfsr = SCB_HFSR;

    printf("\nCFSR = 0x%08lX\n", cfsr);
    printf("HFSR = 0x%08lX\n", hfsr);

    // 分析 MemManage Fault
    if (cfsr & 0xFF) {
        printf("\n-- MemManage Fault --\n");
        if (cfsr & (1 << 0))  printf("  IACCVIOL: 指令访问违规\n");
        if (cfsr & (1 << 1))  printf("  DACCVIOL: 数据访问违规\n");
        if (cfsr & (1 << 3))  printf("  MUNSTKERR: 出栈错误\n");
        if (cfsr & (1 << 4))  printf("  MSTKERR: 入栈错误\n");
        if (cfsr & (1 << 7))  printf("  MMFAR = 0x%08lX\n", SCB_MMFAR);
    }

    // 分析 Bus Fault
    if (cfsr & 0xFF00) {
        printf("\n-- Bus Fault --\n");
        if (cfsr & (1 << 8))  printf("  IBUSERR: 指令总线错误\n");
        if (cfsr & (1 << 9))  printf("  PRECISERR: 精确数据总线错误\n");
        if (cfsr & (1 << 10)) printf("  IMPRECISERR: 不精确数据总线错误\n");
        if (cfsr & (1 << 11)) printf("  UNSTKERR: 出栈错误\n");
        if (cfsr & (1 << 12)) printf("  STKERR: 入栈错误\n");
        if (cfsr & (1 << 15)) printf("  BFAR = 0x%08lX\n", SCB_BFAR);
    }

    // 分析 Usage Fault
    if (cfsr & 0xFFFF0000) {
        printf("\n-- Usage Fault --\n");
        if (cfsr & (1 << 16)) printf("  UNDEFINSTR: 未定义指令\n");
        if (cfsr & (1 << 17)) printf("  INVSTATE: 无效状态\n");
        if (cfsr & (1 << 18)) printf("  INVPC: 无效PC\n");
        if (cfsr & (1 << 19)) printf("  NOCP: 无协处理器\n");
        if (cfsr & (1 << 24)) printf("  UNALIGNED: 未对齐访问\n");
        if (cfsr & (1 << 25)) printf("  DIVBYZERO: 除零\n");
    }

    // 进入死循环，等待调试器连接
    while (1) {
        __asm volatile("bkpt #0");
    }
}

// naked 函数：不生成编译器序言/尾声代码
__attribute__((naked))
void HardFault_Handler(void) {
    __asm volatile (
        "TST   LR, #4       \n"  // 测试 EXC_RETURN 的 bit 2
        "ITE   EQ           \n"
        "MRSEQ R0, MSP      \n"  // 如果 bit2=0，使用 MSP
        "MRSNE R0, PSP      \n"  // 如果 bit2=1，使用 PSP
        "B     hard_fault_analysis \n"  // 跳转到分析函数
    );
}
```

## 9. 内存调试

### 9.1 栈溢出检测 - WaterMark 方法

WaterMark（水印法）在任务创建时用特定模式填充栈空间，运行后检查模式被覆盖了多少。

```c
// stack_watermark.h
#ifndef STACK_WATERMARK_H
#define STACK_WATERMARK_H

#include <stdint.h>
#include <string.h>

#define STACK_FILL_PATTERN 0xA5A5A5A5

// 初始化栈水印
void stack_watermark_init(uint32_t *stack_bottom, size_t stack_size) {
    size_t words = stack_size / sizeof(uint32_t);
    for (size_t i = 0; i < words; i++) {
        stack_bottom[i] = STACK_FILL_PATTERN;
    }
}

// 计算栈使用率（返回百分比 0-100）
uint32_t stack_watermark_get_usage(uint32_t *stack_bottom, size_t stack_size) {
    size_t words = stack_size / sizeof(uint32_t);
    size_t used = 0;

    for (size_t i = 0; i < words; i++) {
        if (stack_bottom[i] != STACK_FILL_PATTERN) {
            used = i + 1;
        }
    }

    return (used * 100) / words;
}

// 计算剩余栈空间（字节）
uint32_t stack_watermark_get_free(uint32_t *stack_bottom, size_t stack_size) {
    size_t words = stack_size / sizeof(uint32_t);
    size_t free_words = 0;

    for (size_t i = 0; i < words; i++) {
        if (stack_bottom[i] == STACK_FILL_PATTERN) {
            free_words++;
        } else {
            free_words = 0;  // 重置，找最靠近栈顶的未使用区域
        }
    }

    return free_words * sizeof(uint32_t);
}

#endif // STACK_WATERMARK_H
```

**FreeRTOS 内置栈检测：**
```c
// FreeRTOSConfig.h
#define configCHECK_FOR_STACK_OVERFLOW  2  // 方法2：同时检查水印和栈指针

// 回调函数
void vApplicationStackOverflowHook(TaskHandle_t xTask, char *pcTaskName) {
    // 栈溢出！打印任务名称
```

### 9.2 堆内存泄漏检测

```c
// mem_leak_detector.h
#ifndef MEM_LEAK_DETECTOR_H
#define MEM_LEAK_DETECTOR_H

#include <stdint.h>
#include <stddef.h>
#include <stdio.h>

#define MAX_TRACKED_ALLOCS  128

typedef struct {
    void       *ptr;         // 分配的地址
    size_t      size;        // 分配大小
    const char *file;        // 分配位置（文件名）
    int         line;        // 分配位置（行号）
    uint8_t     active;      // 是否活跃
} alloc_record_t;

static alloc_record_t alloc_table[MAX_TRACKED_ALLOCS];

// 跟踪 malloc
void *tracked_malloc(size_t size, const char *file, int line) {
    void *ptr = malloc(size);
    if (ptr) {
        for (int i = 0; i < MAX_TRACKED_ALLOCS; i++) {
            if (!alloc_table[i].active) {
                alloc_table[i].ptr = ptr;
                alloc_table[i].size = size;
                alloc_table[i].file = file;
                alloc_table[i].line = line;
                alloc_table[i].active = 1;
                break;
            }
        }
    }
    return ptr;
}

// 跟踪 free
void tracked_free(void *ptr, const char *file, int line) {
    for (int i = 0; i < MAX_TRACKED_ALLOCS; i++) {
        if (alloc_table[i].active && alloc_table[i].ptr == ptr) {
            alloc_table[i].active = 0;
            break;
        }
    }
    free(ptr);
}

// 打印泄漏报告
void mem_leak_report(void) {
    printf("\n=== Memory Leak Report ===\n");
    int leak_count = 0;
    size_t total_leaked = 0;

    for (int i = 0; i < MAX_TRACKED_ALLOCS; i++) {
        if (alloc_table[i].active) {
            printf("LEAK: %p (%u bytes) at %s:%d\n",
                   alloc_table[i].ptr,
                   (unsigned)alloc_table[i].size,
                   alloc_table[i].file,
                   alloc_table[i].line);
            leak_count++;
            total_leaked += alloc_table[i].size;
        }
    }

    printf("Total: %d leaks, %u bytes\n", leak_count, (unsigned)total_leaked);
}

// 宏替换
#ifdef LEAK_DETECT_ENABLED
    #define malloc(s)    tracked_malloc(s, __FILE__, __LINE__)
    #define free(p)      tracked_free(p, __FILE__, __LINE__)
#endif

#endif // MEM_LEAK_DETECTOR_H
```

### 10.3 DWT 周期计数器详解

DWT（Data Watchpoint and Trace）是 Cortex-M 内核内置的调试组件。

```c
// DWT 功能一览
typedef struct {
    // 周期计数器
    volatile uint32_t CYCCNT;     // 周期计数器（32位，溢出约4.3秒@168MHz）

    // CPI 计数器
    volatile uint32_t CPICNT;     // 每条指令的额外周期

    // 异常开销
    volatile uint32_t EXCCNT;     // 异常处理开销周期

    // 睡眠开销
    volatile uint32_t SLEEPCNT;   // 睡眠周期数

    // LSU 开销
    volatile uint32_t LSUCNT;     // Load/Store 单元等待周期

    // 跳转开销
    volatile uint32_t FOLDCNT;    // 折叠指令数（0 周期跳转）
} DWT_Type;

// 实用宏
#define DWT_START_MEASURE()  do { DWT->CYCCNT = 0; } while(0)
#define DWT_STOP_MEASURE(var) do { var = DWT->CYCCNT; } while(0)

// 计算函数（处理溢出）
uint32_t dwt_measure_diff(uint32_t start, uint32_t end) {
    if (end >= start) {
        return end - start;
    } else {
        return (0xFFFFFFFF - start) + end + 1;  // 处理溢出
    }
}
```

## 12. 常见 Bug 排查

### 12.1 死机/复位问题

**排查流程：**
```
1. 区分死机 vs 复位
   - 死机：程序停止响应，PC 指针不动
   - 复位：程序从头开始执行

2. 检查复位源
   - 读 RCC_CSR 寄存器（STM32）
   - 位 [26] IWDGRSTF: 独立看门狗复位
   - 位 [27] WWDGRSTF: 窗口看门狗复位
   - 位 [28] SFTRSTF: 软件复位
   - 位 [29] PORRSTF: 上电复位
   - 位 [30] PINRSTF: NRST 引脚复位
   - 位 [31] LPWRRSTF: 低功耗复位

// 检查复位源
void check_reset_source(void) {
    uint32_t rcc_csr = RCC->CSR;

    if (rcc_csr & RCC_CSR_IWDGRSTF)  printf("IWDG Reset\n");
    if (rcc_csr & RCC_CSR_WWDGRSTF)  printf("WWDG Reset\n");
    if (rcc_csr & RCC_CSR_SFTRSTF)   printf("Software Reset\n");
    if (rcc_csr & RCC_CSR_PORRSTF)   printf("POR Reset\n");
    if (rcc_csr & RCC_CSR_PINRSTF)   printf("NRST Pin Reset\n");
    if (rcc_csr & RCC_CSR_LPWRRSTF)  printf("Low Power Reset\n");

    RCC->CSR |= RCC_CSR_RMVF;  // 清除复位标志
}
```

**常见死机原因：**
```
- 未处理的中断：中断使能但没有对应的 ISR
- 死循环：while(1) 中条件永远为真
- 硬件故障：Hard Fault 未正确处理
- 看门狗未喂狗：优先级问题导致看门狗任务无法执行
```

### 12.2 内存踩踏（Memory Corruption）

**内存踩踏类型：**
```
1. 栈溢出覆盖全局变量
   - 症状：全局变量莫名被修改
   - 排查：在变量前后放置哨兵值（Guard Pattern）

2. 野指针写入
   - 症状：随机地址被写入数据
   - 排查：数据断点（Watchpoint）监控目标地址

3. 缓冲区溢出
   - 症状：数组越界写入
   - 排查：数组末尾放置哨兵值

4. 双重释放
   - 症状：堆管理器数据结构被破坏
   - 排查：使用带保护的内存分配器
```

**哨兵值检测：**
```c
// 在关键变量前后放置哨兵
#define SENTINEL_VALUE 0xDEADBEEF

static uint32_t sentinel_before = SENTINEL_VALUE;
static uint32_t my_critical_variable = 0;
static uint32_t sentinel_after = SENTINEL_VALUE;

void check_sentinels(void) {
    if (sentinel_before != SENTINEL_VALUE) {
        printf("WARNING: Memory corruption detected BEFORE variable!\n");
        printf("Expected: 0x%08lX, Got: 0x%08lX\n",
               SENTINEL_VALUE, sentinel_before);
    }
    if (sentinel_after != SENTINEL_VALUE) {
        printf("WARNING: Memory corruption detected AFTER variable!\n");
        printf("Expected: 0x%08lX, Got: 0x%08lX\n",
               SENTINEL_VALUE, sentinel_after);
    }
}
```

### 12.3 中断嵌套问题

**Cortex-M 中断优先级机制：**
```
- 数值越小，优先级越高
- 优先级分组：抢占优先级 + 子优先级
- 同一抢占优先级的中断不能互相抢占
- 子优先级只在同时到达时决定处理顺序

// 配置优先级分组
NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_4);  // 4位抢占，0位子优先级

// 设置中断优先级
HAL_NVIC_SetPriority(USART1_IRQn, 5, 0);  // 抢占优先级 5
HAL_NVIC_SetPriority(TIM2_IRQn, 3, 0);    // 抢占优先级 3（更高）
```

**常见中断问题：**
```
1. 优先级反转
   - 高优先级任务等待低优先级任务持有的资源
   - 中等优先级任务抢占低优先级任务，间接延迟高优先级任务
   - 解决：优先级继承、优先级天花板协议

2. 中断风暴
   - 中断触发过于频繁，CPU 无法处理其他任务
   - 排查：统计中断频率，检查中断处理时间
   - 解决：降低中断频率、缩短 ISR、使用 DMA

3. 未清除中断标志
   - 中断标志未清除导致反复进入 ISR
   - 排查：检查 ISR 中是否清除了所有需要清除的标志

4. 中断中的阻塞操作
   - ISR 中调用了 HAL_Delay 或等待超时函数
   - 排查：ISR 中只做最少的工作，复杂处理放到主循环
```

### 12.4 时序问题

**常见时序问题：**

**1. 外设初始化顺序**
```c
// 错误：外设未使能时钟就配置寄存器
GPIO_Init();           // 错误！GPIO 时钟未使能
__HAL_RCC_GPIOA_CLK_ENABLE();  // 应该先使能时钟

// 正确顺序：
__HAL_RCC_GPIOA_CLK_ENABLE();  // 1. 使能时钟
GPIO_Init();                    // 2. 配置 GPIO

// SPI 初始化顺序
__HAL_RCC_SPI1_CLK_ENABLE();   // 1. 使能 SPI 时钟
__HAL_RCC_GPIOA_CLK_ENABLE();  // 2. 使能 GPIO 时钟
GPIO_Init_SPI_Pins();           // 3. 配置 SPI 引脚
HAL_SPI_Init(&hspi);           // 4. 配置 SPI 外设
```

**2. I2C 总线时序**
```
常见问题：
- 从机需要时间处理上一个命令，但主机发送过快
  解决：在每次传输之间添加延时或检查 ACK

- NACK 后总线状态异常
  解决：发送 STOP 条件恢复总线

- 时钟拉伸未处理
  解决：检查从机是否支持时钟拉伸，调整主机超时
```

**3. SPI 时序**
```
常见问题：
- CS 信号时序不对
  - CS 拉低后需要等待一小段时间再发送时钟
  - CS 拉高前需要等待最后一个时钟完成

- CPOL/CPHA 配置错误
  - 仔细对照从机数据手册的时序图
  - 使用逻辑分析仪验证实际波形

- 速度过快
  - 降低 SPI 时钟频率验证是否是时序问题
  - 检查 PCB 走线长度和信号完整性
```

### 12.5 EMI 干扰

**EMI 对嵌入式系统的影响：**
```
1. 复位引脚受干扰
   - 表现：随机复位
   - 解决：NRST 引脚加滤波电容（100nF）

2. ADC 采样受干扰
   - 表现：ADC 值跳变、精度下降
   - 解决：多次采样取平均、加硬件滤波

3. 通信错误
   - 表现：UART/SPI/I2C 数据错误
   - 解决：缩短走线、加屏蔽、使用差分信号

4. 晶振受干扰
   - 表现：时钟不稳定、程序跑飞
   - 解决：晶振靠近芯片、加地保护环
```

**EMI 排查方法：**
```
1. 时域分析
   - 用示波器观察电源纹波
   - 检查信号波形是否有毛刺
   - 测量上升/下降时间

2. 频域分析
   - 使用频谱分析仪
   - 识别干扰频率
   - 定位干扰源

3. 排除法
   - 逐个禁用外设
   - 逐个断开负载
   - 缩小干扰源范围

4. PCB 设计检查
   - 电源去耦电容是否靠近芯片
   - 高速信号是否有匹配电阻
   - 地平面是否完整
   - 模拟地和数字地是否正确分离/连接
```

## 附录 C：常见故障排除清单

```
□ 程序无法烧录
  □ 检查调试器连接（SWD/JTAG 引脚）
  □ 检查目标板供电
  □ 检查 BOOT 引脚配置
  □ 尝试降低调试速度
  □ 检查 Flash 是否被写保护

□ 程序运行后立即死机
  □ 检查时钟配置（HSE/HSI/LSE/LSI）
  □ 检查中断向量表偏移
  □ 检查堆栈大小
  □ 检查外设初始化顺序

□ 程序运行一段时间后死机
  □ 检查看门狗是否超时
  □ 检查栈溢出（WaterMark 法）
  □ 检查内存泄漏
  □ 检查中断优先级冲突

□ 通信不稳定
  □ 降低通信速率验证
  □ 检查电平匹配（3.3V/5V）
  □ 检查地线连接
  □ 添加去耦电容
  □ 使用逻辑分析仪检查波形

□ ADC 精度不足
  □ 检查参考电压稳定性
  □ 检查采样时间配置
  □ 检查 PCB 布局（模拟信号走线）
  □ 多次采样取平均
  □ 检查电源纹波
```
