## 一、边缘计算概述

### 1.1 什么是边缘计算

边缘计算（Edge Computing）是一种分布式计算范式，将数据处理和分析从集中式云数据中心移至靠近数据源的网络边缘，以减少延迟、节省带宽并提升实时性。

```
用户设备 → 边缘节点（就近处理） → 云中心（全局分析）
```

**核心思想**：在数据产生的地方进行计算，而非将所有数据传输到远端云。

### 1.2 云计算 vs 边缘计算

| 维度 | 云计算 | 边缘计算 |
|------|--------|----------|
| **计算位置** | 集中式数据中心 | 网络边缘/本地设备 |
| **延迟** | 较高（10-100ms+） | 极低（1-10ms） |
| **带宽需求** | 高（全量数据上传） | 低（本地过滤后上传） |
| **离线能力** | 无 | 有（可离线运行） |
| **计算能力** | 近乎无限 | 受限于硬件 |
| **运维复杂度** | 低（集中管理） | 高（分布式管理） |
| **数据隐私** | 数据离开本地 | 数据可留在本地 |
| **成本模型** | 按用量付费（OpEx） | 硬件投入（CapEx） |
| **适用场景** | 大数据分析、模型训练 | 实时控制、低延迟应用 |

### 1.3 边缘计算的优势

1. **低延迟**：数据在本地处理，响应时间从百毫秒级降至毫秒级
2. **节省带宽**：边缘过滤后仅上传关键数据，减少 60-90% 的上行带宽
3. **数据隐私**：敏感数据不出本地，满足 GDPR 等合规要求
4. **离线可用**：网络中断时边缘节点可独立运行
5. **实时决策**：工业控制、自动驾驶等场景需要毫秒级响应
6. **降低成本**：减少云端计算和传输费用

### 1.4 边缘计算的挑战

1. **资源受限**：边缘设备 CPU/内存/存储有限，无法运行复杂模型
2. **运维难度**：大量分布式设备的管理、监控、升级
3. **安全风险**：物理暴露的边缘节点面临更多攻击面
4. **异构硬件**：不同厂商的硬件平台差异大，软件适配成本高
5. **网络不稳定**：边缘网络带宽和可靠性不如数据中心
6. **标准化不足**：各平台接口和协议尚未统一

### 1.5 边缘计算的应用领域

- **工业物联网（IIoT）**：设备监控、预测性维护、质量检测
- **智能交通**：车路协同、交通信号优化、自动驾驶辅助
- **智慧医疗**：远程监测、医学影像边缘分析
- **智能家居**：语音识别、安防监控、能源管理
- **智慧城市**：环境监测、公共安全、市政设施管理
- **零售**：智能货架、客流分析、无人收银

```
│  ┌─────┐ ┌──────┐ ┌───────┐ ┌──────────┐   │
│  │传感器│ │执行器│ │摄像头 │ │ 智能终端 │   │
│  └─────┘ └──────┘ └───────┘ └──────────┘   │

```

**各层职责**：

| 层级 | 职责 | 典型硬件 | 通信协议 |
|------|------|----------|----------|
| **终端层** | 数据采集、简单预处理 | MCU、传感器、执行器 | I2C/SPI/UART/ADC |
| **边缘层** | 数据过滤、AI推理、本地决策 | 边缘网关、工控机、树莓派 | MQTT/CoAP/HTTP |
| **云端层** | 大数据分析、模型训练、全局调度 | 云服务器集群 | HTTPS/gRPC |

### 2.2 边缘节点类型

#### 轻量级边缘节点
- **硬件**：MCU（ESP32/STM32）、网关设备
- **能力**：数据采集、协议转换、简单规则引擎
- **OS**：FreeRTOS、Zephyr、裸机
- **典型场景**：传感器网关、Modbus转MQTT

#### 标准边缘节点
- **硬件**：ARM Cortex-A（树莓派、RK3568）、工控机
- **能力**：容器运行、AI推理、数据聚合
- **OS**：嵌入式Linux、Ubuntu Core
- **典型场景**：视频分析、预测性维护

#### 沉浸式边缘节点
- **硬件**：GPU/NPU服务器（NVIDIA Jetson、华为Atlas）
- **能力**：大模型推理、复杂数据分析
- **OS**：Linux + Docker/K3s
- **典型场景**：自动驾驶、大规模视觉检测

### 2.3 边缘网关

边缘网关是连接终端设备和云平台的关键枢纽。

**核心功能**：
1. **协议转换**：Modbus/RS485 → MQTT/HTTP
2. **数据预处理**：过滤、聚合、格式化
3. **本地存储**：断网时缓存数据
4. **安全接入**：设备认证、数据加密
5. **远程管理**：OTA升级、配置下发

**常见边缘网关产品**：

| NVIDIA Jetson Nano | Maxwell GPU 128核 | WiFi/Ethernet | GPU加速推理 |
| 研华 WISE-EdgeLink | ARM Cortex-A | 多串口/多网口 | 工业级可靠 |
| Sierra Wireless FX30 | ARM Cortex-A | 4G LTE/串口 | 蜂窝联网 |
| 华为 AR502H | ARM Cortex-A | 4G/5G/LoRa | 鸿蒙系统 |

## 三、边缘AI推理

### 3.1 边缘AI概述

边缘AI（Edge AI）指在边缘设备上运行AI模型进行推理，无需将数据发送到云端。

**核心挑战**：
- 内存受限（通常 < 256KB RAM for MCU）
- 计算能力有限（无GPU）
- 功耗预算严格（电池供电设备）
- 模型大小限制（Flash通常 1-4MB）

### 3.2 TensorFlow Lite Micro（TFLM）

TensorFlow Lite Micro 是专为微控制器设计的推理框架。

**架构**：

```
TensorFlow 模型 → TensorFlow Lite 转换 → 量化 → TFLM 部署
```

**关键特性**：
- 支持 Cortex-M、ESP32、RISC-V 等 MCU
- 内存占用：约 20-100KB RAM
- 支持 INT8 量化推理
- 无需操作系统支持（裸机可运行）

**基本使用流程**：

```cpp
// 1. 包含头文件
#include "tensorflow/lite/micro/micro_interpreter.h"
#include "tensorflow/lite/micro/micro_mutable_op_resolver.h"
#include "tensorflow/lite/schema/schema_generated.h"

// 2. 定义张量 arena
constexpr int kTensorArenaSize = 32 * 1024;  // 32KB
alignas(16) static uint8_t tensor_arena[kTensorArenaSize];

// 3. 加载模型
const tflite::Model* model = tflite::GetModel(g_model_data);

// 4. 注册算子
tflite::MicroMutableOpResolver<5> resolver;
resolver.AddConv2D();
resolver.AddMaxPool2D();
resolver.AddReshape();
resolver.AddFullyConnected();
resolver.AddSoftmax();

// 5. 创建解释器
tflite::MicroInterpreter interpreter(
    model, resolver, tensor_arena, kTensorArenaSize);

// 6. 分配内存
interpreter.AllocateTensors();

// 7. 填充输入
float* input = interpreter.input(0)->data.f;
// ... 填充数据 ...

// 8. 执行推理
interpreter.Invoke();

// 9. 获取输出
float* output = interpreter.output(0)->data.f;
```

**支持的平台**：

| 平台 | MCU | Flash需求 | RAM需求 |
|------|-----|-----------|---------|
| STM32F4 | Cortex-M4 | 256KB+ | 64KB+ |
| STM32F7 | Cortex-M7 | 512KB+ | 128KB+ |
| ESP32 | Xtensa LX6 | 4MB Flash | 520KB SRAM |
| nRF5340 | Cortex-M33 | 1MB | 512KB |
| Arduino Nano 33 | Cortex-M4 | 1MB | 256KB |

### 3.3 ONNX Runtime

ONNX Runtime 是微软开源的高性能推理引擎，支持多种硬件后端。

**边缘部署特点**：
- 支持 ARM、x86、GPU（CUDA/TensorRT）
- 支持 Mobile/Web/Desktop/Embedded
- 提供 ONNX Runtime Mobile（针对移动端优化）
- 支持 NNAPI（Android）、CoreML（iOS）硬件加速

**Python 部署示例**：

```python
import onnxruntime as ort

# 创建推理会话（指定执行提供者）
session = ort.InferenceSession(
    "model.onnx",
    providers=['CPUExecutionProvider']  # 边缘设备用CPU
)

# 准备输入
input_data = {"input": np.array([...]).astype(np.float32)}

# 执行推理
outputs = session.run(None, input_data)
```

**C++ 部署示例**：

```cpp
#include <onnxruntime_cxx_api.h>

// 创建环境
Ort::Env env(ORT_LOGGING_LEVEL_WARNING, "edge-ai");

// 创建会话选项
Ort::SessionOptions session_options;
session_options.SetIntraOpNumThreads(1);  // 边缘设备单线程

// 加载模型
Ort::Session session(env, L"model.onnx", session_options);

// 准备输入输出
auto memory_info = Ort::MemoryInfo::CreateCpu(
    OrtArenaAllocator, OrtMemTypeDefault);

std::vector<float> input_tensor_values = {...};
std::vector<int64_t> input_shape = {1, 3, 224, 224};

Ort::Value input_tensor = Ort::Value::CreateTensor<float>(
    memory_info, input_tensor_values.data(),
    input_tensor_values.size(), input_shape.data(), input_shape.size());

// 推理
auto output_tensors = session.Run(
    Ort::RunOptions{nullptr},
    input_names.data(), &input_tensor, 1,
    output_names.data(), 1);
```

### 3.4 模型量化（INT8）

模型量化将浮点权重和激活值转换为低精度整数表示，是边缘部署的关键技术。

**量化类型**：

| 方法 | 精度 | 速度提升 | 精度损失 |
|------|------|----------|----------|
| FP32 | 32位浮点 | 基准 | 无 |
| FP16 | 16位浮点 | 2x | 极小 |
| INT8 | 8位整数 | 3-4x | 较小 |
| INT4 | 4位整数 | 6-8x | 中等 |

**训练后量化（PTQ）**：

```python
import tensorflow as tf

# 加载 SavedModel
converter = tf.lite.TFLiteConverter.from_saved_model("saved_model")

# INT8 全整数量化
converter.optimizations = [tf.lite.Optimize.DEFAULT]

# 提供校准数据集（用于确定量化范围）
def representative_dataset():
    for data in calibration_data:
        yield [data.astype(np.float32)]

converter.representative_dataset = representative_dataset
converter.target_spec.supported_ops = [tf.lite.OpsSet.TFLITE_BUILTINS_INT8]
converter.inference_input_type = tf.int8
converter.inference_output_type = tf.int8

# 转换
tflite_quant_model = converter.convert()
with open("model_int8.tflite", "wb") as f:
    f.write(tflite_quant_model)
```

**量化感知训练（QAT）**：

```python
import tensorflow_model_optimization as tfmot

# 定义量化感知模型
quantize_model = tfmot.quantization.keras.quantize_model

# 构建模型
base_model = create_model()
qat_model = quantize_model(base_model)

# 编译与训练
qat_model.compile(optimizer='adam', loss='sparse_categorical_crossentropy')
qat_model.fit(train_data, train_labels, epochs=10)

# 转换为TFLite
converter = tf.lite.TFLiteConverter.from_keras_model(qat_model)
converter.optimizations = [tf.lite.Optimize.DEFAULT]
tflite_model = converter.convert()
```

**量化效果对比**：

| 模型 | FP32 大小 | INT8 大小 | 压缩比 | 精度变化 |
|------|-----------|-----------|--------|----------|
| MobileNetV2 | 6.9MB | 1.7MB | 4x | -0.5% |
| EfficientNet-Lite | 12.3MB | 3.1MB | 4x | -0.8% |
| YOLOv5-nano | 3.9MB | 1.0MB | 4x | -1.2% |

### 3.5 模型剪枝

模型剪枝通过移除冗余的权重或神经元来减小模型大小和计算量。

**结构化剪枝**（移除整个通道/层）：

```python
import tensorflow_model_optimization as tfmot

# 定义剪枝参数
pruning_params = {
    'pruning_schedule': tfmot.sparsity.keras.ConstantSparsity(
        target_sparsity=0.5,      # 目标稀疏度 50%
        begin_step=0,
        frequency=100
    )
}

# 应用剪枝
pruned_model = tfmot.sparsity.keras.prune_low_magnitude(
    model, **pruning_params)

# 微调训练
pruned_model.compile(optimizer='adam', loss='categorical_crossentropy')
pruned_model.fit(train_data, train_labels, epochs=10,
    callbacks=[tfmot.sparsity.keras.UpdatePruningStep()])

# 剪枝后去除包装
final_model = tfmot.sparsity.keras.strip_pruning(pruned_model)
```

**非结构化剪枝**（移除单个权重，需要硬件支持稀疏计算）：

```python
import torch.nn.utils.prune as prune

# 对卷积层进行 L1 非结构化剪枝
prune.l1_unstructured(model.conv1, name='weight', amount=0.3)

# 对全连接层进行随机剪枝
prune.random_unstructured(model.fc1, name='weight', amount=0.4)
```

**剪枝 + 量化联合优化流程**：

```
原始模型 → 剪枝（移除冗余参数）→ 微调恢复精度 → 量化（INT8）→ 部署
```

### 3.6 其他边缘AI技术

**知识蒸馏**：用大模型（Teacher）指导小模型（Student）学习

```python
# 蒸馏损失 = α * 硬标签损失 + (1-α) * 软标签损失
def distillation_loss(y_true, y_pred, teacher_logits, temperature=3, alpha=0.5):
    soft_loss = KLDivergence(
        softmax(teacher_logits / temperature),
        softmax(y_pred / temperature)
    ) * (temperature ** 2)
    hard_loss = CategoricalCrossentropy(y_true, y_pred)
    return alpha * hard_loss + (1 - alpha) * soft_loss
```

**模型格式转换链**：

```
PyTorch → ONNX → TensorRT (NVIDIA) / OpenVINO (Intel) / TFLite (MCU)
TensorFlow → SavedModel → TFLite / ONNX
```

## 四、边缘操作系统

### 4.1 Zephyr RTOS

Zephyr 是 Linux 基金会支持的开源实时操作系统，专为资源受限的嵌入式设备设计。

**特点**：
- 支持 300+ 开发板（ARM Cortex-M、RISC-V、x86、Xtensa）
- 极小内存占用：最小 2KB RAM / 8KB Flash
- 内置网络栈（TCP/IP、BLE、Wi-Fi、LoRa）
- CMake + West 构建系统
- 安全认证（PSA Certified）

**基本任务示例**：

```c
#include <zephyr/kernel.h>

#define STACK_SIZE 1024
#define PRIORITY   5

K_THREAD_STACK_DEFINE(sensor_stack, STACK_SIZE);
struct k_thread sensor_thread_data;

void sensor_task(void *p1, void *p2, void *p3) {
    while (1) {
        int value = read_sensor();
        process_data(value);
        k_msleep(1000);  // 1秒周期
    }
}

int main(void) {
    k_tid_t tid = k_thread_create(
        &sensor_thread_data, sensor_stack,
        STACK_SIZE, sensor_task,
        NULL, NULL, NULL,
        PRIORITY, 0, K_NO_WAIT);

    k_thread_name_set(tid, "sensor");
    return 0;
}
```

**Zephyr vs FreeRTOS 对比**：

| 特性 | Zephyr | FreeRTOS |
|------|--------|----------|
| 内核类型 | 宏内核 | 微内核 |
| 最小RAM | 2KB | < 1KB |
| 网络栈 | 内置完整TCP/IP | 需第三方（lwIP） |
| BLE | 内置 | 需第三方 |
| 构建系统 | CMake + West | Makefile/CMake |
| 社区生态 | 快速增长 | 成熟庞大 |
| 安全认证 | PSA Certified | 无官方认证 |
| 学习曲线 | 较陡 | 较平缓 |

### 4.2 RIOT OS

RIOT 是面向物联网的操作系统，强调标准兼容和低功耗。

**特点**：
- 支持 ARM Cortex-M、AVR、MSP430、RISC-V
- 最小 1.5KB RAM / 5KB Flash
- POSIX 兼容 API
- 内置 6LoWPAN、CoAP、MQTT-SN
- C/C++ 混合编程

**RIOT 任务示例**：

```c
#include "thread.h"
#include "xtimer.h"

char sensor_stack[THREAD_STACKSIZE_DEFAULT];

void *sensor_thread(void *arg) {
    (void)arg;
    while (1) {
        int val = read_sensor();
        msg_t m;
        m.content.value = val;
        msg_send(&m, main_pid);
        xtimer_sleep(1);
    }
    return NULL;
}

int main(void) {
    thread_create(sensor_stack, sizeof(sensor_stack),
                  THREAD_PRIORITY_MAIN - 1,
                  THREAD_CREATE_STACKTEST,
                  sensor_thread, NULL, "sensor");
    return 0;
}
```

### 4.3 FreeRTOS + POSIX

FreeRTOS 通过 POSIX 兼容层提供更标准的编程接口。

**FreeRTOS POSIX 兼容层**：

```c
#include <pthread.h>
#include <semaphore.h>
#include <time.h>

sem_t data_ready;
pthread_mutex_t data_mutex;

void *sensor_task(void *arg) {
    while (1) {
        pthread_mutex_lock(&data_mutex);
        sensor_data = read_sensor();
        pthread_mutex_unlock(&data_mutex);

        sem_post(&data_ready);  // 通知数据就绪

        struct timespec ts = { .tv_sec = 1 };
        nanosleep(&ts, NULL);   // POSIX 风格延时
    }
    return NULL;
}

void *process_task(void *arg) {
    while (1) {
        sem_wait(&data_ready);  // 等待数据
        pthread_mutex_lock(&data_mutex);
        process(sensor_data);
        pthread_mutex_unlock(&data_mutex);
    }
    return NULL;
}

int main(void) {
    pthread_t t1, t2;
```

## 五、物联网协议栈

### 5.1 MQTT（消息队列遥测传输）

**特点**：轻量级发布/订阅模式，专为低带宽、不稳定网络设计

**MQTT 协议基础**：

```
客户端 (发布者) --Publish--> Broker --转发--> 客户端 (订阅者)
     ^                          |
     |                          |
     +--------Subscribe---------+
```

**QoS 等级**：

| QoS | 名称 | 描述 | 数据包次数 |
|-----|------|------|-----------|
| 0 | 最多一次 | 发送即忘，可能丢失 | 1 |
| 1 | 至少一次 | 确保到达，可能重复 | 2-3 |
| 2 | 恰好一次 | 不丢不重，最慢 | 4 |

**MQTT 5.0 新特性**：
- 共享订阅（负载均衡）
- 消息过期（TTL）
- 原因码（详细错误信息）
- 用户属性（自定义元数据）

**MQTT 客户端示例（C语言，基于 Mosquitto）**：

```c
#include <mosquitto.h>

void on_connect(struct mosquitto *mosq, void *userdata, int rc) {
    if (rc == 0) {
        mosquitto_subscribe(mosq, NULL, "sensors/+/temperature", 1);
    }
}

void on_message(struct mosquitto *mosq, void *userdata,
                const struct mosquitto_message *msg) {
    printf("Topic: %s, Payload: %s\n", msg->topic, (char *)msg->payload);
}

int main(void) {
    mosquitto_lib_init();
    struct mosquitto *mosq = mosquitto_new("edge-gateway", true, NULL);

    mosquitto_connect_callback_set(mosq, on_connect);
    mosquitto_message_callback_set(mosq, on_message);

    // TLS 配置
    mosquitto_tls_set(mosq, "ca.crt", NULL, NULL, NULL, NULL);

    // 用户名密码认证
    mosquitto_username_pw_set(mosq, "device01", "password123");

    mosquitto_connect(mosq, "broker.example.com", 8883, 60);
    mosquitto_loop_forever(mosq, -1, 1);

    mosquitto_destroy(mosq);
    mosquitto_lib_cleanup();
    return 0;
}
```

### 5.2 CoAP（受限应用协议）

**特点**：基于 UDP 的 RESTful 协议，专为受限设备设计

**CoAP vs HTTP**：

| 特性 | CoAP | HTTP |
|------|------|------|
| 传输层 | UDP | TCP |
| 头部大小 | 4字节 | ~200字节 |
| 方法 | GET/POST/PUT/DELETE | 相同 |
| 消息模型 | 请求/响应 + 观察 | 仅请求/响应 |
| 确认机制 | ACK（可选） | TCP保证 |
| 适用设备 | MCU（8/16/32位） | 需TCP栈 |

**CoAP 请求示例**：

```python
import aiocoap

async def get_temperature():
    protocol = await aiocoap.Context.create_client_context()
    request = aiocoap.Message(
        code=aiocoap.GET,
        uri='coap://sensor.local/temperature'
    )
    response = await protocol.request(request).response
    print(f"Temperature: {response.payload.decode()}")

async def observe_resource():
    """观察资源变化（类似MQTT订阅）"""
    protocol = await aiocoap.Context.create_client_context()
    request = aiocoap.Message(
        code=aiocoap.GET,
        uri='coap://sensor.local/temperature',
        observe=0  # 注册观察
    )
    requester = protocol.request(request)
    async for response in requester.observation:
        print(f"Updated: {response.payload.decode()}")
```

### 5.3 LwM2M（轻量级M2M）

**特点**：基于 CoAP 的设备管理协议，由 OMA 定义

**LwM2M 对象模型**：

```
对象 (Object)  →  资源 (Resource)  →  资源实例
   │
   ├─ /3 (设备) → /3/0/0 (制造商)
   │             → /3/0/1 (型号)
   │             → /3/0/2 (序列号)
   │
   ├─ /5 (固件更新) → /5/0/0 (包)
   │                 → /5/0/1 (包URI)
   │                 → /5/0/2 (更新)
   │
   └─ /3303 (温度传感器) → /3303/0/5700 (传感器值)
```

**LwM2M 操作**：
- **注册**：设备向服务器注册
- **读/写**：读取或设置资源值
- **执行**：触发资源上的操作（如重启）
- **观察**：订阅资源变化通知

### 5.4 HTTP/HTTPS

**在物联网中的适用场景**：
- 固件下载（大文件传输）
- 设备注册/认证
- RESTful API 调用
- Web 仪表板数据上报

**HTTP 在 IoT 中的局限**：
- TCP 连接开销大
- 头部冗长（对比 CoAP 4字节头部）
- 无原生发布/订阅
- 不适合频繁小消息

### 5.5 协议选型指南

```
                    是否需要设备管理？
                    /              \
                  是                否
                  │                 │
               LwM2M           消息模式？
                              /         \
                          发布/订阅      请求/响应
                            │              │
                     是否受限设备？    是否受限设备？
                     /          \      /          \
                   是            否   是            否
                   │             │    │             │
               MQTT-SN        MQTT  CoAP        HTTP
```

**协议对比速查**：

| 特性 | MQTT | CoAP | LwM2M | HTTP |
|------|------|------|-------|------|
| 传输层 | TCP | UDP | UDP(CoAP) | TCP |
| 模式 | 发布/订阅 | 请求/响应 | 请求/响应+观察 | 请求/响应 |
| 头部开销 | 2字节+ | 4字节 | 基于CoAP | ~200字节 |
| 设备管理 | 无（需扩展） | 无 | 原生支持 | 无 |
| 适合场景 | 通用IoT消息 | 受限设备通信 | 设备管理 | 大数据/API |
| 典型带宽 | 10-100Kbps | 10-50Kbps | 10-50Kbps | 100Kbps+ |

### 7.2 OTA（空中升级）

**OTA 升级流程**：

```
1. 发布新固件到OTA服务器
2. 创建升级任务（指定目标设备/分组）
3. 设备检查更新（轮询或推送通知）
4. 设备下载固件包（断点续传）
5. 验证固件签名（防篡改）
6. 写入备份分区（A/B分区方案）
7. 重启并运行新固件
8. 上报升级结果
9. 失败则自动回滚到旧版本
```

**A/B 分区升级方案**：

```
┌─────────────────────────────────┐
│          Flash 布局              │
├─────────┬─────────┬─────────────┤
│ Bootloader │ Slot A │  Slot B    │
│  (固定)    │ 当前运行│  待升级    │
├─────────┴─────────┴─────────────┤
│         Download 区域            │
│        (OTA固件下载暂存)          │
└─────────────────────────────────┘
```

**ESP-IDF OTA 示例**：

```c
#include "esp_ota_ops.h"
#include "esp_https_ota.h"

esp_err_t perform_ota(const char *url) {
    esp_http_client_config_t config = {
        .url = url,
        .cert_pem = server_cert_pem,
    };

    esp_https_ota_config_t ota_config = {
        .http_config = &config,
    };

    esp_https_ota_handle_t ota_handle;
    esp_err_t err = esp_https_ota_begin(&ota_config, &ota_handle);
    if (err != ESP_OK) return err;

    while (1) {
        err = esp_https_ota_perform(ota_handle);
        if (err == ESP_ERR_HTTPS_OTA_IN_PROGRESS) continue;
        if (err != ESP_OK) break;
    }

    if (esp_https_ota_is_complete(ota_handle)) {
        esp_https_ota_finish(ota_handle);
        esp_restart();  // 重启进入新固件
    } else {
        esp_https_ota_abort(ota_handle);
    }
    return err;
}
```

## 八、数据处理

### 8.1 边缘数据过滤

**常见过滤策略**：

1. **阈值过滤**：仅上报超出阈值的数据
2. **变化过滤**：数据变化超过一定幅度才上报
3. **时间过滤**：按固定间隔采样上报
4. **去重过滤**：去除重复数据
5. **异常值过滤**：去除明显异常的读数

**C语言阈值+变化过滤**：

```c
typedef struct {
    float last_value;
    float change_threshold;
    float alarm_threshold;
    uint32_t last_report_time;
    uint32_t min_interval_ms;
} filter_ctx_t;

bool should_report(filter_ctx_t *ctx, float new_value, uint32_t now) {
    // 异常值过滤（明显不合理的读数）
    if (new_value < -50.0 || new_value > 150.0) return false;

    // 阈值告警 - 立即上报
    if (new_value > ctx->alarm_threshold) return true;

    // 最小间隔检查
    if ((now - ctx->last_report_time) < ctx->min_interval_ms) return false;

    // 变化量检查
    float delta = fabsf(new_value - ctx->last_value);
    if (delta >= ctx->change_threshold) {
        ctx->last_value = new_value;
        ctx->last_report_time = now;
        return true;
    }

    return false;
}
```

### 8.2 数据聚合

**聚合策略**：

```c
typedef struct {
    float sum;
    float min;
    float max;
    float avg;
    uint32_t count;
    uint32_t window_start;
    uint32_t window_duration_ms;
} aggregator_t;

void aggregator_init(aggregator_t *agg, uint32_t duration_ms) {
    agg->sum = 0;
    agg->min = FLT_MAX;
    agg->max = -FLT_MAX;
    agg->count = 0;
    agg->window_duration_ms = duration_ms;
    agg->window_start = get_timestamp_ms();
}

void aggregator_add(aggregator_t *agg, float value) {
    agg->sum += value;
    agg->count++;
    if (value < agg->min) agg->min = value;
    if (value > agg->max) agg->max = value;
}

bool aggregator_should_flush(aggregator_t *agg, uint32_t now) {
    return (now - agg->window_start) >= agg->window_duration_ms;
}

void aggregator_flush(aggregator_t *agg, float *avg_out) {
    if (agg->count > 0) {
        *avg_out = agg->sum / agg->count;
    }
    // 重置
    aggregator_init(agg, agg->window_duration_ms);
}
```

### 8.3 边缘异常检测

**简单统计方法**：

```c
#include <math.h>

typedef struct {
    float mean;
    float variance;
    float threshold_sigma;  // 通常设为 2 或 3
    uint32_t sample_count;
    float running_sum;
    float running_sq_sum;
} anomaly_detector_t;

void detector_init(anomaly_detector_t *det, float sigma) {
    det->mean = 0;
    det->variance = 0;
    det->threshold_sigma = sigma;
    det->sample_count = 0;
    det->running_sum = 0;
    det->running_sq_sum = 0;
}

bool detector_check(anomaly_detector_t *det, float value) {
    det->sample_count++;
    det->running_sum += value;
    det->running_sq_sum += value * value;

    // 需要至少30个样本才开始检测
    if (det->sample_count < 30) return false;

    det->mean = det->running_sum / det->sample_count;
    det->variance = (det->running_sq_sum / det->sample_count)
                    - (det->mean * det->mean);
    float stddev = sqrtf(det->variance);

    // 超过 N 个标准差视为异常
    float z_score = fabsf(value - det->mean) / (stddev + 1e-6f);
    return z_score > det->threshold_sigma;
}
```

**移动窗口异常检测**：

```c
#define WINDOW_SIZE 50

typedef struct {
    float buffer[WINDOW_SIZE];
    uint32_t index;
    uint32_t count;
} sliding_window_t;

float window_mean(sliding_window_t *w) {
    float sum = 0;
    uint32_t n = (w->count < WINDOW_SIZE) ? w->count : WINDOW_SIZE;
    for (uint32_t i = 0; i < n; i++) sum += w->buffer[i];
    return sum / n;
}

float window_stddev(sliding_window_t *w) {
    float mean = window_mean(w);
    float sum_sq = 0;
    uint32_t n = (w->count < WINDOW_SIZE) ? w->count : WINDOW_SIZE;
    for (uint32_t i = 0; i < n; i++) {
        float diff = w->buffer[i] - mean;
        sum_sq += diff * diff;
    }
    return sqrtf(sum_sq / n);
}

bool detect_anomaly(sliding_window_t *w, float value, float sigma) {
    if (w->count < WINDOW_SIZE) {
        w->buffer[w->index] = value;
        w->index = (w->index + 1) % WINDOW_SIZE;
        w->count++;
        return false;
    }

    float mean = window_mean(w);
    float stddev = window_stddev(w);

    bool anomaly = fabsf(value - mean) > sigma * stddev;

    // 更新窗口（无论是否异常）
    w->buffer[w->index] = value;
    w->index = (w->index + 1) % WINDOW_SIZE;
    w->count++;

    return anomaly;
}
```

```c
// SAS Token 生成（Azure IoT Hub 示例）
#include <openssl/hmac.h>
#include <openssl/evp.h>

char* generate_sas_token(
    const char *resource_uri,
    const char *key,
    int expiry_seconds
) {
    // 1. 计算过期时间戳
    time_t expiry = time(NULL) + expiry_seconds;

    // 2. 构造签名字符串
    char string_to_sign[256];
    snprintf(string_to_sign, sizeof(string_to_sign),
             "%s\n%ld", resource_uri, expiry);

    // 3. Base64 解码密钥
    // 4. HMAC-SHA256 签名
    unsigned char hmac_result[EVP_MAX_MD_SIZE];
    unsigned int hmac_len;
    HMAC(EVP_sha256(), key, strlen(key),
         (unsigned char *)string_to_sign,
         strlen(string_to_sign),
         hmac_result, &hmac_len);

    // 5. Base64 编码签名
    // 6. URL编码并组装Token
    // 返回: SharedAccessSignature sr=...&sig=...&se=...
    return token;
}
```

### 9.2 数据加密

**TLS/DTLS 配置**：

```c
// mbedTLS TLS 客户端配置
#include "mbedtls/net_sockets.h"
#include "mbedtls/ssl.h"
#include "mbedtls/entropy.h"
#include "mbedtls/ctr_drbg.h"

int tls_connect(mbedtls_net_context *server_fd,
                mbedtls_ssl_context *ssl,
                const char *host, const char *port,
                const char *ca_cert,
                const char *client_cert,
                const char *client_key) {
    mbedtls_ssl_config conf;
    mbedtls_x509_crt cacert, clicert;
    mbedtls_pk_context client_pk;
    mbedtls_entropy_context entropy;
    mbedtls_ctr_drbg_context ctr_drbg;

    // 初始化
    mbedtls_ssl_init(ssl);
    mbedtls_ssl_config_init(&conf);
    mbedtls_x509_crt_init(&cacert);
    mbedtls_x509_crt_init(&clicert);
    mbedtls_pk_init(&client_pk);

    // 加载 CA 证书
    mbedtls_x509_crt_parse(&cacert, ca_cert, strlen(ca_cert) + 1);

    // 加载客户端证书和私钥
    mbedtls_x509_crt_parse(&clicert, client_cert, strlen(client_cert) + 1);
    mbedtls_pk_parse_key(&client_pk, client_key, strlen(client_key) + 1,
                         NULL, 0);

    // 配置 TLS
    mbedtls_ssl_config_defaults(&conf,
        MBEDTLS_SSL_IS_CLIENT,
        MBEDTLS_SSL_TRANSPORT_STREAM,  // TCP (用DATAGRAM for DTLS)
        MBEDTLS_SSL_PRESET_DEFAULT);

    mbedtls_ssl_conf_authmode(&conf, MBEDTLS_SSL_VERIFY_REQUIRED);
    mbedtls_ssl_conf_ca_chain(&conf, &cacert, NULL);
    mbedtls_ssl_conf_own_cert(&conf, &clicert, &client_pk);

    // 设置 RNG
    mbedtls_entropy_init(&entropy);
    mbedtls_ctr_drbg_init(&ctr_drbg);
    mbedtls_ctr_drbg_seed(&ctr_drbg, mbedtls_entropy_func, &entropy,
                          (const unsigned char *)"client", 6);
    mbedtls_ssl_conf_rng(&conf, mbedtls_ctr_drbg_random, &ctr_drbg);

    // 建立连接
    mbedtls_ssl_setup(ssl, &conf);
    mbedtls_ssl_set_hostname(ssl, host);
    mbedtls_net_connect(server_fd, host, port, MBEDTLS_NET_PROTO_TCP);

    // TLS 握手
    while (mbedtls_ssl_handshake(ssl) != 0) {
        // 等待握手完成
    }
    return 0;
}
```

```c
typedef struct __attribute__((packed)) {
    uint8_t  node_id;
    int16_t  temperature;   // x100, 25.5℃ = 2550
    uint16_t humidity;      // x100
    uint16_t soil_moisture; // x100

    uint16_t battery_mv;
    uint32_t uptime_min;
} sensor_payload_t;

void enter_stop_mode(uint32_t sleep_seconds) {
    // 配置 RTC 唤醒
    HAL_RTCEx_SetWakeUpTimer_IT(&hrtc, sleep_seconds,
                                 RTC_WAKEUPCLOCK_CK_SPRE_16BITS);
    HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON,
                          PWR_STOPENTRY_WFI);
}

int main(void) {
    HAL_Init();
    SystemClock_Config();

    // 初始化外设
    I2C_Init();
    SX1276_Init(868000000, SF7, BW125, CR4_5);

    while (1) {
        // 读取传感器
        sensor_payload_t payload;
        payload.node_id = NODE_ID;
        payload.temperature = (int16_t)(SHT31_ReadTemp() * 100);
        payload.humidity = (uint16_t)(SHT31_ReadHumidity() * 100);
        payload.soil_moisture = (uint16_t)(Soil_ReadPercent() * 100);

        SX1276_Send((uint8_t *)&payload, sizeof(payload));

        // 低功耗休眠 15 分钟
```

**振动信号分析（FFT + 特征提取）**：

```python
import numpy as np
from scipy.fft import fft, fftfreq

class VibrationAnalyzer:
    def __init__(self, sample_rate=10240, duration=1.0):
        self.sample_rate = sample_rate
        self.num_samples = int(sample_rate * duration)
        self.freqs = fftfreq(self.num_samples, 1/sample_rate)

    def analyze(self, vibration_data):
        """分析振动信号，提取特征"""
        # FFT变换
        fft_vals = np.abs(fft(vibration_data))[:self.num_samples//2]
        freqs = self.freqs[:self.num_samples//2]

        # 特征提取
        features = {
            # 时域特征
            'rms': np.sqrt(np.mean(vibration_data**2)),
            'peak': np.max(np.abs(vibration_data)),
            'crest_factor': np.max(np.abs(vibration_data)) /
                           np.sqrt(np.mean(vibration_data**2)),
            'kurtosis': float(self._kurtosis(vibration_data)),

            # 频域特征
            'dominant_freq': freqs[np.argmax(fft_vals)],
            'spectral_centroid': np.sum(freqs * fft_vals) /
                                np.sum(fft_vals),
            'band_energy_1x': self._band_energy(fft_vals, freqs, 0.9, 1.1),
            'band_energy_2x': self._band_energy(fft_vals, freqs, 1.9, 2.1),
            'harmonic_ratio': self._harmonic_ratio(fft_vals, freqs),
        }
        return features

    def _band_energy(self, fft_vals, freqs, f_low_ratio, f_high_ratio):
        """计算指定频带能量"""
        base_freq = freqs[np.argmax(fft_vals[1:]) + 1]
        mask = (freqs >= base_freq * f_low_ratio) & \
               (freqs <= base_freq * f_high_ratio)
        return np.sum(fft_vals[mask]**2)

    def _harmonic_ratio(self, fft_vals, freqs):
        """谐波比"""
        fundamental = np.max(fft_vals[1:])
        harmonics = np.sum(fft_vals[1:]) - fundamental
        return harmonics / (fundamental + 1e-10)

    def _kurtosis(self, data):
        """峰度"""
        mean = np.mean(data)
        std = np.std(data)
        return np.mean(((data - mean) / (std + 1e-10))**4) - 3
```

**边缘故障分类模型**：

```python
import onnxruntime as ort
import numpy as np

class FaultClassifier:
    def __init__(self, model_path="fault_model.onnx"):
        self.session = ort.InferenceSession(
            model_path,
            providers=['CPUExecutionProvider']
        )
        self.labels = ['正常', '轴承磨损', '不平衡', '不对中', '松动']

    def predict(self, features):
        """预测设备状态"""
        input_data = self._preprocess(features)
        outputs = self.session.run(None, {'input': input_data})
        probs = outputs[0][0]
        predicted_class = np.argmax(probs)
        confidence = probs[predicted_class]

        return {
            'status': self.labels[predicted_class],
            'confidence': float(confidence),
            'probabilities': {
                label: float(prob)
                for label, prob in zip(self.labels, probs)
            },
            'alert': predicted_class != 0 and confidence > 0.8
        }
```

```python
import paho.mqtt.client as mqtt
import json
from datetime import datetime
from collections import defaultdict

class EnergyCollector:
    def __init__(self, broker, port=1883):
        self.client = mqtt.Client("energy-gateway")
        self.client.on_message = self.on_message
        self.client.connect(broker, port)
        self.client.subscribe("building/+/energy/#")

        # 内存聚合窗口
        self.aggregates = defaultdict(lambda: {
            'power_sum': 0, 'count': 0,
            'peak_power': 0, 'energy_wh': 0
        })

    def on_message(self, client, userdata, msg):
        topic_parts = msg.topic.split('/')
        floor = topic_parts[1]
        device_type = topic_parts[3]
        data = json.loads(msg.payload)

        power_kw = data.get('power', 0)
        now = datetime.now()

        key = f"{floor}_{device_type}_{now.strftime('%Y%m%d_%H')}"
        agg = self.aggregates[key]
        agg['power_sum'] += power_kw
        agg['count'] += 1
        agg['peak_power'] = max(agg['peak_power'], power_kw)
        agg['energy_wh'] += power_kw * (data.get('interval_s', 60) / 3600)

        # 实时告警
        if power_kw > data.get('threshold', 100):
            self.publish_alert(floor, device_type, power_kw)

        # 每小时聚合上报
        if agg['count'] >= 60:
            self.publish_aggregate(key, floor, device_type, agg)

    def publish_aggregate(self, key, floor, device_type, agg):
        report = {
            'floor': floor,
            'device': device_type,
            'hour': key.split('_')[-1],
            'avg_power': agg['power_sum'] / agg['count'],
            'peak_power': agg['peak_power'],
            'energy_wh': round(agg['energy_wh'], 2),
            'timestamp': datetime.now().isoformat()
        }
        self.client.publish(
            f"building/{floor}/energy/hourly",
            json.dumps(report), qos=1
        )
        self.aggregates[key] = {
            'power_sum': 0, 'count': 0,
            'peak_power': 0, 'energy_wh': 0
        }
```

**智能温控规则引擎**：

```python
import schedule
from datetime import datetime, time

class HVACController:
    def __init__(self, modbus_client):
        self.mb = modbus_client
        self.schedule = {
            # 工作日
            'weekday': [
                {'start': time(7, 0), 'end': time(9, 0),
                 'temp': 24, 'mode': 'cooling'},
                {'start': time(9, 0), 'end': time(18, 0),
                 'temp': 23, 'mode': 'cooling'},
                {'start': time(18, 0), 'end': time(22, 0),
                 'temp': 25, 'mode': 'ventilation'},
                {'start': time(22, 0), 'end': time(7, 0),
                 'temp': None, 'mode': 'off'},
            ],
            # 周末
            'weekend': [
                {'start': time(0, 0), 'end': time(23, 59),
                 'temp': None, 'mode': 'off'},
            ]
        }

    def get_target(self):
        now = datetime.now()
        is_weekday = now.weekday() < 5
        day_type = 'weekday' if is_weekday else 'weekend'

        for period in self.schedule[day_type]:
            if period['start'] <= now.time() < period['end']:
                return period
        return {'temp': None, 'mode': 'off'}

    def control_loop(self):
        """每5分钟执行一次"""
        target = self.get_target()
        if target['temp'] is None:
            self.mb.write_register(0x0100, 0)  # 关闭 HVAC
            return

        current_temp = self.mb.read_register(0x0200) / 10.0

        # 带死区的温度控制（±0.5℃）
        if current_temp > target['temp'] + 0.5:
            self.mb.write_register(0x0100, 2)  # 制冷模式
            self.mb.write_register(0x0101, int(target['temp'] * 10))
        elif current_temp < target['temp'] - 0.5:
            self.mb.write_register(0x0100, 3)  # 制热模式
            self.mb.write_register(0x0101, int(target['temp'] * 10))
        else:
            self.mb.write_register(0x0100, 1)  # 通风模式

    def occupancy_override(self, floor, occupied):
        """根据占用状态调整"""
        if not occupied:
            # 无人模式：放宽温度范围
            self.mb.write_register(0x0102, 280)  # 上限 28℃
            self.mb.write_register(0x0103, 180)  # 下限 18℃
        else:
            # 有人模式：舒适范围
            self.mb.write_register(0x0102, 260)  # 上限 26℃
            self.mb.write_register(0x0103, 200)  # 下限 20℃
```
