# 自动化测试

## 核心概念

- **测试** - 验证软件是否符合预期
- **单元测试** - 测试最小代码单元
- **集成测试** - 测试模块间交互
- **自动化测试** - 自动执行测试用例

---

## 一、测试类型

### 1.1 测试层次

| 层次 | 说明 | 覆盖范围 |
|------|------|----------|
| 单元测试 | 测试函数/模块 | 70-80% |
| 集成测试 | 测试模块交互 | 15-20% |
| 系统测试 | 测试完整系统 | 5-10% |

---

### 1.2 测试方法

| 方法 | 说明 | 应用 |
|------|------|------|
| 黑盒测试 | 不关心内部实现 | 功能测试 |
| 白盒测试 | 关心内部逻辑 | 单元测试 |
| 灰盒测试 | 部分了解内部 | 集成测试 |

## 二、单元测试

### 2.1 测试框架

**Unity：**
```c
#include "unity.h"

void setUp(void) {
    // 测试前准备
}

void tearDown(void) {
    // 测试后清理
}

void test_add(void) {
    TEST_ASSERT_EQUAL(3, add(1, 2));
    TEST_ASSERT_EQUAL(0, add(-1, 1));
    TEST_ASSERT_EQUAL(-2, add(-1, -1));
}

int main(void) {
    UNITY_BEGIN();
    RUN_TEST(test_add);
    return UNITY_END();
}
```

**CUnit：**
```c
#include <CUnit/CUnit.h>
#include <CUnit/Basic.h>

void test_add(void) {
    CU_ASSERT_EQUAL(add(1, 2), 3);
    CU_ASSERT_EQUAL(add(-1, 1), 0);
}

int main(void) {
    CU_initialize_registry();
    CU_pSuite suite = CU_add_suite("MathTest", NULL, NULL);
    CU_add_test(suite, "test_add", test_add);
    CU_basic_run_tests();
    CU_cleanup_registry();
    return 0;
}
```

---

### 2.2 测试用例设计

**测试用例要素：**
- 测试名称
- 前置条件
- 输入数据
- 预期输出
- 实际输出

**示例：**
```c
// 测试函数：int max(int a, int b)
void test_max(void) {
    // 正常情况
    TEST_ASSERT_EQUAL(3, max(1, 3));
    TEST_ASSERT_EQUAL(3, max(3, 1));
    
    // 相等
    TEST_ASSERT_EQUAL(5, max(5, 5));
    
    // 负数
    TEST_ASSERT_EQUAL(-1, max(-1, -3));
    
    // 零
    TEST_ASSERT_EQUAL(0, max(0, -1));
}
```

### 2.3 测试覆盖率

**覆盖率类型：**
| 类型 | 说明 | 目标 |
|------|------|------|
| 行覆盖率 | 执行的行数 | ≥80% |
| 分支覆盖率 | 执行的分支 | ≥70% |
| 函数覆盖率 | 调用的函数 | 100% |

**工具：**
- gcov
- lcov
- gcovr

**生成覆盖率报告：**
```bash
gcc -fprofile-arcs -ftest-coverage main.c -o main
./main
gcov main.c
lcov --capture --directory . --output-file coverage.info
genhtml coverage.info --output-directory coverage_report
```

## 三、集成测试

### 3.1 集成策略

**自顶向下：**
- 从顶层模块开始
- 使用桩模块替代底层

**自底向上：**
- 从底层模块开始
- 使用驱动模块调用

**大爆炸：**
- 一次性集成所有模块
- 风险高

---

### 3.2 Mock技术

**Mock框架：**
```c
#include "fff.h"
DEFINE_FFF_GLOBALS;

FAKE_VALUE_FUNC(int, read_sensor);
FAKE_VOID_FUNC(send_data, uint8_t*, int);

void test_process_sensor_data(void) {
    // 设置Mock返回值
    read_sensor_fake.return_val = 25;
    
    // 执行测试
    process_sensor_data();
    
    // 验证调用
    TEST_ASSERT_EQUAL(1, read_sensor_fake.call_count);
    TEST_ASSERT_EQUAL(1, send_data_fake.call_count);
}
```

## 四、系统测试

### 4.1 功能测试

**测试内容：**
- 功能正确性
- 边界条件
- 异常处理

**测试用例：**
```c
void test_button_press(void) {
    // 模拟按键按下
    simulate_button_press(BUTTON_1);
    
    // 验证LED状态
    TEST_ASSERT_EQUAL(LED_ON, get_led_state(LED_1));
    
    // 模拟按键释放
    simulate_button_release(BUTTON_1);
    
    // 验证LED状态
    TEST_ASSERT_EQUAL(LED_OFF, get_led_state(LED_1));
}
```

---

### 4.2 性能测试

**测试指标：**
| 指标 | 说明 |
|------|------|
| 响应时间 | 从请求到响应的时间 |
| 吞吐量 | 单位时间处理量 |
| 资源占用 | CPU/内存使用率 |

**测试代码：**
```c
void test_performance(void) {
    uint32_t start = get_tick();
    
    // 执行操作
    for (int i = 0; i < 1000; i++) {
        process_data();
    }
    
    uint32_t end = get_tick();
    uint32_t elapsed = end - start;
    
    // 验证性能
    TEST_ASSERT_LESS_THAN(100, elapsed);  // 小于100ms
}
```

---

### 4.3 压力测试

**测试方法：**
- 长时间运行
- 高负载测试
- 边界条件测试

**示例：**
```c
void test_stress(void) {
    // 长时间运行
    for (int i = 0; i < 100000; i++) {
        process_data();
        
        // 检查内存泄漏
        TEST_ASSERT_EQUAL(0, get_heap_usage());
    }
}
```

## 五、测试自动化

### 5.1 CI/CD集成

**GitHub Actions：**
```yaml
name: CI

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    
    steps:
    - uses: actions/checkout@v2
    
    - name: Install dependencies
      run: sudo apt-get install -y gcc make
    
    - name: Build
      run: make
    
    - name: Test
      run: make test
    
    - name: Coverage
      run: make coverage
```

---

### 5.2 测试脚本

**Makefile：**
```makefile
# 测试目标
test: $(TEST_OBJS)
	$(CC) $(TEST_OBJS) -o test_runner
	./test_runner

# 覆盖率
coverage: CFLAGS += -fprofile-arcs -ftest-coverage
coverage: test
	gcov src/*.c
	lcov --capture --directory . --output-file coverage.info
	genhtml coverage.info --output-directory coverage_report

# 清理
clean:
	rm -f *.o *.gcda *.gcno *.gcov coverage.info
	rm -rf coverage_report
```

```
测试主机 ──→ 仿真器 ──→ 被测设备
    ↑                      │
    └────── 数据采集 ←─────┘
```

**测试内容：**
- 外设驱动
- 通信协议
- 实时性能

---

### 6.2 目标板测试

**测试方法：**
- 串口输出测试结果
- JTAG调试
- 断言宏

**断言宏：**
```c
#ifdef DEBUG
#define ASSERT(condition) do { \
    if (!(condition)) { \
        printf("ASSERT failed: %s at %s:%d\n", \
               #condition, __FILE__, __LINE__); \
        while(1); \
    } \
} while(0)
#else
#define ASSERT(condition)
#endif
```

---

### 6.3 通信测试

**串口测试：**
```c
void test_uart_communication(void) {
    // 发送测试数据
    uart_send("TEST", 4);
    
    // 接收响应
    uint8_t response[10];
    int len = uart_receive(response, sizeof(response), 1000);
    
    // 验证响应
    TEST_ASSERT_EQUAL(4, len);
    TEST_ASSERT_EQUAL_MEMORY("OK", response, 2);
}
```

## 七、测试最佳实践

### 7.1 测试原则

**FIRST原则：**
- Fast：测试要快
- Independent：测试要独立
- Repeatable：测试可重复
- Self-validating：测试自验证
- Timely：测试要及时

---

### 7.2 测试命名

**命名规范：**
```c
// 模块_场景_预期结果
void test_max_positive_numbers_returns_larger(void);
void test_max_negative_numbers_returns_less_negative(void);
void test_max_equal_numbers_returns_same(void);
```
