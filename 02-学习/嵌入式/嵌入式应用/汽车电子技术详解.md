## 1. 汽车电子概述

### 1.1 汽车电子发展历程

| 阶段 | 时间 | 特征 | 代表技术 |
|------|------|------|----------|
| 机械时代 | ~1970s | 纯机械控制 | 化油器、机械点火 |
| 电子化初期 | 1970s-1990s | 单片机引入 | EFI电喷、ABS |
| 分布式ECU | 1990s-2010s | 大量独立ECU | CAN总线、车身电子 |
| 域集中式 | 2010s-2020s | 域控制器整合 | 域控制器、ADAS |
| 中央计算 | 2020s+ | 跨域融合 | 中央计算平台、SOA |

### 1.2 汽车E/E架构演进

#### 分布式架构（传统）

```
┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐
│ ECM  │  │ TCM  │  │ BCM  │  │ ESP  │  │ IC   │
│发动机 │  │变速器 │  │车身   │  │制动   │  │仪表   │
└──┬───┘  └──┬───┘  └──┬───┘  └──┬───┘  └──┬───┘
   └─────────┴─────────┴────┬────┴─────────┘
                        CAN Bus
```

- 每个功能对应独立ECU
- 典型高端车辆含 **70-100+ 个ECU**
- 线束复杂，重量可达 **40-60kg**
- 软件高度碎片化，难以OTA

#### 域集中式架构

```
┌─────────────────────────────────────────────────┐
│              中央网关 / 跨域控制器                 │
├──────────┬──────────┬──────────┬──────────┬──────┤
│ 动力域   │ 底盘域   │ 车身域   │ 座舱域   │ ADAS │
│ Domain   │ Domain   │ Domain   │ Domain   │Domain│
│Controller│Controller│Controller│Controller│Ctrler│
└──────────┴──────────┴──────────┴──────────┴──────┘
```

**五大域划分：**

| 域 | 功能范围 | 典型供应商 |
|----|----------|-----------|
| 动力域（Powertrain） | 发动机、变速箱、混动控制 | 博世、大陆 |
| 底盘域（Chassis） | 制动、转向、悬架 | 采埃孚、蒂森克虏伯 |
| 车身域（Body） | 灯光、车窗、空调、门锁 | 海拉、法雷奥 |
| 座舱域（Cockpit） | 中控、仪表、HUD、音响 | 高通、三星哈曼 |
| ADAS域 | 感知、决策、执行 | Mobileye、英伟达 |

            │   骨干以太网    │
    ┌───────┴────┐    ┌────┴───────┐
    │ Zone控制-左前│    │ Zone控制-右前│
    │ (传感器/执行)│    │ (传感器/执行)│
    └────────────┘    └────────────┘
    ┌───────┴────┐    ┌────┴───────┐
    │ Zone控制-左后│    │ Zone控制-右后│
    └────────────┘    └────────────┘

- ECU数量减少至 **3-5个** 高性能计算单元
- 线束缩短 30-50%，减重显著
- 软件通过 **SOA（面向服务架构）** 解耦
- 代表：特斯拉 HW4.0、大众 VW.OS、蔚来 NT2.0

## 2. 车载网络

### 2.1 车载网络总览

| 网络类型 | 速率 | 典型应用 | 标准 |
|----------|------|----------|------|
| LIN | 20 kbit/s | 车窗、雨刷、座椅 | ISO 17987 |
| CAN | 125-500 kbit/s | 动力、车身、诊断 | ISO 11898 |
| CAN FD | 最高 8 Mbit/s | 动力域、混合负载 | ISO 11898-1 |
| FlexRay | 10 Mbit/s | 底盘线控 | ISO 17458 |
| MOST | 25-150 Mbit/s | 多媒体 | ISO 21806 |
| 100BASE-T1 | 100 Mbit/s | ADAS、网关 | IEEE 802.3bw |
| 1000BASE-T1 | 1 Gbit/s | 骨干网、HPC | IEEE 802.3bp |

### 2.2 CAN 总线

#### CAN 帧格式（标准帧 / 11位ID）

```
┌─────┬────┬─────┬───┬─────┬───────────┬─────┬───┬───┬─────┬─────┐
│ SOF │ ID │ RTR │IDE│ r0  │  DLC(4b)  │Data │CRC│ACK│ EOF │ IFS │
│ 1b  │11b │ 1b  │0b │ 1b  │   4 bit   │0-8B │15b│2b │ 7b  │ 3b  │
└─────┴────┴─────┴───┴─────┴───────────┴─────┴───┴───┴─────┴─────┘
```

- **SOF（Start of Frame）**：显性位（0），标志帧开始
- **ID（Identifier）**：11位仲裁ID，值越小优先级越高
- **RTR**：0=数据帧，1=远程帧
- **DLC**：数据长度码（0-8字节）
- **CRC**：15位CRC校验 + 1位界定符
- **ACK**：接收方确认
- **EOF**：7个隐性位（1）
- **IFS**：帧间空间（3位隐性）

#### CAN 仲裁机制

```
节点A: ID = 0x100 → 0001 0000 0000
节点B: ID = 0x110 → 0001 0001 0000
                     ↑ ↑
                   相同  这里A发0(显性), B发1(隐性)
                         → A赢得仲裁，B退出发送
```

- **非破坏性仲裁**：获胜节点无损继续发送
- **逐位比较**：显性（0）覆盖隐性（1）
- **优先级**：ID越小优先级越高
- 采用 **NRZ编码** + **位填充**（连续5个相同位后插入1个反相位）

#### CAN 错误处理

| 错误类型 | 检测方式 | 处理 |
|----------|----------|------|
| 位错误 | 发送节点回读对比 | 发送错误帧 |
| 填充错误 | 位填充规则违反 | 发送错误帧 |
| CRC错误 | CRC校验失败 | 发送错误帧 |
| 格式错误 | 固定格式位违反 | 发送错误帧 |
| ACK错误 | 发送方未检测到ACK | 发送错误帧 |

**错误计数器机制：**
- TEC（发送错误计数器）/ REC（接收错误计数器）
- TEC > 127 → 被动错误状态
- TEC > 255 → Bus-Off（脱离总线）

### 2.3 CAN FD（Flexible Data-rate）

```
CAN FD 帧:
┌─────┬────┬───┬───┬───┬─────┬──────────────┬─────┬───┬───┬─────┐
│ SOF │ ID │EDL│r0 │BRS│ESI  │  DLC(4b)     │Data │CRC│ACK│ EOF │
│ 1b  │11b │1b │1b │1b │ 1b  │   4 bit      │≤64B │*  │2b │ 7b  │
└─────┴────┴───┴───┴───┴─────┴──────────────┴─────┴───┴───┴─────┘
                   ↑     ↑
              标志FD帧  切换波特率
```

**CAN FD vs CAN Classic 对比：**

| 特性 | CAN Classic | CAN FD |
|------|-------------|--------|
| 数据段速率 | ≤1 Mbit/s | ≤8 Mbit/s（数据段） |
| 最大载荷 | 8 字节 | 64 字节 |
| DLC编码 | 直接映射 | 非线性映射 |
| CRC | 15位 | 17/21位 |
| 仲裁段速率 | ≤1 Mbit/s | ≤1 Mbit/s（不变） |
| 填充位 | CRC段也填充 | CRC段无填充（Stuff Count） |

**DLC非线性映射（CAN FD）：**

| DLC | 0-8 | 9 | 10 | 11 | 12 | 13 | 14 | 15 |
|-----|-----|---|----|----|----|----|----|-----|
| 字节数 | 0-8 | 12 | 16 | 20 | 24 | 32 | 48 | 64 |

### 2.4 LIN 总线

```
LIN 帧结构:
┌────────┬────────┬──────────┬──────────┬────────┐
│  Header │  Data  │    Data  │    ...   │ Check  │
│ Sync+ID │ Byte 0 │  Byte 1  │          │  sum   │
└────────┴────────┴──────────┴──────────┴────────┘
   ↑           ↑
 主节点发送  从节点响应
```

- **单线传输**，无需专用收发器芯片
- **单主多从**架构（1主 + 最多15从）
- 波特率 **1-20 kbit/s**
- 适用于低实时性场景：车窗、雨刷、后视镜、座椅

**LIN vs CAN 对比：**

| 特性 | LIN | CAN |
|------|-----|-----|
| 线缆 | 单线 | 差分双线 |
| 速率 | ≤20 kbit/s | ≤1 Mbit/s |
| 拓扑 | 单主多从 | 多主 |
| 成本 | 极低 | 低 |
| 实时性 | 低 | 中 |

### 2.5 FlexRay

- **双通道冗余**，每通道 10 Mbit/s
- **确定性时分多址（TDMA）**，支持静态段和动态段
- 适用于线控底盘（Steer-by-Wire、Brake-by-Wire）
- 通信周期由 **静态段 + 动态段 + 符号窗口 + NIT** 组成

```
FlexRay 通信周期:
┌──────────┬──────────┬────┬────┐
│ Static   │ Dynamic  │ SW │NIT │
│ Segment  │ Segment  │    │    │
│ (确定性)  │ (事件触发)│    │    │
└──────────┴──────────┴────┴────┘
     ↑
  每个时隙分配给固定节点
```

### 2.6 车载以太网

#### 100BASE-T1（IEEE 802.3bw）

- 单对非屏蔽双绞线（UTP）传输
- 全双工 100 Mbit/s
- 使用 **PAM3**（三电平脉冲幅度调制）编码
- 传输距离 ≤15m（车内环境足够）
- **Echo Cancellation** 实现全双工

#### 1000BASE-T1（IEEE 802.3bp）

- 单对线 1 Gbit/s
- 使用 **PAM3** 编码（与100BASE-T1类似）
- 支持 ≤40m 传输距离
- 适用于骨干网络、摄像头/雷达高速数据

#### 车载以太网协议栈

```
┌─────────────────────────────────┐
│    应用层: SOME/IP, DoIP, AVB   │
├─────────────────────────────────┤
│    传输层: TCP/UDP              │
├─────────────────────────────────┤
│    网络层: IPv4/IPv6            │
├─────────────────────────────────┤
│    数据链路: 802.1Q VLAN        │
├─────────────────────────────────┤
│    物理层: 100BASE-T1/T1S/T1P  │
│           1000BASE-T1          │
└─────────────────────────────────┘
```

**SOME/IP（Scalable service-Oriented MiddlewarE over IP）：**
- 面向服务的通信中间件
- 支持 Request/Response、Notification、Fire&Forget
- 服务发现（SD）机制，动态注册/发现
- 序列化格式：大端字节序

## 3. AUTOSAR 架构

### 3.1 AUTOSAR 概述

**AUTOSAR（AUTomotive Open System ARchitecture）** 是由汽车OEM和供应商联合建立的开放软件架构标准，旨在实现软件的可移植性和可复用性。

**核心目标：**
- 软件与硬件解耦
- 标准化软件接口
- 支持不同供应商ECU的集成

### 3.2 Classic Platform（CP）分层架构

```
┌─────────────────────────────────────────────┐
│             Application Layer (SWC)          │
│    ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐     │
│    │SWC-1 │ │SWC-2 │ │SWC-3 │ │SWC-4 │     │
│    └──┬───┘ └──┬───┘ └──┬───┘ └──┬───┘     │
├───────┼────────┼────────┼────────┼──────────┤
│       └────────┴────────┴────────┘          │
│            RTE (Runtime Environment)        │
├─────────────────────────────────────────────┤
│        Basic Software (BSW)                  │
│  ┌──────────────────────────────────────┐   │
│  │ Services Layer                       │   │
│  │ (OS, NvM, COM, Diagnostic, ECU Mgmt)│   │
│  ├──────────────────────────────────────┤   │
│  │ ECU Abstraction Layer                │   │
│  │ (I/O HW Abstraction, Memory, Com)   │   │
│  ├──────────────────────────────────────┤   │
│  │ Complex Drivers                      │   │
│  │ (非标准硬件直接访问)                  │   │
│  ├──────────────────────────────────────┤   │
│  │ Microcontroller Abstraction (MCAL)   │   │
│  │ (DIO, ADC, PWM, SPI, CAN, LIN,...)  │   │
│  └──────────────────────────────────────┘   │
├─────────────────────────────────────────────┤
│           Microcontroller (Hardware)         │
└─────────────────────────────────────────────┘
```

#### BSW（基础软件）详解

| 层次 | 模块 | 职责 |
|------|------|------|
| 服务层 | OS | AUTOSAR OS，基于OSEK/VDX |
| 服务层 | COM | 信号级通信（I-PDU封装） |
| 服务层 | NvM | 非易失存储管理 |
| 服务层 | DEM | 诊断事件管理 |
| 服务层 | DCM | 诊断通信管理 |
| ECU抽象层 | I/O HW Abstraction | I/O硬件抽象 |
| ECU抽象层 | Communication Abstraction | CAN/LIN/ETH抽象 |
| MCAL | DIO | 数字I/O驱动 |
| MCAL | ADC | 模数转换驱动 |
| MCAL | PWM | 脉宽调制驱动 |
| MCAL | CAN Driver | CAN控制器驱动 |
| MCAL | SPI Handler | SPI通信驱动 |

#### RTE（运行时环境）

- 自动生成的 **通信中间件**
- 提供标准接口：**Sender-Receiver**（数据交换）、**Client-Server**（服务调用）
- SWC不直接访问BSW，全部通过RTE
- 支持SWC跨ECU的分布式通信（需配合COM）

#### SWC（软件组件）

```
SWC 内部结构:
┌──────────────────────────────┐
│          SWC                 │
│  ┌────────────────────────┐  │
│  │   Application Logic    │  │
│  └────────────────────────┘  │
│                              │
│  Ports:                      │
│  ┌─────┐  ┌─────┐  ┌─────┐  │
│  │ PPort│  │ RPort│  │CPort│  │
│  │(提供)│  │(需求)│  │(客户端)│
│  └──┬──┘  └──┬──┘  └──┬──┘  │
│     │       │       │       │
│  Sender  Receiver  Client   │
│  -Receiver Interface        │
└──────────────────────────────┘
```

## 4. 功能安全 ISO 26262

### 4.1 ISO 26262 概述

ISO 26262 是针对 **道路车辆电气/电子（E/E）系统** 的功能安全标准，适用于量产乘用车（≤3500kg）。标准共12个部分（Part 1-12），覆盖从概念到报废的全生命周期。

### 4.2 ASIL 等级

**ASIL（Automotive Safety Integrity Level）** 由三个因素评估：

| 严重度 (S) | 暴露率 (E) | 可控性 (C) | ASIL等级 |
|-----------|-----------|-----------|---------|
| S0-S3 | E0-E4 | C0-C3 | QM / A / B / C / D |

```
ASIL 分配矩阵 (简表):

         C1(简单可控)  C2(一般)  C3(难控)
S3(致命)    B          C          D
S2(严重)    A          B          C
S1(轻伤)    QM         A          B
S0(无伤)    QM         QM         A

注: 实际分配需综合S+E+C三维评估
```

**ASIL等级含义：**

### 4.4 HARA（危害分析与风险评估）

**HARA流程：**

1. **识别危害**：系统性分析功能异常可能的危害
2. **评估风险**：对每个危害评估 S（严重度）、E（暴露率）、C（可控性）
3. **确定ASIL**：根据S/E/C矩阵确定ASIL等级
4. **定义安全目标**：每个危害对应一个安全目标

**示例——电动助力转向（EPS）HARA：**

| 危害ID | 危害描述 | S | E | C | ASIL | 安全目标 |
|--------|----------|---|---|---|------|----------|
| H1 | 意外转向助力 | 3 | 3 | 2 | D | 不得产生非预期转向扭矩 |
| H2 | 助力突然丧失 | 3 | 2 | 2 | C | 不得突然丧失转向助力 |
| H3 | 助力响应延迟 | 2 | 3 | 2 | B | 转向响应延迟不超过XX ms |

### 4.5 FMEA（失效模式与影响分析）

| CAN TX | 常显性 | 驱动电路短路 | 总线持续显性 | 通信丢失 | Bus-Off检测 | B |

### 6.2 毫米波雷达

**频段分类：**

| 频段 | 频率 | 典型应用 |
|------|------|----------|
| 短距SRR | 24 GHz | 盲区监测、变道辅助 |
| 中距MRR | 77 GHz | 自适应巡航、前碰撞预警 |
| 长距LRR | 77 GHz | 高速ACC、自动紧急制动 |

**FMCW（调频连续波）原理：**

```
发射频率:
  ↑
  │    /\/\/\/\
  │   /        \
  │  /          \
  │ /            \
  └──────────────→ 时间

接收频率 (延迟):
  ↑
  │      /\/\/\/\
  │     /        \
  │    /          \
  │   /            \
  └──────────────→ 时间

差频 → 距离信息 + 速度信息
```

- **距离测量**：通过差频计算 `R = c*T*fb / (2*BW)`
- **速度测量**：通过Chirp间相位差计算
- **角度测量**：通过多天线相位差（波束成形）

**车载雷达指标：**

| 参数 | 长距雷达 | 中距雷达 | 短距雷达 |

| 探测距离 | 250m+ | 100-160m | 30m |
| 距离精度 | ±0.1m | ±0.1m | ±0.05m |
| 速度精度 | ±0.1km/h | ±0.1km/h | ±0.1km/h |
| 角度精度 | ±0.5° | ±1° | ±2° |
| 天线数 | 12T/16R | 4T/4R | 2T/4R |

### 6.3 激光雷达（LiDAR）

**技术路线对比：**

| 类型 | 原理 | 优势 | 劣势 |
|------|------|------|------|
| 机械旋转 | 电机带动激光模块360度旋转 | 视场角大、点云密 | 体积大、可靠性低 |
| MEMS微镜 | 微振镜反射激光 | 成本适中、体积小 | 视场角有限 |

      ↕ DC/DC ↕
   12V系统
```

- 电压范围：**36-52V**
- 功率能力：**10-15kW**（相比12V的3-4kW）
- 典型应用：BSG（Belt-driven Starter Generator）、电动增压
- 节油效果：**10-15%**

| 800V | 500-920V | 高性能快充平台 |

### 7.2 汽车瞬态特性

#### 冷启动（Cold Crank）

```
电压波形:
  14V ───┐
         │    ┌───┐
  10V    └────┘   │
         │        │
   6V ───┤        └── 恢复
         │
   4V ───┘ ← 最低点(持续时间t)
         ───────────────→ 时间
```

- 蓄电池在 **-30°C** 低温下启动
- 起动瞬间电压可跌落至 **4-6V**
- 持续时间：**10-40ms**
- 要求ECU在电压低至 **4V** 时仍能正常工作

#### 负载突降（Load Dump）

- 发电机运行时突然断开负载
- 电压尖峰可达 **40-60V**（无钳位）/ **35-40V**（有钳位TVS）
- 持续时间：**400ms**（ISO 7637-2 Pulse 5）
- ECU需具备 **TVS保护** 或 **钳位电路**

#### 其他瞬态脉冲

| 脉冲类型 | ISO 7637-2 | 特征 | 持续时间 |
|----------|------------|------|----------|

### 8.2 OTA 安全签名机制

```
签名流程 (云端):
┌──────────┐    ┌──────────┐    ┌──────────┐
│ 软件包    │───→│ SHA-256  │───→│ RSA/ECDSA│

                              │ 随软件包下发  │
                              └─────────────┘

验签流程 (车端):
┌──────────┐    ┌──────────┐    ┌──────────┐

**安全要素：**
- **TLS 1.2/1.3** 保护传输通道

- **Secure Boot** 从ROM到应用逐级验签

### 8.3 回滚机制

```
Flash 分区布局:
┌──────────────────────────────┐
│ Bootloader (不可更新)         │
├──────────────────────────────┤
│ Bank A (当前活动分区)         │
│  - 应用程序                   │
│  - 配置数据                   │
│  - 版本信息                   │
├──────────────────────────────┤
│ Bank B (备份/待更新分区)      │
│  - 应用程序 (OTA下载)         │
│  - 配置数据                   │
│  - 版本信息                   │
├──────────────────────────────┤
│ Reserved (回滚恢复区)         │
└──────────────────────────────┘
```

**A/B分区策略：**
1. 新版本下载至 **Bank B**
2. 校验通过后，Bootloader切换启动至 **Bank B**
3. 运行正常 → Bank B成为活动分区
4. 启动失败/运行异常 → 自动回滚至 **Bank A**

**回滚触发条件：**
- 启动超时（Bootloader看门狗）
- 运行时自检失败（CRC、Health Monitor）
- 应用程序主动请求回滚

### 8.4 刷写流程

```
完整OTA刷写流程:

1. 通知阶段
   Cloud → T-Box → OTA Master → 被刷ECU
   (通知有新版本可用)

2. 下载阶段
   Cloud ──HTTPS──→ T-Box (下载差分/完整包)

3. 预检阶段
   - 检查电池电压 > 阈值 (通常12.5V)
   - 检查点火状态
   - 检查车速 = 0
   - 检查网络连接

4. 刷写阶段
   - OTA Master 转发刷写数据
   - 使用 UDS $34-$36-$37 服务
   - (RequestDownload → TransferData → TransferExit)
   - 逐块校验 CRC32

5. 激活阶段
   - 验证完整软件签名
   - 标记新分区为活动分区
   - ECU复位

6. 验证阶段
   - 新版本自检
   - 报告版本号至云端
   - 监控运行状态 (24-48h)

7. 确认阶段
   - 运行正常 → 更新成功
   - 异常 → 自动回滚 + 上报
```

**OBD-II 诊断模式（SID）：**

### 9.2 UDS（统一诊断服务）

**UDS（ISO 14229）** 是诊断通信的上层协议规范，定义了完整的诊断服务集。

**常用UDS服务：**

| SID | 服务名称 | 功能 |
|-----|---------|------|
| 0x10 | DiagnosticSessionControl | 切换诊断会话 |
| 0x11 | ECUReset | ECU复位 |
| 0x14 | ClearDiagnosticInformation | 清除DTC |
| 0x19 | ReadDTCInformation | 读取DTC信息 |
| 0x22 | ReadDataByIdentifier | 读取DID数据 |
| 0x23 | ReadMemoryByAddress | 读取内存 |
| 0x27 | SecurityAccess | 安全访问（种子/密钥） |
| 0x28 | CommunicationControl | 通信控制 |
| 0x2E | WriteDataByIdentifier | 写入DID数据 |
| 0x2F | InputOutputControlByIdentifier | I/O控制 |
| 0x31 | RoutineControl | 例程控制 |
| 0x34 | RequestDownload | 请求下载 |
| 0x36 | TransferData | 数据传输 |
| 0x37 | RequestTransferExit | 传输退出 |
| 0x3E | TesterPresent | 测试仪在线 |
| 0x85 | ControlDTCSetting | DTC设置控制 |

**诊断会话类型：**

| 会话 | SID | 功能 | 权限 |
|------|-----|------|------|
| 默认会话 | 0x01 | 基本诊断 | 低 |

**安全访问流程（Seed-Key）：**

```
Tester                     ECU
  │                         │
  │ ── 0x27 01 (请求种子) ─→│
  │                         │
  │ ←── 0x67 01 + Seed ────│
  │                         │
  │    (计算Key = f(Seed))  │
  │                         │
  │ ── 0x27 02 + Key ──────→│
  │                         │
  │    (验证Key)            │
  │ ←── 0x67 02 (成功) ────│
  │                         │
  │    (安全等级已解锁)      │
```

### 9.3 DTC（故障码）

**DTC结构（UDS格式）：**

```
DTC = 3字节 = 24位

┌──────────────┬──────────────┬──────────────┐
│   Byte 1     │   Byte 2     │   Byte 3     │
│  (DTC高字节)  │  (DTC中字节)  │  (DTC低字节)  │
└──────────────┴──────────────┴──────────────┘
       ↑
  高2位定义DTC类型:
  00 = Powertrain (P)
  01 = Chassis (C)
  10 = Body (B)
  11 = Network/Communication (U)
```

**DTC状态字节（StatusByte）：**

| 位 | 名称 | 含义 |
|----|------|------|
| Bit 0 | testFailed | 当前测试失败 |
| Bit 1 | testFailedThisOperationCycle | 本操作周期内测试失败 |
| Bit 2 | pendingDTC | 待定DTC（已失败但未确认） |
| Bit 3 | confirmedDTC | 已确认DTC |
| Bit 4 | testNotCompletedSinceLastClear | 清除后测试未完成 |
| Bit 5 | testFailedSinceLastClear | 清除后测试失败过 |
| Bit 6 | testNotCompletedThisOperationCycle | 本周期测试未完成 |
| Bit 7 | warningIndicatorRequested | 请求警告指示灯 |

**常见DTC示例：**

| DTC | 含义 | 可能原因 |
|-----|------|----------|
| P0300 | 随机/多缸失火 | 火花塞、喷油嘴、点火线圈 |
| P0171 | 系统过稀（Bank 1） | 进气泄漏、MAF故障 |
| P0420 | 催化转化器效率低 | 三元催化器老化 |
| U0001 | CAN总线通信故障 | 线路断路/短路 |
| C0035 | 左前轮速传感器故障 | 传感器/线路故障 |

### 10.2 SOC 估算方法

| 方法 | 原理 | 精度 | 适用性 |
|------|------|------|--------|
| 安时积分法 | 积分电流计算容量变化 | ±3-5% | 简单，需初始SOC |
| OCV法 | 开路电压查SOC-OCV表 | ±1-2% | 需长时间静置 |
| 卡尔曼滤波 | 状态估计融合多信息 | ±1-3% | 复杂，实时性好 |
| 机器学习 | 数据驱动预测 | ±1-2% | 需大量数据训练 |

**扩展卡尔曼滤波（EKF）SOC估算：**

```
状态方程: SOC(k+1) = SOC(k) - η*I(k)*Δt / Cn
观测方程: V(k) = OCV(SOC(k)) - I(k)*R - ΔV

其中:
- SOC(k): k时刻荷电状态
- η: 库仑效率
- I(k): 充放电电流
- Cn: 额定容量
- OCV(SOC): 开路电压-SOC函数
- R: 内阻
- ΔV: 极化电压
```

### 10.3 均衡策略

#### 被动均衡

```
原理: 通过电阻放电消耗高电压电芯的多余能量

┌──────┐   ┌──────┐   ┌──────┐
│Cell 1│   │Cell 2│   │Cell 3│
│ 4.1V │   │ 4.2V │   │ 4.15V│
└──┬───┘   └──┬───┘   └──┬───┘
   │     ┌──R─┤          │
   │     │    │          │
   │     └→ 开关控制      │
   └──────────────────────┘

均衡后: 所有电芯 ≈ 4.1V (取最低值)
```

- 优点：电路简单，成本低
- 缺点：能量浪费（转化为热），速度慢
- 均衡电流：**50-200mA**

#### 主动均衡

| 方式 | 原理 | 效率 | 复杂度 |
|------|------|------|--------|
| 电容式 | 开关电容转移能量 | 85-90% | 中 |
| 电感式 | Buck/Boost变换器 | 80-90% | 高 |
| 变压器式 | 隔离变压器转移 | 85-95% | 高 |

热管理策略:

         ┌──────────────────┐

### 11.4 感知-决策-规划-控制流水线

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│  感知    │───→│  决策    │───→│  规划    │───→│  控制    │
│Perception│   │Decision │   │Planning │   │Control  │
└─────────┘    └─────────┘    └─────────┘    └─────────┘

感知:
- 目标检测 (2D/3D检测框)
- 语义分割 (车道线/可行驶区域)
- 目标跟踪 (多目标跟踪MOT)
- 定位 (高精地图匹配/GNSS+IMU)

决策:
- 行为决策 (跟车/换道/停车/绕行)
- 场景理解 (高速/城区/路口)
- 风险评估 (碰撞概率计算)

规划:
- 路径规划 (全局路径 + 局部轨迹)
- 速度规划 (速度曲线优化)
- 轨迹优化 (舒适性/安全性约束)

控制:
- 横向控制 (转向角 PID/MPC)
- 纵向控制 (加速度/制动 PID/MPC)
- 执行器接口 (EPS/iBooster)
```

### 11.5 目标检测算法

| 阶段 | 算法 | 特点 |
|------|------|------|
| 传统 | HOG+SVM | 手工特征，精度低 |
| 2D检测 | YOLO/SSD/Faster R-CNN | 实时2D检测框 |
| 3D检测 | PointPillars/CenterPoint | 点云3D检测 |
| BEV感知 | BEVFormer/LSS | 鸟瞰图统一感知 |
| 端到端 | UniAD/BEV+OCC | 感知-规划一体化 |

### 11.6 高精地图

**高精地图（HD Map）要素：**

| 层级 | 内容 | 精度 |
|------|------|------|
| 道路层 | 道路几何、拓扑、车道连接 | ±10cm |
| 车道层 | 车道线类型、宽度、曲率 | ±10cm |
| 定位层 | 地标、路面标志、杆状物 | ±10cm |
| 动态层 | 实时交通、施工区 | 实时更新 |
