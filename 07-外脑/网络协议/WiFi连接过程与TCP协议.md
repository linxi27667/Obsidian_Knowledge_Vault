# WiFi 连接过程与 TCP 协议

## WiFi 上电获取的信息

ESP32 连 WiFi 的过程中，依次拿到：

| 步骤 | 做什么 | 获取什么 |
|------|--------|---------|
| ① 物理层连接 | 扫描射频信号 | 找到目标 SSID 的路由器 |
| ② 认证 | 发送密码 | 路由器验证通过 |
| ③ 关联 | 加入路由器 | 分配 Association ID |
| ④ DHCP | 广播"我要 IP" | IP、子网掩码、网关、DNS |
| ⑤ 完成 | 可以通信了 | 能访问局域网和互联网 |

DHCP 获取的四个信息：

| 信息 | 示例 | 作用 |
|------|------|------|
| IP 地址 | 192.168.1.100 | 你自己的地址 |
| 子网掩码 | 255.255.255.0 | 判断是否同一局域网 |
| 网关地址 | 192.168.1.1 | 路由器地址（出公网经过它） |
| DNS 服务器 | 192.168.1.1 | 域名解析（域名→IP） |

### ESP-IDF 事件流

```
WIFI_EVENT_STA_START         ← WiFi 驱动启动
WIFI_EVENT_STA_CONNECTED     ← 物理层连上（还没 IP）
IP_EVENT_STA_GOT_IP          ← 拿到 IP，真正可用了
```

拿到 IP 之后 MQTT 才能连 broker。

## TCP 协议

TCP 是**传输层协议**，保证数据可靠传输。底层由 lwIP 协议栈自动处理。

### 三次握手（建连接）

```
ESP32  → Broker:  SYN（你好，能连吗？）
Broker → ESP32:  SYN+ACK（可以，确认）
ESP32  → Broker:  ACK（好的，连上了）
```

### 数据传输

```
send() → TCP 切包、编号、逐个发送、等 ACK
recv() ← 收包、排序、重组（丢包自动重传，流控自动限速）
```

### 四次挥手（断连接）

```
close() → 双方互相确认，安全断开
```

### 应用代码视角

```c
connect()   → 底层三次握手
send()      → 底层分包+发送+等ACK
recv()      → 底层收包+排序+重组
close()     → 底层四次挥手
```
