# 浏览器自动化桥接工具

本工具让 Codex 通过本机浏览器页面读取信息和执行用户授权的网页操作。当前桥接版本支持 Microsoft Edge 和 Google Chrome。

项目仓库：[linxi27667/agent-browser-bridge](https://github.com/linxi27667/agent-browser-bridge)（私有）

## 怎么理解

- Edge 和 Chrome 都使用 Chromium 内核，所以可以通过同一种本地连接方式桥接。
- 每个浏览器要用独立的专用配置目录。Edge 与 Chrome 的登录状态互不共用。
- 浏览器只开放本机 127.0.0.1 调试端口，并在连接前核对浏览器类型、端口、profile 和代理。
- 不连接日常 Edge/Chrome profile，不复制 Cookie；专用 profile 留在本机，不放进 Git。
- 登录和验证码默认由用户处理。若业务项目明确授权使用本机凭据配置，应按该项目自己的规则操作，且不输出或保存密码。
- Firefox、Safari 不是这套 CDP 桥接的实机支持范围。要支持它们，需要独立适配 Playwright 或 WebDriver。

## 启动方式

Edge 示例（端口 9224）：

    pwsh -NoProfile -File .\lib\profile\Start-DebugBrowser.ps1 -Browser Edge -Port 9224 -Scene K3Cloud

Chrome 示例（端口 9222）：

    pwsh -NoProfile -File .\lib\profile\Start-DebugBrowser.ps1 -Browser Chrome -Port 9222

默认配置目录位于本机 LOCALAPPDATA 下的 AgentBrowserBridge\profiles，不在项目仓库内。启动器会拒绝复用日常浏览器配置目录，也不会自动关闭已打开的浏览器。

## 连接前校验

运行 check 前，按要连接的浏览器设置下列环境变量：

    CDP_HTTP=http://127.0.0.1:9224
    BROWSER_BRIDGE_REQUIRE_INSTANCE=1
    BROWSER_BRIDGE_EXPECT_PROFILE=<本机专用配置目录的绝对路径>
    BROWSER_BRIDGE_EXPECT_PROXY=none
    BROWSER_BRIDGE_EXPECT_BROWSER=edge

然后执行：

    npm run check
    npm run smoke

check 验证桥接端口连到指定的浏览器。smoke 使用隔离的 about:blank 测试页，不读取或提交业务单据。

依赖安装和项目回归：

    npm ci --ignore-scripts
    npm test
    npm audit --omit=dev --audit-level=high
