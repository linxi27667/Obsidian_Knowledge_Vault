# NVS 与 Flash 及文件系统

## NVS vs 外部 Flash

| | NVS (Non-Volatile Storage) | 外部 Flash |
|--|---------------------------|-----------|
| 位置 | 芯片内部 Flash 的一个分区 | 板子上额外焊的 SPI Flash 芯片 |
| 大小 | 通常几十 KB | 几 MB（4MB、16MB 等） |
| 存什么 | WiFi 密码、MQTT 配置、用户设置 | 固件代码、文件系统、OTA 升级包 |
| 读写方式 | key-value 键值对（像字典） | 按地址读写（像硬盘） |
| 速度 | 快 | 慢（走 SPI 总线） |
| 擦写次数 | 有限（~10 万次） | 有限（~10 万次） |

## ESP32 内部 Flash 典型布局（4MB）

```
┌──────────────┐
│  bootloader  │  启动引导程序
├──────────────┤
│  app (固件)   │  你的代码
├──────────────┤
│  nvs         │  存 WiFi 密码、配置等小数据
├──────────────┤
│  spiffs      │  文件系统（可选）
└──────────────┘
```

NVS 就像手机的**设置 App**（存账号密码），外部 Flash 像**硬盘**（存文件和系统）。

## 文件系统是独立分区

文件系统（SPIFFS/LittleFS）在 Flash 里是**独立分区**，不在 NVS 里：

```
# 分区表（partitions.csv）
# Name    Type   SubType  Offset   Size
nvs       data   nvs      0x9000   0x6000    ← 键值对
phy_init  data   phy      0xf000   0x1000
factory   app    factory  0x10000  0x1F0000  ← 固件代码
spiffs    data   spiffs   0x200000 0x200000  ← 文件系统（独立）
```

文件系统不是 ESP-IDF 自动建的，需要在分区表里手动加，代码里挂载才能用。

## NVS vs 文件系统存什么

| 用什么存 | 存什么 | 例子 |
|---------|--------|------|
| NVS | 小配置（几字节~几KB） | WiFi 密码、MQTT 地址、开关状态 |
| 文件系统 | 大文件（几KB~几MB） | 图片、音频、网页、日志、字体 |

NVS 就像手机的**设置页面**（存几个选项），文件系统就像手机的**相册/文件管理**（存文件）。

## 文件系统的作用

文件系统就是给存储空间**组织文件的方式**：

```
没有文件系统（裸 Flash）：
  只能按地址读写第几个字节，不知道第 5000 字节存的是什么

有文件系统（SPIFFS/LittleFS）：
/config.json    → {"wifi":"Ll","password":"123"}
/image.bin      → 图片数据
/log.txt        → "2026-06-24 温度28.5°C"
  按文件名读写，不用管底层地址
```
