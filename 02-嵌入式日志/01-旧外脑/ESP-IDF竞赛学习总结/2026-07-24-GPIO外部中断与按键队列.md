# 2026-07-24 · GPIO 外部中断与按键队列

## 概述

按键中断的核心：**ISR 只入队报信，任务里消抖并做业务**。  
“是哪个键”靠 **注册时绑脚** + **事件里带 pin**；不是糊成一个神秘中断再瞎猜。

## 核心概念

### 1. 全链路时间线

```text
手指按下
  → GPIO 从高到低（内部上拉 + 另一端接 GND）
  → 下降沿触发
  → Key_Isr_Handler：event.pin 入队（极短）
  → Key_Task 被唤醒
  → vTaskDelay(20ms) 消抖
  → 再读电平，仍为按下才做业务
```

### 2. 初始化顺序（必须背）

```text
① Key_Init / gpio_config
     输入 + 上拉，intr = DISABLE   ← 先配脚，中断先关
② gpio_set_intr_type(pin, NEGEDGE)
     只设定「何时触发」，不绑回调
③ xQueueCreate
     ISR → 任务的信箱
④ gpio_install_isr_service(0)
     全局 GPIO 中断服务（装一次）
⑤ gpio_isr_handler_add(pin, fn, arg)
     把「这根脚」和「回调」绑在一起
```

**为什么 ① 要传 `GPIO_INTR_DISABLE`？**

- 先把电气属性配安全，等队列和 handler 都就绪再开中断
- 避免「中断已开、处理函数还没挂」的窗口
- `Key_Init` 同时服务轮询模式，轮询不该开中断

### 3. 两个 API 别混

| API | 干什么 |
|-----|--------|
| `gpio_set_intr_type(pin, NEGEDGE)` | **何时** 触发（边沿/电平） |
| `gpio_isr_handler_add(pin, fn, arg)` | 触发后 **跑谁** |

### 4. “是哪个键？”两层机制

```text
层1  注册时绑定：gpio_isr_handler_add(哪根脚, 哪个函数, 可选参数)
层2  事件携带：  event.pin = 脚号（任务里用）
```

当前工程 **只有 1 个键**，ISR 里写死 `KEY_PIN`；`event.pin` 是为扩展预留的标签。

多键共用一个回调时：

```c
gpio_isr_handler_add(KEY1, Key_Isr, (void *)KEY1);
gpio_isr_handler_add(KEY2, Key_Isr, (void *)KEY2);

// ISR 内
event.pin = (gpio_num_t)(uintptr_t)argument;
```

也可以每脚各自一个回调。  
**不是**“硬件强制所有键进同一个中断，只靠 event 分辨”；  
**而是**“服务框架共享，回调按脚注册，可共用也可分开”。

### 5. ISR 规则

```c
static void IRAM_ATTR Key_Isr_Handler(void *argument)
{
    key_event_t event = { .pin = KEY_PIN };
    BaseType_t hp_woken = pdFALSE;
    xQueueSendFromISR(g_key_event_queue, &event, &hp_woken);
    portYIELD_FROM_ISR(hp_woken);
}
```

| 要做 | 不要做 |
|------|--------|
| `xQueueSendFromISR` | 普通 `xQueueSend` |
| 极短、无阻塞 | `vTaskDelay` / 复杂逻辑 / 大量日志 |
| `IRAM_ATTR`（Flash 忙时也能跑） | 在 ISR 里消抖 20ms |

`higher_priority_task_woken`：ISR 给调度器的提示——是否唤醒了更高优先级任务；为真时 `portYIELD_FROM_ISR` 请求退出中断后立刻切换。  
**不是**中断直接指定下一个任务。

### 6. 任务侧消抖

```c
Key_GetEvent(&event, portMAX_DELAY);  // 阻塞等
vTaskDelay(pdMS_TO_TICKS(20));
Key_IsPressed(&pressed);              // 再读确认
// pressed 为真才做业务
```

ISR 说“可能按下”；任务说“确认按下”。

### 7. 轮询 vs 中断

| | 轮询 | 中断 |
|--|------|------|
| 初始化 | `Key_Init` | `Key_Interrupt_Init` |
| 取结果 | `Key_Scan` | `Key_GetEvent` |
| 没按键时 | 任务仍在扫 | 任务睡觉 |
| 同一键 | **不要两套同时用** | |

## 与 STM32 HAL 对照（今天重点理清）

| 点 | STM32 HAL | ESP-IDF |
|----|-----------|---------|
| 多键一个回调 | ✅ `HAL_GPIO_EXTI_Callback(GPIO_Pin)` | ✅ 同一 `Key_Isr` + `arg`/`event.pin` |
| 必须每键一个回调？ | 否 | 否 |
| 硬件模型 | EXTI 线共享、部分 NVIC 入口共享 | 按脚注册 handler，服务层分发 |
| 标志位 | 挂起位要清（HAL 常代劳；共享 IRQ 要查是谁） | 驱动代劳，应用几乎不碰 |
| 典型业务放置 | 回调置标志 / 主循环处理 | ISR 入队 / 任务处理 |

**结论心智：**

> 两边都能一个回调服务多键。  
> STM32 多的是 EXTI 线冲突 + 挂起标志；  
> IDF 把分发和清标志藏进驱动，体感是「直接绑脚和回调」。

竞赛场景用 IDF 即可；迁移能力看的是共同模型：

```text
配脚 → 设触发条件 → 挂处理 → ISR 极短 → 主上下文做业务
```

## 实践要点（复习口诀）

1. **先 init 硬件，后 enable 中断**
2. **`set_intr_type` 管边沿，`isr_handler_add` 管回调**
3. **ISR 只入队；消抖和业务在任务**
4. **单键：注册绑脚；多键：arg 或 event.pin**
5. **轮询 / 中断二选一，别叠用**

## API 速查

| API | 作用 |
|-----|------|
| `gpio_set_intr_type` | 设置触发类型 |
| `gpio_install_isr_service` | 安装全局 GPIO ISR 服务 |
| `gpio_isr_handler_add` | 引脚 ↔ 回调 |
| `xQueueCreate` | 创建队列 |
| `xQueueSendFromISR` | ISR 安全入队 |
| `xQueueReceive` | 任务取事件 |
| `portYIELD_FROM_ISR` | 必要时请求切换 |
| `portMAX_DELAY` | 永久等待 |
| `IRAM_ATTR` | ISR 放内部 RAM |
