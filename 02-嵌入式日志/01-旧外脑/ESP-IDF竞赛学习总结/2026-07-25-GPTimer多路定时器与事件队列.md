# 2026-07-25 · GPTimer 多路定时器与事件队列

## 概述

竞赛 BSP 的硬件定时器做成 **STM32 选 TIMx 风格**：`TIMER_ID_0..3` 共 4 路（ESP32-S3 = 2 组 × 2 个 GPTimer）。  
核心：**ISR 只入队带 id 的事件，业务在 `Timer_Task` 里 `switch(event.id)` 做状态机**。

工程：`E:\MCU\esp32\ESP_BSP_IN_QIANSAI\demo`  
文件：`main/hardware/hal_timer.c` / `hal_timer.h`

## 核心概念

### 1. 和 STM32 的对应

| STM32 习惯 | 本库 |
|------------|------|
| 选 `htim2` / `htim3` | `TIMER_ID_0` .. `TIMER_ID_3` |
| `HAL_TIM_Base_Start` | `Timer_Start_Periodic_Ms(id, ms)` |
| 回调里 `if (htim->Instance == TIM2)` | 任务里 `switch (event.id)` |
| 置 flag，主循环处理 | 队列事件，`Timer_GetEvent` 阻塞取 |
| 10µs 基 tick + 全局累加多路软延时 | **不采用**（现场太重） |

现场策略：

- 日常节奏：优先 `vTaskDelay`
- 题目点名硬件定时器：用本库 GPTimer
- 要两路周期：直接 Start 两个 id，或 1 硬件 + 1 软定时/`vTaskDelay`

### 2. 全链路

```text
Timer_Init()
  建共享队列
  for id=0..3:
    gptimer_new_timer
    注册同一回调 Timer_Isr_Handler，user_ctx=id
    gptimer_enable          ← 可用，但还没计数
    软件状态清零

Timer_Start_Periodic_Ms(id, ms) / OneShot
  检查 → 若在跑先 stop
  记 period_ms / oneshot
  set_alarm_action(ms*1000, auto_reload=!oneshot)
  set_raw_count(0)
  start → running=true

硬件到点
  → 统一 ISR：认 id →（单次则 stop）→ 入队 {id,count_us,period_ms}
  → Timer_Task：GetEvent → switch(id) 业务/状态机
```

### 3. 为什么 `period_ms * 1000`

```c
#define TIMER_RESOLUTION_HZ 1000000  // 1MHz → 1 tick = 1µs
alarm_count = period_ms * 1000ULL;   // 1ms = 1000µs = 1000 ticks
```

`ULL` 防止大周期乘法溢出。  
**不是 \*100**（会少 10 倍）。

### 4. 周期 vs 单次

| | 周期 | 单次 |
|--|------|------|
| `oneshot` | false | true |
| `auto_reload` | true | false |
| 到点后 | 硬件重装继续 | ISR 里 `gptimer_stop` + `running=false` |
| 再用 | 一直跑 | 再调 Start |

### 5. 4 路为何一个回调还能区分

```c
// Init 时
gptimer_register_event_callbacks(handle, &cb, (void *)(uintptr_t)i);

// ISR 里
const timer_id_t id = (timer_id_t)(uintptr_t)user_ctx;
```

- **回调函数可以相同**
- **user_ctx 不同** → 知道是哪路
- 业务不在 ISR 的 `if (timer==)` 里写长逻辑，而在任务 `switch(id)`

### 6. 输出参数 + 队列（最易混）

```c
timer_event_t event;                    // 任务栈上的空盒子
Timer_GetEvent(&event, portMAX_DELAY);  // 把地址给库
// 返回后 event 才有内容，任务直接用
```

| 对象 | 角色 |
|------|------|
| 你的 `event` | 输出缓冲区（结果往哪写） |
| `g_timer_event_queue` | ISR↔任务中转站（Init 时创建） |
| ISR `SendFromISR` | 往队列**放** |
| 任务 `Receive` | 从队列**取**，拷进你的 `event` |

方向：

```text
不是：把 event 塞进队列
而是：队列里已有 ISR 的消息 → 拷贝进 event
```

`if (event == NULL)`：防止空指针写入崩溃（防御性）。

类比按键库、STM32 flag：

```text
STM32: ISR 置 flag → 主循环轮询
ESP:   ISR 入队    → 任务阻塞取事件（还能带数据）
```

### 7. Init / enable / start / Stop / Deinit

| API | 含义 |
|-----|------|
| `gptimer_enable` | 模块可用（Init） |
| `gptimer_start` | 真正开始数（Start） |
| `Timer_Stop(id)` | 停一路，句柄保留，可再 Start |
| `Timer_Deinit_All` | **仅 Init 失败回滚**，销毁全部+队列 |

失败不会自动再 Init；`ESP_ERROR_CHECK` 会直接暴露问题方便排查。  
一直跑周期定时器时 `Stop` 少用；切模式/暂停时才用。

### 8. 内部数据结构

```c
typedef struct {
    gptimer_handle_t handle;
    uint32_t period_ms;
    bool oneshot;
    bool running;
} timer_slot_t;

static timer_slot_t g_timers[TIMER_ID_COUNT]; // 4 槽
static QueueHandle_t g_timer_event_queue;     // 共享 1 队列
```

```text
g_timers[0..3] 各自硬件
       ↓ 到点
   同一 queue（事件带 id）
       ↓
   Timer_Task 按 id 分流
```

## 实践要点（竞赛）

### 最小用法

```c
Timer_Init();
Timer_Start_Periodic_Ms(TIMER_ID_0, 500);
Timer_Start_Periodic_Ms(TIMER_ID_1, 200);

// Timer_Task
timer_event_t e;
while (1) {
    if (Timer_GetEvent(&e, portMAX_DELAY) != ESP_OK) continue;
    switch (e.id) {
    case TIMER_ID_0: /* 状态机 A */ break;
    case TIMER_ID_1: /* 状态机 B */ break;
    default: break;
    }
}
```

### 现场决策

| 题目需要 | 做法 |
|----------|------|
| 一个周期闪灯 | `TIMER_ID_0` 即可 |
| 两个不同周期 | Start 两路 id，Task 里 switch |
| 未点名硬件定时器 | `vTaskDelay` 更简单 |
| 不要 10µs 全局累加框架 | 调试贵、中断密 |

### 自检清单

1. Init 完在不在计数？→ **不在**，要 Start  
2. 为何 `*1000`？→ 1MHz 下 ms→tick  
3. 4 路怎么区分？→ `user_ctx` / `event.id`  
4. 业务写哪？→ **Task**，不是 ISR  
5. Stop vs Deinit？→ 暂停可再用 vs 失败销毁  
6. 单次谁停表？→ **ISR**

## 与按键库同构

```text

```

都是：**中断报信，任务干活**。
