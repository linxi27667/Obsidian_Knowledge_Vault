# MAC 地址全球唯一机制

## 格式

MAC 地址 48 位（6 字节）：

```
AA:BB:CC:DD:EE:FF
│       │
│       └── 设备序列号（后 3 字节，厂商分配）
└── 厂商编号（前 3 字节，IEEE 分配）
```

## 为什么不重复

| 部分 | 谁管 | 数量 |
|------|------|------|
| 前 3 字节（OUI） | IEEE 分配给厂商 | 全球每家厂商不同 |
| 后 3 字节 | 厂商自己分配 | 2^24 = 1677 万个，够用 |

**分级管理**：IEEE 管厂商编号不冲突，厂商管自家产品编号不冲突，合起来全球唯一。

## 烧录过程

1. Espressif 向 IEEE 购买 OUI 编号（如 `24:6F:28`）
2. 芯片生产时将 MAC 写入 **eFuse**（一次性熔丝）
3. eFuse 是硬件只读存储，写进去改不了
4. 工厂管理系统保证每个芯片序列号不重复

## ESP32 读取 MAC

```c
uint8_t mac[6];
esp_efuse_mac_get_default(mac);   // 从芯片 eFuse 读出厂 MAC
```

MAC 不是固件里写死的，是芯片出厂时烧在硬件里的，代码运行时去读它。

## 在项目中的用途

| 用途 | 代码 | 作用 |
|------|------|------|
| MQTT Client ID | `"xiaozhi_slave_<MAC>"` | 区分不同从设备，避免踢下线 |
| MQTT Topic 后缀 | `"xiaozhi/iot/heartbeat/<MAC>"` | Master 从 topic 知道是谁发的 |
