# 嵌入式项目管理详解

## 核心概念

- **需求分析** - 功能/非功能需求
- **架构设计** - 系统分层、模块划分
- **风险管理** - 技术/进度风险
- **质量管理** - 评审、测试、度量

## 一、需求分析

### 1.1 需求分类

```c
// 需求分类
typedef enum {
    REQ_FUNCTIONAL,      // 功能需求
    REQ_PERFORMANCE,     // 性能需求
    REQ_RELIABILITY,     // 可靠性需求
    REQ_SAFETY,          // 安全需求
    REQ_SECURITY,        // 安全性需求
    REQ_USABILITY,       // 易用性需求
    REQ_INTERFACE,       // 接口需求
    REQ_CONSTRAINT,      // 约束条件
} req_type_t;

// 需求条目
typedef struct {
    char id[16];          // 需求ID
    req_type_t type;      // 类型
    char description[256];// 描述
    char priority[8];     // 优先级(P0/P1/P2)
    char source[64];      // 来源
    char verification[64];// 验证方法
    bool traced;          // 是否可追溯
} requirement_t;

// 需求追踪矩阵
typedef struct {
    char req_id[16];
    char design_id[16];
    char code_file[64];
    char test_case[32];
} trace_matrix_t;
```

## 三、风险管理

### 3.1 风险评估

```c
// 风险矩阵
typedef struct {
    char id[16];
    char description[128];
    int probability;    // 1-5(概率)
    int impact;         // 1-5(影响)
    int risk_level;     // probability × impact
    char mitigation[128]; // 缓解措施
    char owner[32];     // 负责人
    char status[16];    // 状态
} risk_t;

// 风险等级计算
int calc_risk_level(int probability, int impact) {
    return probability * impact;
}

// 风险分类
/*
 * 高风险(15-25): 需立即处理
 * 中风险(8-14):  需关注并制定计划
 * 低风险(1-7):   可接受或监控
 */

// 常见嵌入式风险
risk_t common_risks[] = {
    {"R001", "芯片缺货导致延期", 4, 5, 0, "备选芯片评估", "硬件", "Open"},
    {"R002", "实时性不满足要求", 3, 4, 0, "性能测试提前", "软件", "Open"},
    {"R003", "EMC测试不通过", 3, 5, 0, "预测试、屏蔽设计", "硬件", "Open"},
    {"R004", "功耗超标", 3, 3, 0, "功耗分析、优化方案", "软件", "Open"},
    {"R005", "第三方库bug", 2, 4, 0, "充分测试、备选方案", "软件", "Open"},
};
```

### 5.2 缺陷管理

```c
// 缺陷分类
typedef enum {
    BUG_CRITICAL,    // 致命(系统崩溃、数据丢失)
    BUG_MAJOR,       // 严重(功能不可用)
    BUG_MINOR,       // 一般(功能部分可用)
    BUG_TRIVIAL,     // 轻微(界面/提示问题)
} bug_severity_t;

typedef enum {
    BUG_OPEN,
    BUG_IN_PROGRESS,
    BUG_RESOLVED,
    BUG_CLOSED,
    BUG_REOPENED,
} bug_status_t;

typedef struct {
    char id[16];
    bug_severity_t severity;
    bug_status_t status;
    char title[128];
    char description[512];
    char steps[256];
    char assignee[32];
    char reporter[32];
    char date[16];
    char resolution[128];
} bug_t;

// 缺陷度量
typedef struct {
    int total_bugs;
    int open_bugs;
    int critical_bugs;
    float bug_density;  // bugs/KLOC
    float fix_rate;     // 修复率
} bug_metrics_t;
```

## 六、配置管理

### 6.1 版本号规范

```
语义化版本: MAJOR.MINOR.PATCH

MAJOR: 不兼容的API变更
MINOR: 向后兼容的功能新增
PATCH: 向后兼容的Bug修复

示例: v1.2.3
- 1: 主版本号(大版本升级)
- 2: 次版本号(新功能)
- 3: 修订号(Bug修复)

预发布版本: v1.2.3-rc.1
构建元数据: v1.2.3+build.456
```

### 6.2 分支策略

```
main ─────────────────────────────────→
  │                                    ↑
  ├── develop ─────────────────────→ merge
  │     │
  │     ├── feature/xxx ─────→ PR
  │     ├── feature/yyy ─────→ PR
  │     │
  │     ├── release/1.0 ─────→ tag
  │     │     │
  │     │     ├── hotfix/xxx → PR
  │     │
  │     └── bugfix/xxx ─────→ PR

分支说明:
- main: 生产版本
- develop: 开发主线
- feature/*: 功能分支
- release/*: 发布分支
- hotfix/*: 紧急修复
- bugfix/*: Bug修复
```
