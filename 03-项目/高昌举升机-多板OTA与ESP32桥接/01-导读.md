# 高昌多板 OTA 与 ESP32 桥接导读

## 核心概念

- ==这是举升机产品线的「板卡演进 + 升级能力」仓库，不是 Gc_Iot_Lift 的简单重复==。  
- ==OTA 两段式：APP 收包落盘 → Bootloader 校验刷写/回滚==。  
- ==ESP32 支线解决无线桥接/升级通道，不替代 STM32 安全控制==。  

## 一、和 Gc_Iot_Lift 怎么分工写简历

| 仓库 | 简历侧重点 |
|---|---|
| `Gc_Iot_Lift` | 四机型状态机、本地安全、4G MQTT 管理闭环 |
| `GcMultiLinkLift` | 多硬件版本共存、Bootloader/OTA、ESP32 通信桥、外部 Flash 暂存固件 |

可写成**同一工作项目下的两个模块**，不要拆成两个无关项目硬凑。

## 二、仓库地图

```text
GcMultiLinkLift/
├─ stm407_lifter_reconsitution_*     较早重构主控
├─ stm407_lifter_newBoard_*          新板 5.5/8.0/TPFI
├─ stm407_lifter_newBoard_8.0MC_ESP32  新板 + ESP32
├─ newBoard_OTA_APP/
│  ├─ newBoard_Boot                  Bootloader
│  └─ *_OTA                          业务 APP OTA 版
└─ ESP32_Proj                        无线桥接侧
```

## 三、系统在升级时做什么

```text
运行中 APP
→ 经通信通道收固件包
→ 写入外部 Flash（W25Q 等）并置升级标志
→ 复位
→ Bootloader：校验 → 编程内部 Flash → 成功跳转 / 失败回滚
```

关键关注文件（计划文档点名）：

- `newBoard_Boot/.../boot_ota.c`
- `newBoard_Boot/.../ota_aes.c`（若启用加密）
- APP 侧 `ota_task.c`、`disk_task.c`
