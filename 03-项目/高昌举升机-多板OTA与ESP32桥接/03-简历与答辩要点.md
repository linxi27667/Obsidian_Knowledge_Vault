# 简历与答辩要点

## 一、建议写法：并入「高昌举升机」一条

**高昌汽车举升设备控制系统（实时控制 / 物联网 / OTA）**

- 基于 STM32F407 + FreeRTOS 实现多机型举升安全控制与动作时序（详见 Gc_Iot_Lift 知识库）。  
- 参与/负责多板卡固件矩阵维护，完成 **Bootloader + 外部 Flash 暂存的两段式 OTA**（收包—校验—刷写—失败回滚）。  
- 推进 ESP32 无线桥接版本，将调试/升级通道与实时安全控制解耦。  

若 OTA 是你深度主导，可单列子条 2～3 行；否则不要从举升机拆成两个一级项目。

## 二、OTA 30 秒口播

> 我们采用 APP 与 Bootloader 分工：运行中的 APP 负责接收固件并写入外部 Flash、置位升级标志；复位后 Bootloader 负责校验并编程内部 Flash，失败则不跳转到坏镜像。这样把“传输”和“刷写”隔离，掉电和错包时更不容易变砖。

## 三、高频追问

| 问 | 答 |
|---|---|
| 为什么不在 APP 里直接刷自身？ | 刷写自身映射区风险高；Boot 常驻更可控 |
| 掉电怎么办？ | 校验+标志+保留旧镜像/回滚 |
| 和 4G DTU 项目什么关系？ | 同一产品线不同阶段/通道：管理网 vs 现场无线/升级 |
| 如何防错误包？ | CRC/长度/版本号；可选 AES |
