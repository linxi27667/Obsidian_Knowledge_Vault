# 技术栈与架构

## 一、技术栈

| 层 | 技术 | 作用 |
|---|---|---|
| 主机 MCU | ESP32-S3 + ESP-IDF | 小智语音、MCP、MQTT 控制器 |
| 从机 MCU | ESP32-S3 + ESP-IDF | GPIO/ADC/LEDC/RMT、自动逻辑 |
| AI | 小智云 + MCP `self.garden.*` | 自然语言 → 结构化工具 |
| 通信 | MQTT Broker `8.134.167.240:1883` / WS `:9001` | 主从/App/Web 总线 |
| 灯光 | WS2812 RMT（氛围灯）+ GPIO 灯 | 场景灯效 |
| 传感 | 土壤 ADC、雨滴 ADC、DHT11、火焰、求助键 | 自动与告警 |
| Web | mqtt.js / WebSocket 面板 | 调试与演示 |
| App | Kotlin、Compose、Filament/SceneView | 3D 数字孪生 |
| 持久化 | NVS（能耗累计、自动开关） | 掉电保持 |

## 二、主机分层

```text
main/
├─ application.* / mcp_server.* / protocols/   # 小智主框架
├─ boards/custom-esp32s3-cam/
│  └─ garden_mcp_tool.cpp                     # self.garden.* 工具注册
├─ APP/  app_garden / iot_controller
└─ BSP/  bsp_garden / bsp_iot_controller
```

## 三、从机分层

```text
slave/gardenslave/main/
├─ APP/
│  ├─ mqtt_receive / mqtt_heartbeat
│  ├─ iot_control_task
│  └─ sensor_adc_task
└─ BSP/  GPIO、ADC、舵机、Wi-Fi
```

Flag-driven：MQTT 回调更新期望状态，控制任务周期刷新硬件（与楼宇从机同构）。

## 四、从机硬件映射（README 事实）

| GPIO | 功能 |
|---|---|
| 11 / 12 / 13 | 西庭灯 / 灯带逻辑 / 长廊灯 |
| 14 / 15 / 16 | 风扇 / 水泵 / 雾化器 |
| 17 | **安防总闸**（高=供电，低=火灾切断） |
| 18 | 遮雨棚/晾衣架舵机 |
| 2 | 火焰（中断） |
| 48 | 求助按钮（中断） |
| 38 | DHT11 |
| 1 / 4 | 土壤 ADC / 雨滴 ADC |
| 21 | ASR UART TX |

> 注：WS2812 氛围在完整功能表中为 RMT 驱动；以从机当前编译配置与 README 交叉核对现场接线。

## 六、Android 架构（孪生 App）

```text

├─ mqtt/          订阅状态、能耗、chat
├─ data/model|repository
├─ filament/      SceneviewGardenModel 加载 garden.glb
```

3D 模型：`assets/models/garden.glb`（Blender 从 124 STL 装配）。

## 七、架构原则

1. 安全决策优先在从机本地（火灾切总闸不等云端）。  
2. 主机负责语义与播报，从机负责 IO 与阈值熔断。  
3. App/Web 只做展示与便捷控制，不断言“毫秒级安全”。  
4. 能耗为软件积分，部署时需声明非计量电表。
