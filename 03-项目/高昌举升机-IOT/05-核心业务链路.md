# Gc_Iot_Lift 核心业务链路（从物理输入到远程回执）

## 核心概念

- ==先看链路，再看函数==，能够避免陷入单个文件。
- 所有运动链路最终都应经过本地安全判断。
- 远程命令完成的标准不是“MQTT 发布成功”，而是收到匹配的设备回执。

## 一、上电启动链路

```text
复位
→ HAL_Init / SystemClock_Config (168MHz)
→ GPIO、DMA、SPI、USART 初始化
→ RTT + EasyLogger
→ App_W25Qxx_System_Init（恢复配置/统计）
→ LiftLock / LiftIot / App_IO_Map / LiftCore(或 App_LiftCore)
→ MX_FREERTOS_Init
→ 创建 Lift_Task（或 defaultTask）、TasDtu_Task
→ osKernelStart
→ 周期控制与联网并发运行
```

入口：`*/Core/Src/main.c`、`*/Core/Src/freertos.c`

## 二、本地上升链路

```text
上升按钮
→ app_io_map：有效电平归一化 + 20ms 去抖
→ Lift_Task 周期 Poll
→ lift_core / 产品状态机：急停/锁定/光电/上限位检查
→ App_IO_Write(MOTOR, 1) [+ 阀组按机型]
→ 按钮释放或限位 → App_IO_All_Off()
```

推荐追踪（大剪）：

1. `APP/Src/app_io_map.c`
2. `Driver/Src/dri_lift.c`
3. `APP/Src/lift_core.c`
4. `APP/Src/lift_large_scissor.c`

## 三、下降时序链路

下降不是“直接打开下降阀”，而是为机械解锁和液压动作安排时序。

| 机型 | 下降时序摘要 |
|---|---|
| 大剪 | 200ms 开气阀 → hold 2500/1500ms → 关电机开下降阀 |
| 小剪 | DOWN_PREPARE 200ms → HOLD 2500ms → DROPPING |
| 超薄 | 同小剪类；下限位时 AIR=0 仅 DROP（防反挺） |
| 两柱 | t=0 电机 → t≥200 电磁铁 → t≥2000 关电机开下降阀 |

两柱源码常量：

```c
DP_ELECTROMAGNET_DELAY_MS = 200
DP_MOTOR_HOLD_TOTAL_MS    = 2000
```

这种写法使用 Tick 差值，不阻塞任务，因此每个周期仍能响应急停。

## 四、急停链路

```text
急停触发（PE2 低有效，20ms 去抖）
→ 公共安全层优先检测
→ 状态切换 ESTOP
→ App_IO_All_Off
→ 统计急停次数、写操作日志
→ 标记 IoT 事件
→ DTU 任务在最小上报间隔满足后上传
```

急停的本地断输出不等待网络，也不等待 W25Qxx 写完。

## 五、光电报警链路

- 大剪/小剪/超薄有 PE8 光电；**两柱无光电**。
- 光电触发时先停机。
- 运动中触发通常要求远程清报警。
- 某些机型在下限位触发时屏蔽光电（车辆落地遮挡可能是正常工况）。

## 六、远程锁机闭环

```text
浏览器 POST 锁机
→ Node.js 权限校验并创建 msg_id
→ MQTT 发布到 {uid}/down，QoS1
→ TAS DTU 透传 USART3
→ STM32 App_TasDtu_HandleJsonCommand
→ UID/命令/msg_id 去重
→ LiftIot_SetLocked → LiftCore_SetRemoteLock + All_Off
→ command_response 上行 {uid}/up
→ Web 匹配 uid+cmd+msg_id → 命令终态 succeeded
→ WebSocket 推浏览器
```

## 七、遥测上报链路

`Lift_Task` 更新状态和事件，`TasDtu_Task` 决定何时发送：

- 事件优先，仍受最小间隔限制
- 静止约 5 s 一包，运动约 1 s
- DTU 未进入透明可用状态时跳过或重试，不能阻塞控制

## 八、保养与举升计数链路

```text
状态机进入有效上升
→ App_RiseCounter_Poll 累积时间（3s 折算）
→ 入队 / journal
→ W25Qxx 持久化
→ DTU 在线后上报
→ Web 写入保养与运行记录
```

两柱有独立 RiseStore 任务异步写 Flash，避免阻塞 10 ms 控制。

## 九、现场讲解模板

> 我会用三条链路解释系统：第一条是按钮到执行器的本地实时控制；第二条是急停和光电到全输出关闭的安全链路；第三条是 Web 命令通过 MQTT、TAS DTU 和 USART3 到达 STM32，再由 `command_response` 返回确认的管理闭环。
