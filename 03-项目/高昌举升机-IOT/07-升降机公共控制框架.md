# 升降机公共控制框架（稳定骨架承载不同产品状态机）

## 核心概念

- ==公共层处理共同安全和管理能力==。
- ==产品层只实现机械动作差异==。
- ==所有输出必须可被一个统一的 All-Off 路径立即关闭==。

## 一、公共状态

```c
typedef enum {
    LIFT_STATE_IDLE = 0,
    LIFT_STATE_RISING = 1,
    LIFT_STATE_DROPPING = 2,
    LIFT_STATE_LOCKED = 3,
    LIFT_STATE_REFILLING = 4,
    LIFT_STATE_ESTOP = 5,
    LIFT_STATE_PHOTO_ALARM = 6
} lift_state_t;
```

来源：`GC_Big_Scissor/APP/Inc/lift_core.h`

公共状态用于遥测、LED 和跨机型管理；产品内部可以再定义更细的子状态。

## 二、产品操作接口

`lift_ops_t` 是产品插件接口。`LiftCore_Init()` 根据 `g_product_type` 选择实现：

| 回调 | 含义 |
|---|---|
| `init` | 产品状态和输出初始化 |
| `on_estop` | 急停时清理产品子状态 |
| `on_photoelectric_blocked` | 光电报警时清理产品状态 |
| `on_clear_alarm` | 清报警后恢复产品内部状态 |
| `poll` | 周期推进产品状态机 |

| 工程 | Init 选择 |
|---|---|
| Big | 仅 `large_scissor_ops` |
| Thin | `thin_scissor_ops` |
| Two_Pillars | `DOUBLE_POST→double_post_ops` |
| Small | **不使用 lift_ops**，走 `app_lift_core` |

## 三、LiftCore_Poll 的安全顺序

```text
1. 急停
   - 触发：ESTOP, App_IO_All_Off, stats++, ops->on_estop,
           OpLog OP_ESTOP, LiftIot_NotifyEstop
   - 释放：ESTOP → IDLE
2. 光电与下限位屏蔽规则
   - 大剪主机：下限位触发可 skip 光电
   - 运动中触发 → s_photo_alarm_requires_remote_clear = 1
3. 远程锁定
   - s_remote_locked → 跳过 ops->poll（输出已在 SetRemoteLock 时 All_Off）
4. 产品 poll
```

来源：`GC_Big_Scissor/APP/Src/lift_core.c`

## 四、IO 抽象

`app_io_map` 把逻辑名称和物理 GPIO 解耦：

```c
App_IO_Read(IO_IN_UP_BUTTON);
App_IO_Write(IO_OUT_MOTOR, 1U);
App_IO_All_Off();
```

输入处理：物理读取 → 有效电平归一化 → 去抖 → 稳定值缓存。  
输出处理：逻辑值转物理电平 → 输出影子值 → 统一全关。

### 四机型输入输出速查

| 逻辑 | 大剪 | 小剪 | 超薄 | 两柱 |
|---|---|---|---|---|
| UP | PG15 low | PG15 low | PG15 low | PG15 low |
| DOWN | PE0 low | PE0 low | PE0 low | PE0 low |
| LOCK | PE1 low | PE1 low | PE1 low | PE1 low |
| ESTOP | PE2 low | PE2 low | PE2 low | PE2 low |
| UPPER | PE5 high | PE5 high | PE5 high | PE5 high |
| LOWER | PE6 high | PE6 high | PE6 high | **无** |
| REFILL | PE3 low | PE3 low | PE3 low | **无** |
| PHOTO | PE8 high 50ms | PE8 high 50ms | PE8 high 50ms | **NULL** |
| ROTARY | PE12 high 50ms | 无 | 无 | 无 |
| MOTOR | PF8 | PF8 | PF8 | PF8 |
| DROP | **PF9** | **PD9** | **PD9** | **PD8** |
| AIR/MAG | PD8/PD10 | PD8 | PD8 | **PF9 电磁铁** |
| WORK | PD9/PD11 | 无 | 无 | 无 |

普通按钮/限位去抖 20 ms；光电/旋转开关 50 ms。

## 五、小剪的输出仲裁

小剪集中式核心比公共 `lift_ops` 更强调纯计算：

```text
状态机生成“期望输出”
→ lift_output_arbitrate()
→ safety_guard_before_output()
→ app_lift_apply_outputs()
```

硬规则：`motor_req && down_valve_req` 永远非法。这能防止某个状态分支漏关电机。

## 六、IoT 状态与控制状态分离

`lift_iot.c` 负责：

- 远程锁定和解锁（→ `LiftCore_SetRemoteLock`）
- 管理员模式（密码 `123456`）
- 清报警/清故障
- 状态快照与 telemetry JSON
- 运动统计和事件标记

它不应直接编写某个机型的下降时序。

设备身份示例（大剪）：

```text
LIFT_IOT_DEVICE_ID    "gaochang_lift_f407zet6"
LIFT_IOT_DEVICE_NAME  "Gaochang-LargeScissor-F407-01"
LIFT_IOT_DEVICE_MODEL "GC-F407-LSCISSOR"
```

telemetry 关键字段：`state, motor, drop_valve, valves, counts, locked, admin_mode, dtu.state, dtu.csq, chip_uid, product_type, seq, tick, uptime_ms`

## 七、W25Qxx 持久化

### 地址布局（大剪 `app_w25qxx.h`）

| 区 | 地址 |
|---|---|
| Slot A/B | 0x0000 / 0x1000 |
| Config A/B | 0x2000 / 0x3000 |
| Stats A/B | 0x4000 / 0x5000 |
| OpLog | 0x6000，4KB，256 条 ×16B |
| RiseQueue | 0x8000，16×4KB |
| Maintenance | 0x20000，4×4KB |

### 主要数据

| 数据 | 用途 |
|---|---|
| 配置 | 延时、阈值、模块开关、设备信息 |
| 统计 | 上升、下降、急停、锁定、补油次数 |
| 操作日志 | 追踪动作开始、停止和异常 |
| 保养账本 | 总举升次数、周期次数、保养完成 |
| 离线队列 | 网络恢复后补传 |

### rise_counter

- 大剪：`APP_RISE_COUNTER_INTERVAL_MS = 3000`，仅 RISING 累计；RAM 队列 8；Flash magic `0x55504351`
- 两柱：独立 Store 任务 384w；journal magic `0x52495345`；保养阈值 5000 次

## 八、代码阅读问题

读每个控制函数时都问：

1. 哪个输入使它进入？
2. 进入时打开了哪些输出？
3. 哪些条件可以退出？
4. 急停、远程锁定和非法组合能否覆盖它？
5. 状态和输出是否同步？
6. 是否写日志、统计和 IoT 事件？
