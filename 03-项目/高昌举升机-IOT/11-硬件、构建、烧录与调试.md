# 硬件、构建、烧录与调试（从接线到三段证据）

## 核心概念

- ==接线先区分输入有效电平与输出驱动电平==。
- ==烧录和构建以每个机型自己的 Keil 工程为单位==。
- ==调试先证明链路在哪一段断开，再修改代码==。

## 一、硬件总览

| 模块 | 接口 | 作用 |
|---|---|---|
| STM32F407ZET6 | 主控 | 状态机和安全控制，168 MHz |
| 按钮/限位/光电 | GPIO 输入 | 操作和安全条件 |
| 继电器/阀/电磁铁 | GPIO 输出 | 执行机构 |
| TAS 4G DTU | USART3 PB10/PB11 | MQTT 联网 |
| W25Qxx | SPI | 配置、统计和日志 |
| J-Link | SWD + RTT | 烧录和日志 |
| LED_RUN/COM/POWER | PG2/3/4 低亮 | 运行与通信指示（小剪等） |

## 三、构建

每种机型是独立 Keil 工程：

```text
GC_Big_Scissor/MDK-ARM/GC_Big_Scissor.uvprojx
GC_Small_Scissor/MDK-ARM/GC_Small_Scissor.uvprojx
GC_Thin_Scissor/MDK-ARM/GC_Thin_Scissor.uvprojx
GC-Two_Pillars/MDK-ARM/*.uvprojx
```

仓库内有 `build_keil.bat`、`flash_keil.bat` 或 J-Link 脚本时优先使用。不要把另一机型的 hex 烧到当前设备。

## 四、烧录前检查

- [ ] 机型和工程一致
- [ ] GPIO 映射和接线一致（特别注意下降阀 PF9 vs PD9 vs PD8）
- [ ] 输出默认全部关闭
- [ ] 急停实际有效（低有效 NC）
- [ ] TAS DTU 串口波特率 9600 优先
- [ ] Broker、主题和设备 UID 正确
- [ ] W25Qxx 型号与容量配置正确

## 五、RTT 日志标签

| 标签 | 看什么 |
|---|---|
| `SYS/RTOS` | 任务创建、堆、栈溢出 |
| `IOMAP` | 启动输入快照、输入变化、GPIO 映射 |
| `LIFT/CORE/THIN/DP` | 状态转换和动作时序 |
| `SAFETY` | 急停、光电、冲突输入 |
| `DTU` | AT、MQTT、重连、收发 |
| `IOT` | 远程锁定、清报警、保养命令 |
| `W25Q/RISE` | 存储、恢复和计数 |

高频控制循环中不要无条件打印大量日志。

## 六、故障定位矩阵

| 现象 | 第一检查点 | 下一步 |
|---|---|---|
| 按键无反应 | IOMAP 输入变化 | 有输入再查状态机，无输入查接线/有效电平 |
| 状态变化但继电器不动 | 输出影子值和 GPIO | 查驱动级、电源、端子 |
| 急停不生效 | 急停物理电平和去抖 | 查 NC/NO 接线和映射 |
| DTU 无响应 | USART3 RX/TX、波特率 | 查 `+++` 握手和 AT 响应 |
| MQTT 在线但命令不到 MCU | down 主题和订阅 | 查 UID、DTU 透传和 RX FIFO |
| MCU 收到命令但 Web 超时 | command_response | 查上行主题、msg_id、发送缓冲 |
| 重启后配置丢失 | W25Qxx 初始化/CRC | 查 SPI、地址、写入提交 |
| 随机 HardFault | 栈水位和数组边界 | 查 DTU JSON 栈、DMA 缓冲 |

## 七、测试顺序

1. 空载：所有输出默认关闭
2. 单输入：逐个验证按钮、限位、急停和光电
3. 单动作：验证上升、下降、锁定、补油的输出时序
4. 冲突：上升+下降、运动中急停、运动中远程锁定
5. 断网：验证本地控制和停机不受影响
6. 重连：验证遥测恢复和离线数据补传
7. 重复命令：同一 `msg_id` 不应重复执行
