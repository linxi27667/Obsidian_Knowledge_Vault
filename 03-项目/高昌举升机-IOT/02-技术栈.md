# Gc_Iot_Lift 技术栈（每项技术都对应一个工程问题）

## 核心概念

- ==STM32F407==：实时控制主体。
- ==FreeRTOS==：把控制循环、DTU 通信和存储任务隔离调度。
- ==TAS-LTE-892D_s4==：完成 4G 联网和 MQTT 连接，STM32 通过 AT 指令配置它。
- ==MQTT v1==：设备与管理平台的数据通道。
- ==Node.js 管理平台==：设备管理、远程命令、告警、保养和日志展示。

## 一、嵌入式技术栈

| 技术 | 项目中的作用 | 关键目录/文件 |

| SPI + W25Qxx | 配置、统计、操作日志、保养数据 | `*/APP/Src/app_w25qxx.c` |

## 二、通信技术栈

| 技术 | 作用 | 设计重点 |
|---|---|---|
| TAS 4G DTU | 蜂窝网络接入和 MQTT 客户端 | AT 配置、透传状态、自动重连 |
| UART 9600/115200 | MCU-DTU 物理链路 | 主波特率 9600，兼容探测 115200 |
| DMA Circular RX | 连续接收 | 降低 CPU 搬运开销 |
| TX DMA/FIFO | 非阻塞分段发送 | 避免长 JSON 阻塞控制循环 |
| MQTT QoS 1 | 至少一次投递 | 必须配合 `msg_id` 幂等去重 |
| JSON | 遥测、事件、命令和回执 | 可读、易扩展，但占栈和缓冲区 |

当前 v1 主题：

```text
上行：gaochang/lift/v1/devices/{chip_uid}/up
下行：gaochang/lift/v1/devices/{chip_uid}/down
Broker：8.134.167.240:1883
ClientID：gc-lift-{chip_uid}
```

## 五、明确不是什么

| 误解 | 事实 |
|---|---|
| 有 ESP32 网关 | 没有，是 TAS 4G DTU |
| DTU 是主控 | STM32 是控制主机 |
| QoS 1 不重复 | 会重复，需要 msg_id |
| 四机型 GPIO 完全相同 | 下降阀/光电/阀组有差异 |
