# 四种机型状态机源码精读（同一安全框架，不同机械时序）

## 核心概念

- ==四机型差异集中在下降机构、阀组、限位和补油==。
- 不能把某一机型的输入输出和时序套到其他机型。
- 读状态机时以“进入动作、阶段推进、停止条件、安全覆盖”四步分析。

## 二、大剪 `lift_large_scissor.c`

### 2.1 角色

`IO_IN_ROTARY_SWITCH` 高=MAIN，低=SUB。角色切换时必须全关输出并回空闲。

输出按角色：`MAIN/SUB_WORK_VALVE`、`MAIN/SUB_AIR_VALVE`  
上限位：MAIN=`IO_IN_UPPER_LIMIT`，SUB=`IO_IN_SUB_UPPER_LIMIT`  
下限位：仅主机读 `IO_IN_LOWER_LIMIT`（光电屏蔽）

### 2.2 配置默认

| 字段 | 默认 |
|---|---|
| `motor_to_valve_delay_ms` | 200 |
| `motor_hold_ms`（主机） | 2500 |
| `sub_motor_hold_ms` | 1500 |

### 2.3 子状态

```text
LS_IDLE, LS_UP_WAITING_AIR, LS_RISING,
LS_DOWN_PHASE_1, LS_DOWN_PHASE_2, LS_DOWN_DROPPING,
LS_LOCKED, LS_REFILLING
```

### 2.4 时序

```text
上升:
  上限位？→ 拒绝
  MOTOR=1, WORK=1 → LS_UP_WAITING_AIR
  等 motor_to_valve_delay_ms → AIR=1 → LS_RISING
  松键或上限位 → All_Off → IDLE

下降:
  若上限位或锁定键 → force_down: MOTOR=0, WORK=1, AIR=1, DROP=1
  否则:
    PHASE_1: MOTOR=1, WORK=1, 等 200ms → AIR=1
    PHASE_2: 等 hold_ms(主2500/子1500) → MOTOR=0, DROP=1
    DROPPING: 松键 → IDLE

锁定: WORK=1, DROP=1（电机关）按住保持
补油 (UP+REFILL): MOTOR=1, WORK=1; 延时后 AIR=1
```

## 三、小剪 `app_lift_core.c`

### 3.1 状态更细

```text
STATE_INIT, IDLE, RISING,
DOWN_PREPARE, DOWN_HOLD_MOTOR, DROPPING,
LOCKING, REFILL, SAFE_STOP, PHOTO_ALARM, ESTOP, FAULT
```

### 3.2 输出仲裁链

```text
读输入去抖
→ 安全状态机 step
→ lift_output_arbitrate()
→ safety_guard_before_output()
→ app_lift_apply_outputs()   // 唯一写 PF8/PD9/PD8
```

硬规则：`motor_req && down_valve_req` 永远非法。

### 3.3 常量（硬编码，不读 g_config）

| 宏 | 值 |
|---|---|
| `LIFT_TICK_MS` | 10 |
| `MOTOR_TO_VALVE_DELAY_MS` | 200 |
| `DOWN_MOTOR_HOLD_MS` | 2500 |
| `UP_TIMEOUT_MS` / `DOWN_TIMEOUT_MS` | 60000 |

### 3.4 输出表

| 状态 | motor | air | drop |
|---|---|---|---|
| RISING | 1 | 1（≥200ms 后） | 0 |
| DOWN_PREPARE | 1 | 0 | 0 |
| DOWN_HOLD_MOTOR | 1 | 1 | 0 |
| DROPPING | 0 | 1 | 1 |
| LOCKING | 0 | 0 | 1 |
| REFILL | 1 | 1 | 0 |

### 3.5 下降

```text
IDLE + down → DOWN_PREPARE (motor)
  200ms → DOWN_HOLD_MOTOR (motor+air)
  再 2500ms → DROPPING (drop+air)
  上限位或锁定 → 强制 DROPPING
```

补油：`UP && REFILL && !DOWN && !LOCK`  
光电：下限位有效时屏蔽；运动中光电 → 需远程 clear  
超时 60s → FAULT

### 3.6 当前 GPIO 事实

| 功能 | GPIO | active | 去抖 |
|---|---|---|---|
| 上升 | PG15 | low | 20 |
| 下降 | PE0 | low | 20 |
| 锁定 | PE1 | low | 20 |
| 急停 | PE2 | **low** | 20 |
| 上限位 | PE5 | high | 20 |
| 下限位 | PE6 | high | 20 |
| 补油 | PE3 | low | 20 |
| 光电 | PE8 | high | 50 |
| 电机 | PF8 | 高吸合 | — |
| 气阀 | PD8 | 高 | — |
| 下降阀 | **PD9**（不是大剪 PF9） | 高 | — |

> [!WARNING]
> 头文件注释可能过时；以 `main.h` 宏 + `app_io_map.c` 的 `s_in_map` 为准。

## 四、超薄 `lift_thin_scissor.c`

子状态：`TS_IDLE, TS_RISING, TS_DOWN_PREPARE, TS_DOWN_HOLD_MOTOR, TS_DROPPING, TS_LOCKING, TS_REFILLING`

默认：`motor_to_valve_delay_ms=200`, `motor_hold_ms=2500`

```text
上升: MOTOR=1；松键/上限位 → Idle
      （上升过程不强制开气阀，与小剪不同）

下降:
  PREPARE: MOTOR=1
  ≥200ms → AIR=1 → HOLD_MOTOR
  ≥motor_hold_ms → MOTOR=0, DROP=1 → DROPPING
  强制快降(上限/锁定): MOTOR=0, DROP=1, AIR=1
  下限位: MOTOR=0, DROP=1, AIR=0   // drop only，防反挺

锁定: MOTOR=0, DROP=1, AIR=0
补油: MOTOR=1, DROP=0, AIR=0（仅电机）
```

GPIO：与小剪同类；输出 MOTOR=PF8, DROP=PD9, AIR=PD8。

## 五、两柱 `lift_double_post.c`

### 5.1 精确毫秒

```c
#define DP_ELECTROMAGNET_DELAY_MS  200U   // 电机接通 → 电磁铁接通
#define DP_MOTOR_HOLD_TOTAL_MS     2000U  // 电机接通 → 电机断开总时间
```

输出映射：

```text
IO_OUT_MOTOR         → PF8
IO_OUT_ELECTROMAGNET → PF9   (= IO_OUT_MAIN_AIR_VALVE 别名)
IO_OUT_DROP_VALVE    → PD8
```

### 5.2 时序

```text
上升: MOTOR=1；松键/上限 → All_Off

下降 (从 action_start 计时):
  t=0      MOTOR=1                     DP_DOWN_PHASE_1
  t≥200ms  ELECTROMAGNET=1             DP_DOWN_PHASE_2
  t≥2000ms MOTOR=0, DROP=1             DP_DOWN_DROPPING
  强制解锁(上限或锁定, 且尚未 DROPPING):
           MOTOR=0, ELECTROMAGNET=1    DP_DOWN_FORCED_UNLOCK
           仍等到 total 2000ms 再 DROP=1
  松下降键 → Idle

锁定: DROP=1 保持
无补油 (on_refill_pressed=NULL)
无光电 (PHOTO=NULL，读永远 0)
```

```text
t(ms):  0 -------- 200 -------- 2000 -------- ...
MOTOR:  ON=========ON========== OFF
MAG:    OFF--------ON========== ON
DROP:   OFF--------OFF--------- ON
        | PHASE_1  | PHASE_2   | DROPPING
```

> [!NOTE]
> 两柱 `g_config.motor_hold_ms=3000`，但下降实际用硬编码 2000 ms，不依赖该字段。

## 六、公共 lift_core 安全顺序

来源：`lift_core.c`（大剪/超薄/两柱）

```text
1. 急停
   触发 → ESTOP, All_Off, stats++, ops->on_estop, OpLog, NotifyEstop
   释放 → ESTOP → IDLE
2. 光电
   大剪主机下限位可 skip 光电
   触发 → PHOTO_ALARM, All_Off...
   运动中触发 → 需远程 clear
3. 远程锁定 → 跳过 ops->poll
4. 否则 g_lift_ops->poll()
```

公共状态：`IDLE / RISING / DROPPING / LOCKED / REFILLING / ESTOP / PHOTO_ALARM`

ops 接口：`init / on_estop / on_photoelectric_blocked / on_clear_alarm / poll`（多数按键逻辑在 poll 内）

## 七、阅读方法

每个状态机函数固定问：

1. 哪个输入使它进入？
2. 进入时打开了哪些输出？
3. 哪些条件可以退出？
4. 急停、远程锁定和非法组合能否覆盖它？
5. 状态和输出是否同步？
6. 是否写日志、统计和 IoT 事件？
