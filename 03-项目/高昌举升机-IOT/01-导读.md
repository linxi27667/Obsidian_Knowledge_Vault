# Gc_Iot_Lift 导读（先建立全局地图，再进入状态机）

## 核心概念

- ==这是一套四机型举升机控制与物联网管理系统==，不是单片机演示程序。
- ==设备侧负责实时控制和安全闭环==，网络侧只负责管理、查询和数据留痕。
- ==联网设备是 TAS-LTE-892D_s4 4G DTU==，不存在 ESP32 网关。
- ==答辩主线==：输入采集 → 去抖 → 安全检查 → 状态机 → 输出仲裁 → TAS DTU → MQTT → Web。

> [!IMPORTANT]
> 急停、限位、光电和远程锁定的最终执行都在 STM32 本地。即使 MQTT 或 Web 断开，设备仍能本地停机。

## 一、项目包含什么

| 子项目 | 作用 | product_type | 阅读优先级 |
|---|---|---:|---:|
| `GC_Big_Scissor/` | 大剪，主/子机和旋转开关 | 3 | 1 |
| `GC_Small_Scissor/` | 小剪，集中式安全状态机最完整 | 1 | 1 |
| `GC_Thin_Scissor/` | 超薄小剪，下限位防反挺 | 2 | 2 |
| `GC-Two_Pillars/` | 两柱，电磁铁解锁时序 | 0 | 2 |
| `Gaochang_Iot_Web/` | Node.js 管理平台 | — | 3 |

四套固件都基于 STM32F407、HAL、FreeRTOS、Keil、W25Qxx、USART3 和 TAS DTU。区别主要在输入输出映射和动作状态机。

## 四、必须记住的一句话

> 本项目以 STM32F407 和 FreeRTOS 实现四类举升机的本地实时控制，通过统一状态机接口复用公共安全与物联网能力；USART3 使用 DMA 和 FIFO 对接 TAS 4G DTU，再以 MQTT v1 协议接入 Node.js 管理平台，形成可确认、可追踪的远程管理闭环。
