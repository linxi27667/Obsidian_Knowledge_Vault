# 通信协议与数据结构（P4 与 S3 的共同合同）

## 核心概念

- ==Topic 决定消息去哪里，数据包决定消息是什么意思==。
- ==共享头文件必须被 P4 和三套 S3 同时遵守==。
- ==协议版本、长度校验和索引映射决定兼容性==。
- 权威源：`shared/mqtt_iot_protocol.h`（主机侧经 `main/smart_home/services/mqtt_iot_protocol.h` 转发）

## 一、双通道注意

| 通道 | 用途 | 实现 |
|---|---|---|
| 小智云协议 | STT/LLM/TTS/MCP | `main/protocols/` MQTT 或 WebSocket |
| 智能家居 IoT MQTT | P4↔S3 设备控制 | `xiaozhi_mqtt.cc`，硬编码公网 Broker |

两者不要混为一谈。

## 二、Broker 与身份

| 项 | 值 |
|---|---|
| Broker | `8.134.167.240:1883` |
| P4 ClientId | `xiaozhi_p4_host` |
| KeepAlive | 90 s |
| 心跳超时 | **60 s**（`kHeartbeatTimeoutSeconds`） |
| S3 心跳周期 | 30 s |

## 三、Topic

| Topic | 方向 | 作用 |
|---|---|---|
| `xiaozhi/iot/cmd/{floor}` | P4→S3 | 单层命令 |
| `xiaozhi/iot/cmd/broadcast` | P4→全部 | 广播 |
| `xiaozhi/iot/power/{floor}` | P4→S3 | 总电源 |
| `xiaozhi/iot/power/broadcast` | P4→全部 | 全层总电源 |
| `xiaozhi/iot/resp/{mac}` | S3→P4 | 执行响应 |
| `xiaozhi/iot/heartbeat/{mac}` | S3→P4 | 状态快照 |
| `xiaozhi/iot/announce/{mac}` | S3→P4 | 发现与注册 |
| `xiaozhi/iot/sensor/{mac}` | S3→P4 | 传感器事件 |

P4 订阅：`announce/#` QoS1、`heartbeat/#` QoS0、`resp/#` QoS1、`sensor/#` QoS0。

## 五、普通命令包

```c
typedef struct {
    uint8_t command;
    uint8_t device_id;
    uint8_t gpio_index;   // 逻辑索引，≠ 物理 GPIO
    uint8_t value;
    uint8_t reserved[4];
} __attribute__((packed)) iot_command_packet_t;  // 8B
```

其他结构：

```c
// RGB V3
iot_rgb_light_packet_t:
  cmd, protocol_version, device_id, index,
  r, g, b, brightness, effect, speed, reserved[6]

// 场景
iot_scene_packet_t:
  cmd, protocol_version, scene_id, source, reserved[8]
```

## 六、心跳 V2 / V3

```text
IOT_PROTOCOL_VERSION    = 2
IOT_PROTOCOL_VERSION_V3 = 3
IOT_MAX_LIGHTS/RELAYS/SERVOS = 3
IOT_MAX_RGB_LIGHTS = 2
```

### V2 字段

| 字段 | 说明 |
|---|---|
| command / protocol_version | HEARTBEAT / 2 |
| device_id / device_status | 楼层 / 在线 |
| device_name[24] / mac_str[13] | 标识 |
| light/relay/servo/sensor_count | 能力计数 |
| lights[3] / relays[3] / servos[3] | 状态 |
| **smoke_mv** | **legacy 名，实际火焰 mV** |
| rain_mv | 雨滴 mV |
| fire_status / rain_status / help_status | 状态枚举 |
| uptime_s | 运行秒 |
| main_power_status | 总闸 |
| reserved[7] | |

### V3 = V2 +

```text
rgb_count
rgb_on/red/green/blue/brightness/effect [IOT_MAX_RGB_LIGHTS]
current_scene
reserved_v3[8]
```

P4 解析：先按 V2 大小判断，再若 `protocol_version==3` 且包够大 → V3。

| 楼层 | 版本 |
|---|---|
| 1F | V2 |
| 2F | **V3** |
| 3F | V2（含传感器） |

| scene | 主机侧动作摘要 |
|---|---|
| 1 SLEEP | 关全灯；2F 冷蓝暗 RGB；2F light1/2 off；relay0 off；3F 天窗关、晾衣杆 0 |
| 2 MOVIE | 关全灯；2F 蓝氛围；3F 天窗关 |
| 3 NIGHT | 2F 暖黄 8%；living off、toilet on；3F balcony off |
| 4 FIRE | 3F 天窗 90/90；全灯开；1F 大门 180；2F 红闪 RGB |
| 5 RAIN | 2F 雨氛围；2/3 晾衣杆 0；3F 天窗关 |
| 6 AWAY | ALL_OFF；1F 门 0；3F 天窗/晾衣杆关 |
| 7 HOME | 全总闸 ON；全灯 ON；1F 门 180；暖 RGB |

## 九、P4 MQTT 处理

`xiaozhi_mqtt.cc` 职责：

- 连接 Broker、订阅四组上行 Topic
- 维护 MAC→楼层映射 `s_floor_mac[1..3]`
- 解析 announce / heartbeat V2/V3 / response / sensor
- 心跳超时 60s → `device_model_set_floor_runtime_offline`
- 发送 command / RGB / scene / main_power / broadcast
- **雨锁**：3 楼 `rain_status != 0` 时强制 2/3 楼晾衣杆（index=8）关闭

## 十、发送 API

| API | Topic | 包 |
|---|---|---|
| `mqtt_send_command(floor,cmd,idx,val)` | `cmd/{floor}` | `iot_command_packet_t` |
| `mqtt_send_main_power` | `power/{floor}` QoS1 | SET_MAIN_POWER |
| `mqtt_send_all_main_power` | `power/broadcast` QoS1 | 同上 |
| `mqtt_send_rgb_light` | `cmd/{floor}` | RGB 包 |
| `mqtt_send_scene` | broadcast + 多条编排 | scene + 动作 |
| `mqtt_send_broadcast` | `cmd/broadcast` | 广播命令 |

## 十一、MCP 工具契约

`smart_home_mcp_tool.cc` 注册 `self.iot.*`。优先使用语义接口：

- `set_servo_power(device_id, open)` — AI 主入口
- 按 index 的工具标为 user_only，用于调试

## 十二、协议演进规则

1. 新字段优先追加，不改变旧字段偏移。
2. 增加版本或用包长度识别。
3. P4 与三套 S3 同步修改。
4. 所有接收端先校验长度。
5. QoS 1 命令考虑重复执行。
6. 场景应有来源、序列号或幂等策略。

## 十三、抓包阅读方法

看到一条消息时依次确认：

```text
Topic → payload 长度 → command → device_id → index → value
→ 协议版本 → QoS → 响应 Topic
```

## 十四、坑点

1. 舵机协议 index 从 **6** 起。
2. `smoke_mv` = 火焰 mV，不是烟雾。
3. 仅 2F 发 V3 心跳。
4. 3F 天窗开合角度不对称。
5. 小智云协议 ≠ 智能家居 IoT MQTT。
6. `smart_home_transaction` 的 ACK 结构尚未完全写入 shared 头。
