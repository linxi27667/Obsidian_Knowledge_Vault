# 核心业务链路（把静态架构变成动态调用流程）

## 核心概念

- ==04 讲代码放在哪里，05 讲运行时怎么流动==。
- 每条链路都按“入口→调度→协议→执行→反馈”理解。
- 读完本篇后，再进入 06～10 的模块精读。

## 一、系统启动链路

```text
app_main()
→ nvs_flash_init()
→ Application::Initialize()
   → Board 初始化显示/触摸/音频/TF卡/摄像头
   → AudioService
   → MCP 工具注册（通用 + 智能家居 + 人脸）
   → 登录 UI + face_recog task (core1)
   → SetDeviceState(Locked)
   → SmartHomeTasksStart()   // 网络前
   → network_start task
→ Application::Run()  // prio 10，EventGroup 阻塞
```

> [!CODE] 源码
> `main/main.cc` → `main/application.cc` → `main/boards/esp-p4-function-ev-board/`

## 二、网络与激活链路

```text
WifiBoard::StartNetwork()
→ ESP-Hosted / Wi-Fi Remote / SDIO → ESP32-C6
→ NetworkEvent::Connected
→ SmartHomeTasksNotifyNetworkReady()  // SNTP
→ 若非 Locked → Activating
→ ActivationTask (8KB, prio2)
   CheckAssetsVersion → CheckNewVersion → InitializeProtocol
→ MAIN_EVENT_ACTIVATION_DONE
→ Idle（若已登录）
```

P4 本身无 Wi-Fi，依赖板载 C6。

## 三、语音对话链路

```text
麦克风/唤醒词
→ AudioService 回调设置 MAIN_EVENT_*
→ Application::Run()
→ 打开小智音频通道并上传音频
→ 云端 STT/LLM/TTS
→ 下行 tts/stt/llm JSON 和音频包
→ UI 文本/表情 + 扬声器播放
```

`InitializeProtocol()` 选择小智 MQTT 或 WebSocket。Locked 状态忽略唤醒词。

## 四、语音控制设备链路

```text
自然语言
→ 云端 LLM 选择 MCP 工具
→ type=mcp payload
→ McpServer::ParseMessage()
→ tools/call → 参数校验
→ Application::Schedule()          // 回主任务
→ SmartHome MCP callback
→ mqtt_send_command()/scene/rgb
→ S3 mqtt_receive → g_device_flags
→ IotControl_Task 100ms → BSP
→ resp + heartbeat 回 P4
→ device_model → UI
```

> [!CODE] 源码
> `application.cc` → `mcp_server.cc` → `smart_home_mcp_tool.cc` → `xiaozhi_mqtt.cc` → S3

## 五、触屏控制链路

```text
LVGL 点击
→ page_* 事件回调
→ mqtt_send_*()
→ xiaozhi/iot/cmd/{floor}
→ S3 mqtt_receive.c
→ g_device_flags
→ IotControl_Task
→ BSP/GPIO/PWM/UART
```

触屏和语音最终复用同一 MQTT 与 S3 执行路径。

## 六、S3 反馈与 UI 更新链路

```text
S3 response/heartbeat/announce
→ P4 MQTT callback（非 LVGL 线程）
→ process_response/heartbeat/announce
→ mqtt_device_model（mutex + PSRAM）
→ ui_event_publish
→ 50 ms UI_Manager_Poll
→ 当前页面刷新
```

心跳超时 60s 由 `mqtt_client_poll()` 检测，楼层标记离线。

## 七、传感器安全链路

```text
三楼 ADC/GPIO (500ms)
→ sensor_adc_task
→ sensor topic / heartbeat
→ P4 device_model
→ event_center (FIRE/RAIN/HELP)
→ auto_mode_on_event / rule_engine
→ mqtt_send_scene / command
→ 多楼层 S3 执行
→ 告警 UI / 语音
```

自动模式任务周期约 **1 秒**，没有实测时不要宣称“毫秒级”。

### 雨锁（主机侧额外逻辑）

```text
3F rain_status != 0
→ 主机强制 2F/3F 晾衣杆（协议 index 8）关闭
```

## 八、人脸识别链路

```text
MIPI-CSI 摄像头
→ EspVideo 取帧
→ face_recog FreeRTOS task (core1, 12KB, prio4)
→ FaceRecognition::DetectAndRecognize()
→ 本地 ESP-DL 特征比对
→ Application::Schedule()
→ UI_EVENT_FACE_RECOGNIZED
→ LOGIN_SUCCESS → Idle + mqtt_send_scene(HOME)
```

当前是 P4 本地识别，不是 USB 摄像头云端识别。0 张脸时 `DetectAndRegister("default")` 可自动注册。

## 九、场景控制链路

场景将一次意图拆成多个楼层命令。8 种场景：睡眠、观影、夜间、火警、雨天、离家、回家、明亮。

以雨天为例：

```text
雨滴触发 / 场景 5
→ 2F 雨氛围 RGB
→ 2/3 晾衣架收回（servo 8 = 0）
→ 3F 天窗关闭
→ 心跳反馈最终状态
```

以火警为例：

```text
火焰 / 场景 4
→ 3F 天窗 90/90
→ 全灯开
→ 1F 大门 180
→ 2F 红闪 RGB
```

## 十、登录与归家

```text
Locked
→ 人脸识别 或 手动登录
→ UI_EVENT_LOGIN_SUCCESS
→ Schedule(OnLoginSuccess)
→ Idle
→ mqtt_send_scene(IOT_SCENE_HOME)
  （MQTT 未连则排队，连上后 flush）
```

## 十一、端到端追踪方法

追一条功能时固定回答：

1. 入口事件是什么？
2. 运行在哪个任务/回调？
3. 写入哪个模型或事件？
4. 调用哪个协议函数？
5. Topic 和数据包是什么？
6. S3 如何映射到本地设备？（协议 index vs 本地）
7. 硬件由哪个 BSP 函数操作？
8. 执行结果如何返回？
