# S3 从机源码精读（三层楼的实际执行者）

## 核心概念

- ==三层从机是三个独立 ESP-IDF 工程==。
- ==BSP 封装物理硬件，APP 封装业务==。
- ==MQTT 回调更新期望状态，设备任务统一刷新硬件==。
- ==舵机协议 index 从 6 起，本地数组从 0 起==。

## 五、MQTT 接收

`mqtt_receive.c` 收到 `MQTT_EVENT_DATA` 后：

```text
1. 校验 Topic 和包长度
2. 解析 command
3. 协议索引 → 本地索引
4. 更新 g_device_flags
5. 发布 resp/{mac}
6. 可选心跳 Publish_Now
```

Flag-driven 架构：==回调只改标志，不阻塞等舵机/串口==。

```c
g_device_flags.light[index] = ON;
g_device_flags.relay[index] = OFF;
g_device_flags.servo[index] = SERVO_90;  // 本地 0 基
```

## 六、协议索引 vs 本地索引

| 通道 | 协议 index | 本地数组 | 说明 |
|---|---|---|---|
| Light | 0..N-1 | 同 | `IOT_CMD_SET_LIGHT` |
| Relay | 0..N-1 | 同 | `IOT_CMD_SET_RELAY` |
| **Servo** | **6, 7, 8** | **0, 1, 2** | `SERVO_PROTOCOL_BASE_INDEX=6` |
| RGB | 0 | 0 | 仅 2F |
| Main power | 0 | — | 独立 Topic |

转换：

```text
protocol = (local < 6) ? local + 6 : local
local    = protocol - 6
```

舵机角度量化：`step = value / 45` → 映射 0/45/90/135/180。

| 功能 | GPIO | 协议 index |
|---|---|---|
| 总闸 | 40 | — |
| 大厅灯 | 7 | light 0 |

## 八、二楼

| 功能 | GPIO | 协议 index |
|---|---|---|

| Light0 主卧 | **GPIO_NUM_NC**（走 WS2812） | light 0 / rgb 0 |
| Light1 客厅 | 5 | light 1 |
| Light2 厕所 | 6 | light 2 |
| Relay0 风扇 | 7 | relay 0 |

### 传感器阈值

来源：`sensor_config.h` / `sensor_adc_task.c`

| 宏 | 值 | 含义 |
|---|---|---|
| `FIRE_THRESHOLD_PERCENT` | 60 | 火焰阈值百分比 |
| `FIRE_TRIGGER_COUNT` | 3 | 连续触发次数 |
| `FIRE_ALERT_INTERVAL_MS` | 5000 | 报警上报间隔 |
| `RAIN_THRESHOLD_LIGHT` | 2640 mV | 雨滴阈值 |
| `RAIN_TRIGGER_COUNT` | 2 | 连续触发次数 |
| `ADC_SAMPLE_INTERVAL_MS` | 500 | 采样周期 |
| `SENSOR_ADC_FULL_SCALE_MV` | 3100 | 满量程 |

> [!IMPORTANT]
> 心跳字段 `smoke_mv` 实际承载 **火焰 mV**（线协议兼容旧名），不是烟雾。

上报路径：

1. 心跳 V2 内嵌 `smoke_mv/rain_mv/fire_status/rain_status/help_status`
2. 独立 Topic `xiaozhi/iot/sensor/{mac}` + `IOT_CMD_SENSOR_REPORT`

## 十一、APP-BSP 调用关系

```text
MQTT / 传感器 / 业务任务（APP）
          ↓
app_uart / app_servo / app_wifi（APP 封装）
          ↓
bsp_uart / bsp_servo / bsp_wifi（BSP）
          ↓
ESP-IDF driver → GPIO / UART / LEDC / ADC
```
