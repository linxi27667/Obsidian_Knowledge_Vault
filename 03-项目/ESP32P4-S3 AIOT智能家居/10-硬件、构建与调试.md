# 硬件、构建与调试（让源码理解落到真实设备）

## 核心概念

- ==当前主工程目标是 ESP32-P4 Function EV Board==。
- ==P4、三个 S3 是四个独立固件，必须分别构建和烧录==。
- ==调试按层定位：入口→协议→模型→任务→BSP→硬件==。

## 一、P4 硬件资源

| 资源 | 实现 |
|---|---|
| LCD | 1024×600 MIPI-DSI |
| 触摸 | GT911，经 LVGL port |
| 音频 | ES8311，24 kHz 输入/输出 |
| 摄像头 | MIPI-CSI + SC2336，经 esp_video |
| 存储 | 16 MB Flash、PSRAM、TF 卡 |
| 网络 | ESP-Hosted → 板载 **ESP32-C6**，SDIO 4-bit 40 MHz |
| 按键 | BOOT GPIO35 |

板级入口：`main/boards/esp-p4-function-ev-board/esp-p4-function-ev-board.cc`。

## 二、内存与分区

`partitions/v2/16m.csv`：

| 分区 | 偏移/大小 | 用途 |
|---|---|---|
| nvs | 0x9000 / 0x4000 (16 KiB) | 配置 |
| phy_init | 0xf000 / 0x1000 (4 KiB) | PHY |
| app | 0x20000 / 0xC80000 (12.5 MiB) | **单 factory** |
| assets | 0x300000 (3 MiB) | UI/音频 SPIFFS |
| face_db | 0x40000 (256 KiB) | 人脸数据库 SPIFFS |

当前不是双 OTA 分区。大图像、摄像头帧和模型工作区优先使用 PSRAM；任务栈、DMA 关键数据保留内部内存。

## 四、主工程构建

```powershell
# 项目自带包装
.\idf.cmd build

# 标准 ESP-IDF
idf.py set-target esp32p4
idf.py build
idf.py -p COMx flash monitor
```

`set-target` 会重置部分构建配置，比赛前不要无备份随意执行。

## 八、故障分层

### 8.1 UI 控制无动作

```text
LVGL 回调
→ mqtt_send_* 返回值
→ Broker 连接 (8.134.167.240:1883)
→ S3 心跳 (30s)
→ S3 MQTT_EVENT_DATA
→ g_device_flags
→ IotControl_Task
→ BSP/供电
```

### 8.2 语音能聊天但不能控设备

查 `type=mcp`、工具注册、参数校验、`DoToolCall()`、`Application::Schedule()` 和 **智能家居 MQTT** 连接（不是小智云连接）。

### 8.3 设备动作但 UI 不更新

查 response/heartbeat 发布、P4 订阅、MAC→楼层映射、device_model 和 UI event。

### 8.4 人脸失败

查 MIPI-CSI 初始化、图像格式、模型、PSRAM、光照、正脸和 face_db。

### 8.5 UI 卡顿

查 LVGL 上下文耗时、页面重建、图片加载、人脸任务 CPU、PSRAM 带宽和显示锁。

### 8.6 舵机角度不对

确认协议 index（6/7/8）与本地 0/1/2 映射；确认 3F 天窗开合角度不对称（右 90/180，左 90/0）。
