# 代码架构（看懂目录、分层、依赖和任务）

## 核心概念

- ==主仓库包含一个 P4 主工程和三个独立 S3 工程==。
- ==P4 以 Application 为总调度，以 Board 为硬件抽象==。
- ==智能家居采用服务、任务、模型、UI、MCP 分层==。
- ==S3 采用 BSP-APP 分层和状态刷新任务==。

## 二、P4 分层

| 层 | 目录/文件 | 责任 |
|---|---|---|
| 入口 | `main/main.cc` | NVS、Application 启动 |
| 应用编排 | `application.*` | 状态、事件、音频、协议、登录 |
| 状态机 | `device_state_machine.*` | 状态转移与监听 |
| AI 工具 | `mcp_server.*` | MCP 注册、解析和执行 |
| 协议 | `protocols/` | 小智云 MQTT/WebSocket |
| 音频 | `audio/` | Codec、处理、队列、编解码 |
| 显示 | `display/` | Display 抽象、LVGL、小智 UI |
| 板级 | `boards/` | LCD、触摸、Codec、Camera |
| 智能家居 | `smart_home/` | UI、MQTT、规则、人脸、工具 |

依赖方向：应用层 → 抽象接口 → 板级实现。业务不直接依赖某个 LCD 或 Codec 芯片。

## 四、P4 启动顺序

```text
app_main
→ nvs_flash_init
→ Application::Initialize
   → Board::GetInstance
   → display->SetupUI
   → AudioService Initialize/Start
   → 注册状态监听和时钟
   → 注册 MCP/智能家居/人脸工具
   → 登录 UI + face_recog task
   → Locked 状态
   → 网络事件回调
   → SmartHomeTasksStart
   → network_start task
→ Application::Run  (prio 10)
```

## 五、P4 任务与上下文

| 任务/上下文 | 栈 | 优先级 | 核 | 作用 |
|---|---:|---:|---|---|
| Application 主任务 | 10240 | 运行时 10 | — | 主事件循环 |
| `network_start` | 8192 | 5 | — | 网络初始化 |
| `activation` | 8192 | 2 | — | 版本检查与协议初始化 |
| `sh_iot_mqtt` | 8192 | 5 | 1 | MQTT/天气/自动模式 1s |
| `face_recog` | 12 KiB | 4 | 1 | 摄像头与人脸识别 |
| LVGL 上下文 | 端口管理 | — | — | UI 对象操作 |

## 六、S3 分层

每个从机都是独立 ESP-IDF 工程：

```text
main/
├─ iot_slave_main.c
├─ BSP/Inc + BSP/Src
└─ APP/Inc + APP/Src
   ├─ mqtt_receive / mqtt_heartbeat
   ├─ iot_control_task
   ├─ app_wifi / app_uart / app_servo
   ├─ (2F) app_ambient_light
   └─ (3F) sensor_adc_task / app_asr_uart
```

| 任务 | 栈 | prio | 周期 |
|---|---:|---:|---|
| `iot_ctrl` | 4096 | 3 | 100 ms |
| `mqtt_hb` | 2048 | 4 | 30 s |
| `Sensor_ADC` (3F) | 4096 | 4 core1 | 500 ms |

网络回调更新 `g_device_flags`，`IotControl_Task` 再统一刷新硬件。

## 七、编译时架构

`sdkconfig` 选中 `ESP_P4_FUNCTION_EV_BOARD`，`main/CMakeLists.txt` 才加入对应板级文件。大量其他板型存在于仓库，但不属于当前固件。

`main/idf_component.yml` 按 target 条件加载 P4 专用组件：ESP-Hosted、Wi-Fi Remote、P4 BSP、人脸识别。

## 八、双协议通道

| 通道 | 作用 | 关键文件 |
|---|---|---|
| 小智云协议 | 语音 AI、MCP JSON | `main/protocols/` |
| 智能家居 IoT MQTT | 设备控制二进制 | `xiaozhi_mqtt.cc` + `shared/` |

答辩时必须说明：能聊天只证明小智云通；控设备还要智能家居 MQTT 与 S3 心跳。

## 九、架构阅读入口

| 顺序 | 文件 | 目的 |
|---:|---|---|
| 1 | `main/main.cc` | 找入口 |
| 2 | `main/application.cc` | 找总编排 |
| 3 | `boards/.../esp-p4-function-ev-board.cc` | 找硬件实例 |
| 4 | `smart_home/tasks/smart_home_tasks.cc` | 找业务任务 |
| 5 | `smart_home/services/xiaozhi_mqtt.cc` | 找通信中枢 |
| 6 | `shared/mqtt_iot_protocol.h` | 找协议合同 |
| 7 | 三层 `iot_slave_main.c` | 找从机入口 |

## 附录：架构原则

- 回调短、任务阻塞、跨线程投递。
- UI 不直接解析 MQTT。
- P4/S3 共享协议只有一个定义源。
- APP 不应绕过 BSP 直接操作硬件。
- 第三方组件按接口理解，不混入自研代码统计。
