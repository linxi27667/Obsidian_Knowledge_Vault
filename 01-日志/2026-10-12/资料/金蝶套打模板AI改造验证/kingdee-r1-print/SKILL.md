# 金蝶套打模板修改与验证

使用用户提供、已知可导入的 r1-print 导出文件作为骨架。先确认任务是静态版式 Demo，还是打印真实业务单据；参考图与源模板属于不同业务对象时，先说明差异。不要凭样张猜字段标识。

## 执行顺序

1. 读取文件字节、XML、版式样张与用户授权；备份源文件并计算哈希，明确实际编辑的是哪份文件。
2. 检查 Parameters、DataSources、Styles、Layers、Report、PrintInfo。保留不需改变的结构、版本、数据源关联和绑定。清空 XML 节点会同时删掉属性；保存 Styles 的原属性，至少保留已知有效的 version。
3. 从样张确定标题、信息区、表格、二维码、签收栏及页码。纸型/方向不明确时记录假设。Demo 可用固定示例；正式模板保留并验证动态字段、明细循环和关联。
4. 在候选文件中修改；使用 scripts/validate_xml.py 做结构检查。scripts/build_layout_demo.py 只用于静态版式 Demo，不用于替换正式业务绑定。
5. 本机有匹配的金蝶库时，按 references/workflow.md 用 Windows PowerShell 5.1 和 scripts/validate_native.ps1 读取及重新序列化。链中传入工具箱对象，数据翻译器不能为 null；要求全部控件 ID 可找到、前后数量相同、静态内容与位置保留。Helper 暂覆盖 Text、Barcode、Currency；其他控件需扩展对应注册，不能跳过后宣称通过。
6. 对静态二维码检查编码字符串和原生生成。此案例的编码值是大小写准确的 Qrcode。动态二维码内容、扫码目的及真实数据要另验。
7. 生成布局模拟预览并人工看换行、边框、字号、空白和页码。模拟图不是金蝶实际打印证据。
8. 按用户授权替换目标文件或交付候选，让用户在设计器导入，记录截图或明确结果。区分 XML 可读、原生解析通过、设计器载入、保存发布、真实数据预览、实物打印等状态。
9. 归档源文件、候选/失败版、修复版、验证记录、样张和结果；日志正文通俗可读，技术步骤与证据放附件。

## 发生导入错误

先用原文件和候选文件做相同校验，保留异常堆栈。若堆栈在 StyleParser.Upgrade，且原模板有 Styles 的 version、候选没有，使用 scripts/repair_styles_version.py 从原模板恢复，重新原生验证。别把所有空引用错误都归为这一原因。

运行依赖不存在或版本不匹配时保存候选并说明未验证的范围，不用“XML 能解析”替代“能导入金蝶”。原生检查后仍需按任务完成设计器/业务预览确认；任何未执行步骤保持待验。
