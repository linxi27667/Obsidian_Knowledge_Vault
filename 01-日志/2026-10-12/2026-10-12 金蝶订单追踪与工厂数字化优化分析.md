# 2026-10-12 金蝶订单追踪与工厂数字化优化分析

## 15:03 · 用通俗语言梳理工厂订单、金蝶和数字化问题

### 记录背景
我负责公司 IT 与数字化工作，但不是生产管理出身，希望先用容易理解的语言弄清工厂现状，再带着证据向董事长请教优化方向。以下正文先讲结论、样本和建议；复杂字段、完整取证与来源放在附件中供核对。



### 先记住一句话

一台举升机要按时交付，不是“生产部门把机器做出来”就够了。它需要很多零件按顺序到位，焊接组件先齐，整机再齐；生产实际发生的领料、加工、检验和入库，还要及时记进系统。只要物料、计划、现场动作和系统记录有一处对不上，大家就可能要靠打电话、翻旧单、问熟悉情况的人来判断。

这次看到的资料提示：公司已经有金蝶、生产工单和部分 MES 报工能力。当前更值得查清的是各系统和岗位之间的衔接，而不是先假定“金蝶坏了”或“全厂库存都不准”。

### 一、把生产流程想成接力

可以把一张整机订单想成一场接力：

1. 销售确定客户要什么产品、多少台、希望什么时候交。
2. 计划人员把整机拆成需要生产或采购的零件与组件。
3. 仓库、生产、采购和外协分别准备各自负责的物料。
4. 零件先凑成焊接组件；多个组件再凑成一台整机。这叫“两层齐套”。
5. 车间按计划加工、装配、检验、报工。
6. 成品入库后，才能安排发货。

“齐套”就是开工或转到下一步前，所需的关键东西都已经准备好。若只看某一个部门完成了多少件，却不看这些件能不能组成下一步需要的整套产品，就容易出现“大家都很忙，但整机还是交不出去”。

### 二、这次查到的订单是什么

样本是销售订单 26GC106，客户需求为 18 台重型龙门举升机 GC-5.0PRO。销售单的 18 台整机下面有两条各 18 件的子项：基本型装配和控制盒。父项是整机需求，子项是组成部分，所以不能把三个 18 相加成 54 台。

系统把这两条生产线分开记录：

- 控制盒生产单显示 18 件已报工、已完工，并有 18 件成品入库记录。
- 基本型装配生产单显示已下达，但合格报工和成品入库仍为 0。
- 订单要货日是 2026-07-15；基本型生产计划完工日显示 2026-09-10；机架组装工序计划结束时间显示 2026-10-26。

这说明系统里的两个子项进度不同，而且销售、生产、工序三种日期没有对齐。它还不能单独证明订单为什么没完成，也不能直接断定谁造成延期：可能涉及改期、客户条件、实际现场进度没有及时录入、计划调整或 MES 同步问题。应先向 PMC 和现场确认这张旧订单现在是否仍在执行，再选择仍有效的订单做试点。

### 三、库存数字为什么不能直接等于“能不能开工”

金蝶里的库存余额是账面记录。实际判断某批料能不能用，还要确认：

- 料是否真的在仓库或车间，位置是否找得到；
- 是否已经分给其他订单；
- 是否在线边、在制、待检或有质量问题；
- 是否已经拿到现场但还没过账；
- 单位、替代料和 BOM 版本是否一致。

这张基本型生产用料表有 75 种物料。系统属性显示其中 43 种是自制、32 种是外购；66 种按直接领料方式记录，9 种按倒冲方式记录。倒冲可以理解为按约定的报工或入库节点扣减用料，不一定是仓库发料当时就扣。

在本次只读查询中，75 种物料里有 41 种的可见账面余额低于本单需求量。这 41 种只是“值得去现场核实”的候选，并非已经确认缺料。比如主立柱组件、从立柱组件和横梁组件，本单各需要 18 件，当前可见账面各有 3 件；还要查其余数量是否已经在制、在别的仓位、由其他批次生产或尚未登记。

本单查到的 17 条领料明细都对应控制盒生产分录，基本型分录没有查到登记的领料数量。这说明控制盒的系统记录比较完整，而基本型的用料记录需要继续查。它不等于证明现场一件料都没拿，也不等于证明一定缺料。

采购单也要看新旧和有效性。本次候选采购记录里有一条 2024 年创建、仍显示未结的旧单。它不能被当成 2026 年可靠的在途供给，必须问采购是否还有效、是否已经到货或需要清理。

### 四、两天访谈反映了什么

刘博的流程说明和余总/PMC交流提到了一些值得实地确认的问题：

- 有些内部领料发生后，不一定马上按实发数量记账；实际领用量和系统记录可能有差别。
- 大件会在仓库和车间之间转移，标准小件通常在仓库。即使系统显示有料，现场人员仍可能要找位置或问人。
- 有些补料需求在接到工序单、配料或装配时才被发现；采购、外协或自制都需要时间。
- 主计划下发后，各部门还要自己安排小计划；上下工序的完成时间不一定自然衔接。
- 员工计件和部门局部产量需要与整机交付协调。访谈提出的是管理上可能存在的压力，不能据此认定工人故意挑活。
- 部分工序已有手机或扫码报工。本新 MES 项目也有焊接排产、齐套、质量和报工等建设方向；具体部署、回写范围和验收状态要查项目记录，不能把“代码存在”当作“全厂已稳定使用”。

这些内容来自访谈和项目资料，不是全厂统计。需要结合具体单据、现场盘点与岗位说明确认。

### 五、金蝶、MES 和未来的 Agent 各做什么

- 金蝶 ERP：保存销售、物料、BOM、生产、采购、库存和审核结果等正式业务记录。
- MES：帮助车间安排工序、记录现场生产和质量情况。它与金蝶之间需要明确哪些数据由谁产生、何时同步、失败由谁处理。
- 报表：把多张单据的状态放到一起，帮助人看订单、物料和工序哪里卡住。
- Agent：先读取授权范围内的数据，告诉人“哪张单、哪个分录、什么数字和时间有差异”，再给出需要核实的建议。它不能只靠模型猜实际库存，也不应该在业务规则没定之前自动保存、审核、扣库存或改计划。

金蝶客户端是使用系统的界面，不等同于金蝶全部源码。改进通常先利用金蝶已有单据、报表、权限和官方接口，再与现有 MES 配合。不要直接连生产数据库改业务表。

### 六、建议先做的小范围改进

1. 先让 PMC 选一张仍在执行的整机订单，完整核对订单父子项、生产单、关键物料、采购/外协、工序、检验、入库和发货。
2. 做一张可回查的订单进度页：每个子项分别显示计划日、当前状态、缺口、位置、负责人和最后更新时间；同时看零件齐套与整机齐套。
3. 重点料先按“缺了是否停线、补货需要多久、库存记录是否可信、型号是否特殊”分级，而不是要求所有零件都扫码。
4. 申请可一次填多种物料，仓库确认实际发了多少；大件按批次记录转序，小件按箱/盒和补充周期管理；钢材等按公斤、米和余料记录。先由岗位人员确认流程，避免多录一套无用数据。
5. 把直接领料、倒冲、退料和现场实发的规则理清，防止同一批物料被扣两次，或现场已经拿料但系统还显示在库。
6. 先量出基线：开工前关键料齐套率、缺料等待时长、临时加急次数、计划完成率、MES 到金蝶同步时间、重点料账实差异。没有基线前不要承诺改善百分比。

### 七、见董事长时，通俗地问清这些事

1. 现在最希望先减少什么：延期、缺料停工、找料时间、库存差异，还是报工重复？
2. 先拿哪个机型、车间和仍在执行的订单试？
3. 客户交期、生产计划和工序计划冲突时，以哪个批准版本为准？谁有权改？
4. 插单或多人争用同一批物料时，PMC 能决定什么，最终由谁裁决？
5. 哪些关键动作必须记录？由谁确认真实发料、转序、退料和完工？
6. 现有 MES 项目承诺交付什么？哪些问题由实施方负责，哪些可以由我参与开发？
7. 刘博、PMC、仓库和主管能提供多少配合时间？先试 10 到 20 种重点料是否合适？
8. 用哪些订单和指标观察多久，由谁验收后再决定是否扩大？

会后至少需要拿到：一张有效订单、当前批准的交期与生产计划、现场实际在制与物料位置、关键料的实发/退料/占用情况、采购和外协的有效承诺、MES 报工同步记录，以及每个环节的责任人。

### 词语小抄

| 词语 | 白话解释 |
|---|---|
| ERP | 公司正式记录业务和库存的系统，金蝶属于这一类。 |
| MES | 连接车间现场的生产管理系统，记录工序、报工和质量等。 |
| BOM | 产品组成清单，说明一件产品要用什么料、各用多少。 |
| MRP | 根据订单、BOM、库存和计划计算还需要买或生产什么。 |
| 工单 | 安排生产某个物料或组件的任务单。 |
| 齐套 | 进入某个工序前，需要的东西都准备好。 |
| 报工 | 员工或班组记录实际完成的工序和数量。 |
| 入库 | 完工品被正式记入仓库。它不一定等同于客户已经收货。 |
| 账实差异 | 系统数量与现场实际数量不一致。 |

### 结论与范围

这次分析的价值，是把一张整机需求拆成可以逐项核对的系统记录，并指出哪些地方需要 PMC、仓库、采购和车间解释。它不是全厂审计，也没有证明 26GC106 现在仍是活跃订单，更没有证明该订单因缺料而停工。

完整数据表、官方接口与现有 MES 依据、董事长问题清单见下方附件中的详细分析报告、访谈提纲和取证材料。第一次查询的 MO020624 是控制盒部件单的局部跟踪，不是整机完整链路。

## 15:58 · 高总明确数字化优化先从焊接量化开始

### 这次会听到的重点

高总希望先把范围缩小到焊接车间：每天计划做什么，实际完成多少，当前积压多少，完成量对应多少标准工时。近期先研究未来 1–3 天能否稳定安排，同时看第 4–6 天要准备哪些工作。具体哪些情况允许改计划，还要和 PMC、车间主管确认。

下料、激光切割和机加怎样按焊接需要准备，是下一步要核对的衔接问题。现在还不能只凭会议判断焊接就是唯一瓶颈；要看当前有效工单、报工和现场等待情况。

### 对库存问题的补充理解

我此前观察到工人取料可能没有及时登记，库存账面和现场实际可能不一致，缺料会让后续工序等待或临时加急。高总提醒，单纯增加备料员不一定解决问题，关键还要有清楚的领料规则、实际数量确认和责任记录。后续要用具体物料和工单验证发生在哪一步，不能先把原因定成“缺备料员”。

### 下一步先查已有系统

刘博提到金蝶已有“工序计划”和“工序汇报”页面，可以查看焊接工单及每天汇报量。先和刘博一起看过滤方案、字段和数据更新时间，再确认 MES 是否也记录这些内容。Open API 和 K3CloudOps 是可调查的扩展路径，但会议没有证明所有金蝶数据都能通过 API 读取，也没有决定直接开发或改写业务数据。

### 本周准备讨论的事项

我把会议要求整理成 5 个候选方向：查看现有焊接页面和报表；由 PMC 选 3–5 张当前有效工单做基线；统一计划数量、实际完成和标准工时的口径；讨论近期计划稳定范围与变更记录；找一项能减少刘博重复查询或汇总工作的办法。这是待讨论清单，不代表已经批准实施。

会议还建议补看金蝶生产管理课件，先熟悉现有功能和报表，再决定技术方案。完整归纳、推理过程、数据清单和待核问题见 [[资料/金蝶订单跟单与数字化分析/07 2026-10-12 高总会议纪要与数字化优化推理|高总会议纪要与数字化优化推理]]。

## 16:31 · 刘博提出三项日常操作优化需求

### 刘博今天提出的原话

来源是用户在今天转述的三个问题，具体提出时刻未提供；本节时间为记录时间。

> 1、零部件下单时，除按单生产的零部件之外，其余零部件在下单生产之前，基本都需要查询库存情况、生产情况、用料情况，能否优化。
>
> 2、每张工单需要在资料室找图纸，或者找底图复印配套工单下发车间，该流程后续如何简化。
>
> 3、关于研发领料，能否快速定位可调整物料及对应单价/金额。

### 用直白的话理解这三个问题

**第一项是减少开生产单前反复查数。** 刘博要结合库存、正在生产的数量和用料需求，才能决定还要不要做、做多少。可以先研究把这些信息集中到一个查询入口，每个数字保留来源和更新时间。需要分清真正可用的库存、已被其他需求占用的料，以及在制物料能否赶上需要时间。

**第二项是减少工单下发前找图和复印。** 可以先选一张常用工单，建立物料、图号、图纸文件和适用版本的对应关系。仍需纸图的岗位，先研究一次准备好工单与配套图纸的打印资料；能看电子图的岗位，再研究从工单或二维码直接打开。重点是配对正确的已批准版本。

**第三项是让研发领料明细和价格更容易找到。** “可调整物料”的具体含义还没有说明：可能涉及领料单数量或金额的调整，也可能指可供研发领用、调配或替代的物料，需用实际例子确认。单价还要明确是采购价、库存核算成本还是参考价，并标明单位、币种、税和来源日期，才能正确理解金额。

### 下一步与当前状态

上述改进方式是初步建议，尚未实施。下一次可请刘博分别演示一次下单前查询、一张工单配图、一个研发领料例子，记录重复步骤和耗时，再确认已有金蝶或 MES 功能能解决多少、哪一项适合先做样例。
