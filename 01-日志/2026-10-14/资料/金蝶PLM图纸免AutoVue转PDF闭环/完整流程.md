## 一、输入、目标与约束边界

### 1. 业务痛点与目标
- **业务痛点**：高昌机电销售、业务、采购及车间主管需要查阅 SolidWorks CAD 图纸。金蝶原厂自带的“浏览”按钮强制依赖 Oracle AutoVue 插件，现代浏览器（Edge/Chrome）无法兼容，且在每个客户端部署维护极易损坏；业务客户端绝不能也不应该安装几十 GB 的 SolidWorks 商业软件。
- **核心目标**：建立一条集中、自动化、免装客户端插件的端到端流水线：
  1. 从金蝶 PLM 电子仓自动检出 `.SLDDRW` 工程图与依赖模型；
  2. 调度独立 CAD 工作站后台无损导出高精度矢量 PDF（完整保留图框、文字、尺寸公差）；
  3. 将 PDF 直传金蝶电子仓，并合规关联回金蝶文档对象，标记 `ISCONVERTPDF = 1`；
  4. 业务/销售在客户端直接点击“浏览PDF”或“下载PDF”即可秒级预览。

### 2. 约束边界（遵循项目 AGENTS.md）
- **数据库默认只读**：严禁直接通过 SQL `UPDATE` 业务表；所有业务对象关联必须通过官方服务与金蝶事务模型（`KDTransactionScope`、`DocumentModel.AddRelationCadPdf`、`DocAddPdfRecManager`）。

## 三、踩坑细节与现场排查依据记录

今天在推进全流程时遭遇并解决的五个核心问题：

### 踩坑 1：PowerShell 数组参数解包导致 WebApi 调用失败
- **现象**：调用 `RichClientDocumentService.BeforeDownloadFiles` 提示参数不匹配或失败。
- **原因**：PowerShell 的管道与参数传递机制中，`-Arguments @($allDocIds)` 会把包含 2 个 ID 的数组展开为 2 个独立的参数，而服务端的 C# 签名为 `BeforeDownloadFiles(List<long> docIds)`，期望的是一个包含 ID 列表的单一参数。
- **解决**：在 PowerShell 中使用一元逗号语法 `-Arguments (,$allDocIds)`，强制将数组作为单一对象包装入参数列表。

### 踩坑 2：跨 WinRM 编码不一致导致 PDF 抓取文件名乱码
- **现象**：工作站端 SolidWorks 成功生成了 `3.5MS-C-01-11滑板下垫板.pdf`，但调度脚本拉取时报错：
  `Cannot find path '...\3.5MS-C-01-11婊戞澘涓嬪灚鏉?pdf' because it does not exist.`
- **原因**：工作站将结果序列化为 UTF-8 无 BOM 的 `result.json`，而调用端 Windows PowerShell 5.1 的 `Get-Content` 默认按系统的 ANSI/GBK 解码，造成多字节中文字符转义为乱码。
- **解决**：
  1. 读取 JSON 时显式指定 `[IO.File]::ReadAllText($path, [Text.Encoding]::UTF8)`；
  2. 拉取文件时不依赖传递的路径字符串，改用目录通配符直接复制 `Copy-Item -FromSession $cadSession -Path "$remoteRoot\output\*.pdf" -Destination $localPdfDir`，并在本地以原生 FileInfo 获取名称，彻底消除跨网络编码风险。

### 踩坑 3：Task Scheduler 并发配置与 ROT 隔离
- **现象**：批量执行第 3 张图纸时，进程卡在 `WaitingForOwnedCadAutomationRegistration` 超过 180 秒超时。
- **原因**：
  1. `GcPlmPdfPilot-CurrentIsolated-20261014` 任务计划被配置为 `MultipleInstances: IgnoreNew`。当脚本连续快速调用 `Start-ScheduledTask` 时，前一个任务尚未完全释放，后一个触发被 Task Scheduler 直接静默忽略；
  2. Windows 运行对象表（ROT）是按 Windows 会话（Session ID）严格隔离的。WinRM 运行在 Session 0，无法直接枚举交互桌面 Session 1 的 ROT。
- **解决经验**：调度批量任务时必须在每一次转换完成后确认计划任务回到 `Ready` 状态，并在工作站端设置守护逻辑防止孤儿进程占位。

### 踩坑 4：金蝶 PLM 许可报错（错误ID：3B2DDEB9DFEA4896338BC110D284553C）
- **现象**：用户在客户端打开文档库时弹出错误 ID，操作为 `PLM_CFG_LIBARAYOBJECT.LoadData`。
- **现场排查证据**：
  登录应用服务器 `K3APP-LAB`，检索 `C:\Program Files (x86)\Kingdee\K3Cloud\WebSite\App_Data\Log\2026-10-14\Cloud.log`，第 6026 行抓取到原始异常：
  ```text
  2026-10-14 13:49:33,792 [75680] ERROR - BOS - Code:c877e077afd24f648b51597e6c0ed9d6,FormId:PLM_CFG_LIBARAYOBJECT,LoadData:[]
  Kingdee.BOS.KDExceptionLicense: 您没有PLM云许可，请联系系统管理员分配许可！
     在 Kingdee.BOS.VerificationHelper.RegisterUserV2LicStrategy.ApplyNewUser(Context ctx, LinkedFormId form)
     在 Kingdee.K3.PLM.CFG.Business.PlugIn.BaseObject.LibarayObjectList.LoadTree(...)
     在 Kingdee.BOS.Web.DynamicForm.DynamicWebFormView.LoadData()
  ```
- **原因**：金蝶云星空的 PLM 是独立授权收费模块。用户在客户端打开 PLM 目录树时，系统校验到当前登录账号未在【系统管理】➔【用户管理】➔【许可分配】中分配“PLM 云许可”，或者企业购买的 PLM 模块并发许可已被占满。

### 踩坑 5：点击“浏览”要 AutoVue，点击“浏览PDF”显示无对应 PDF
- **现象**：用户在金蝶客户端打开总成 `3.5MS-A-00-00-V4.0 底座部分总成【增高型用】.SLDASM`，在【组成结构】树中点击零件 `3.5MS-A-01-2下支座底板.SLDPRT`：
  - 点击“浏览”：提示需要安装 AutoVue；
  - 点击“浏览PDF”：弹出警告“没有对应的PDF文档: 可能原因: 该文件对象 DOC-文档-2026.09.04-656(3.5MS-A-01-2下支座底板.SLDPRT)没有进行PDF转换...”。


  3. 金蝶前端的“浏览PDF”逻辑是**只检查当前选中行对应的文档 ID 本身**；此前我们的流水线是将 PDF 关联到了 `.SLDDRW` 上。因此用户在装配树里点击零件 `.SLDPRT` 去点“浏览PDF”，自然提示该零件没有 PDF；
  4. 且该图纸 `656/657` 尚未在批处理中被转换。

## 五、最终闭环与后续改进方案

为了彻底解决用户在装配体/BOM 树中查看图纸的痛点，后续改进设计如下：

```mermaid
flowchart LR
    A["工程图 (.SLDDRW)"] -->|SolidWorks 导出| B["高精度矢量 PDF"]
    B -->|上传| C["PLM 电子仓"]
    C -->|同时关联| D["工程图对象 (.SLDDRW)<br>RelevantObject = PDF"]
    C -->|同时关联 (核心增强)| E["三维模型对象 (.SLDPRT / .SLDASM)<br>RelevantObject = PDF"]
```

1. **双向关联增强**：
   在通用桥接服务 `Gc_AttachPdfService.Attach` 或批处理中，当生成一份工程图 PDF 后，不仅给 `.SLDDRW` 绑定 `RelevantObject`，**同时也给对应的 `.SLDPRT`（或 `.SLDASM`）写入相同的 `RelevantObject`**。
   - **效果**：无论业务人员是在文档库列表点击 `.SLDDRW`，还是在装配体总成/BOM 结构中点击某一个零件 `.SLDPRT`，点击“浏览PDF”都能瞬间直接弹开该零件的图纸！
2. **批处理流水线容错强化**：
   在 `Invoke-PlmDrawingBatchPipeline.ps1` 中加入计划任务状态检测，每次触发前检测 Task 状态，完成后执行清理，避免并发堵塞。
3. **免 PLM License 的业务看图方案（扩展）**：
   对于大量没有 PLM 许可的销售/生产人员，将导出的 PDF 定时同步挂载到金蝶【物料基础资料】的附件中，业务员在普通物料界面即可查阅图纸，彻底避开 PLM 许可证限制。
